# Agent 内核:设计与迁移

## 1. 内核是什么

GeoCode 的会话循环、模型接入、OAuth 登录、权限系统与工具调度,由 OpenCode 的 agent 引擎承担。这是刻意的选择:这些子系统的正确性——尤其 OAuth 的 wire 协议——直接决定用户能否用已有订阅登录,自研或深改它们没有收益,只有风险。对 GeoCode 的其余部分,内核呈现为一组 HTTP API(供界面)与一个 MCP 客户端(供地理内核挂载工具),接近黑盒。

内核以**薄 fork** 的方式维护:源码住在独立的内核仓库(保留与上游的 git 合并谱系,这是三方合并能力的根,源码绝不复制进产品仓),构建产物(server bundle)作为构件进入产品仓打包。我们对源码的差异有一条铁律:**越薄越好**——差异越薄,合并上游的成本越低,薄到极致时升级内核约等于换一个依赖版本。

## 2. 定制阶梯

GeoCode 的一切内核定制,按下面的优先级实现,只允许用尽可能高的层级;源码补丁是最后手段:

1. **配置** —— agent 定义与默认 agent、禁用内置 agent、权限规则、MCP 注册、技能扫描目录;
2. **环境变量** —— 数据目录定向(XDG 族)、服务口令;
3. **外挂进程** —— 地理工具经 MCP 进入引擎,技能经扫描目录进入引擎;
4. **界面** —— 纯展示层的取舍(如不显示某些斜杠命令)在界面代码完成;
5. **源码补丁** —— 每一处必须书面回答"为什么上面四层做不到",并配一个运行时绊线测试。

这条阶梯建立在对引擎装配面的逐项验证上:agent 可以完全由配置定义并设为默认,内置 agent 可被真正禁用(从列表删除,而非隐藏);权限引擎按通配符匹配任意工具名与路径模式,足以表达"栅格文件禁止文本读取""OSM 工具只许下载子代理使用";数据目录完全由 XDG 环境变量决定,macOS 亦然。

**GeoCode 的装配内容**:GeoAgent 是唯一暴露的主 agent(地理科学专家人设,独享地理工具与全网搜索,内置编码向 agent 禁用);osmfetch 是唯一子代理(OSM 数据下载),其网络出口被权限规则锁死——只许 OSM 工具组,webfetch、websearch 与再派生子任务一律拒绝,防止提示注入把它变成任意抓取器。地理工具默认对所有 agent 拒绝、仅对 GeoAgent 放行,保证将来引入其他 agent 时地理能力边界不会静默扩大。

**冻结区**:内核中 provider、auth、account 及模型协议相关的包永久与上游逐字节一致,合并时无条件取上游;`@opencode-ai/*` 包名、`OPENCODE_*` 环境变量、User-Agent 与 Referer 等 wire 指纹逐字保留。

## 3. 如何迁移 OpenCode 内核

### 3.1 瘦身:把既有定制搬上阶梯

迁移的第一阶段不是写新代码,而是把内核仓库里的历史注入逐类搬出源码。每类独立提交、配绊线测试,搬完一类验证一类:

| 既有源码注入 | 搬往 |
|---|---|
| GeoAgent / osmfetch 定义、隐藏内置 agent、默认 agent | 配置(agent 定义 + disable + default_agent) |
| 地理工具权限分组 | 配置(工具名通配规则,`geo_` 前缀圈组) |
| 栅格文件防文本误读 | 配置(read 权限的 glob 拒绝规则;引导措辞移入工具描述) |
| 数据目录命名空间 | 环境变量(壳注入 XDG 族)或保留两行补丁,择薄者 |
| 地理工具与 HTTP 路由、技能商店 | 地理内核进程(独立迁移工程,设计见 DESIGN.md §3) |
| 面向程序员的斜杠命令裁剪 | 界面过滤 |

预期留守的源码补丁:Windows shell 白名单(约 60 行,保证 GIS 工具链路径风格唯一)、快照对大型地理文件的排除,以及个别逐案评估的小差异。终态目标:补丁总量不超过百行、集中在个位数文件。

### 3.2 验证:以上游 TUI 为测试台

内核瘦身与配置装配的验证不需要 GeoCode 界面:直接以终端形态运行内核,确认 GeoAgent 出现并成为默认、内置 agent 消失、权限规则生效、MCP 工具可调。这让内核迁移与界面开发完全解耦,零界面成本闭环。

### 3.3 升级:按需合并上游

内核升级是可选的、按需的,停靠不设期限(当前基线:上游 v1.18.4)。流程:

1. 内核仓库合并目标上游版本(薄差异使冲突极小;解冲突逐处手解,**绝不整文件取某一方**);
2. 运行绊线测试套件——每处源码补丁对应一个运行时测试,补丁被上游重构架空时测试变红,而不是靠人工排查静默失效;
3. 构建内核 bundle,进入产品仓,全链路实机重测;
4. 任何一步不满意,回退停靠原版本。

### 3.4 迁移期间的安全网

迁移全程,旧版 GeoCode 保持可发布;内核仓库的每一步瘦身都先打备份标签,可整步回退。历史经验反复证明:编译通过与测试全绿不等于运行时正确,凡涉及"配置期望被某个服务读到"的改动,必须追踪到读取方并用运行时测试锁定。

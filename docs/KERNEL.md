# 内核

内核是 GeoCode 的 agent 引擎,负责会话、模型接入、权限裁决与工具调度。本文说明内核里的 agent 怎样为地理工作服务:默认与用户对话的是 GeoAgent,所有模型共用同一份基础提示词;Plan 模式只做计划,不写出数据;撤回会话时,文件只在 git 项目里恢复,一份地理数据要么整份恢复,要么整份不动。内核作为进程怎样启动、从哪里读配置,见 `DESKTOP.md`;地理工具怎样执行,见 `GEOENGINE.md`。

## 1. 定位

GeoCode 的用户在对话里请 agent 处理地理数据:找数据、读数据、做分析、出结果,其间也常常要写脚本。内核让 agent 的各项机制都以这样的工作为中心:对话的对象、交给模型的提示词、长对话的摘要、撤回时对文件的处理,都要在数据文件夹里成立,而不只是在代码仓库里。

## 2. 核心设计

### 2.1 agent 与提示词

默认的主 agent 是 GeoAgent,在配置里的名字是 `geoagent`,它取代了上游写代码的 `build`。另一个主 agent 是 Plan,用来在动手之前和用户一起定计划。主 agent 可以把子任务交给两个子 agent:`general` 处理一般的多步任务,`explore` 在文件夹里查找代码,也查找本机的地理数据。GeoAgent 总是默认的那一个:配置里指定的默认 agent 不存在时,内核退回 GeoAgent,而不是 Plan,用户写错名字也不会让对话落到只做计划的 agent 上。用户可以定义自己的 agent;在配置里写 `geoagent`,则是调整 GeoAgent 本身。

agent 没有自己的提示词时,不论用哪个模型,系统提示词的开头都是 GeoCode 的同一份基础提示词。不为不同厂商的模型分别写提示词:同一份,行为一致,也只有一处要改。写了自己提示词的 agent 用它自己的。

管理应用自身的工具(会话、worktree、模型目录等)以 `geocode` 为命名空间交给模型,而不是上游的 `opencode`。

### 2.2 权限与 Plan

GeoAgent 的多数操作直接放行,读 `.env` 一类的文件要询问。地理工具在此之上有自己的检查(不可逆的处理、项目以外的读写,见 `GEOENGINE.md`)。`geerun` 的默认规则与命令行相同(`GEE.md` 第 2.7 节)。

Plan 是软只读的:除了自己的计划文件,它不能编辑文件;会写出数据的 QGIS 处理与 OSM 下载也在 Plan 里被拒绝。`geerun` 与命令行一样不拒绝,只靠进入 Plan 时插入的提醒约束模型。拒绝发生在调用的时候,而不是把这些工具从 Plan 的工具清单里拿掉:这样 Plan 与 GeoAgent 的系统提示词与工具清单完全相同,切换时只在对话末尾多一条提醒,模型服务的提示缓存不会因此失效。进出 Plan 只能由用户切换。

### 2.3 对话的延续与回退

一段对话可以持续很久,也可以退回去。让 agent 一直做到某个条件达成才停的是目标,GeoCode 里有两套:界面上的目标按钮由壳实现,`/goal` 命令由内核实现,两套互不相通。界面的命令补全不列 `/goal`,它与目标按钮重复,手动输入仍然有效。定时任务只用壳提供的那一套,内核自己的定时任务默认关闭。

对话太长时,内核把前面的内容压缩成一份摘要,让对话接得下去。摘要除了任务与进展,还专门记下数据:用到的数据从哪里来、坐标系是什么、结果写到了哪里。图层名、字段名与坐标系代码原样保留,因为换个说法就找不回原来的数据。

撤回会话时,文件能不能恢复取决于快照。快照只在 git 项目里建立;不是 git 项目的文件夹(多数数据文件夹与不属于项目的对话)撤回只撤对话,不碰文件。没被 git 追踪又太大的文件不进快照,而地理数据常由几个文件共同组成,如 Shapefile 的各个部分、栅格的附属文件、`.gdb` 文件夹;只有一部分进了快照,撤回时就会把数据拆坏。所以一个文件因太大被跳过时,属于同一份数据的文件一起跳过:一份数据要么整份在快照里,要么整份不在。

## 3. 边界与约束

- 不按模型厂商分别适配,所有模型用同一份基础提示词。
- 上游写代码的 `build` agent、审查代码改动的 `/review` 命令、把问题报给 OpenCode 的 `report` 技能都关闭;用户配置里写 `build` 也造不回来。
- 不提供以 Claude 订阅运行的 Claude Agent 服务商:Anthropic 不允许第三方产品让用户使用自己的订阅额度。用 Claude 的用户以 API 密钥接入 Anthropic 服务商。
- Plan 派出的子 agent 不受 Plan 的限制:子会话不继承父 agent 的规则,只靠进入提醒约束模型不让它们去写出数据。
- 撤回不保证恢复文件:非 git 文件夹里只撤对话。要能回到以前的数据,需要用户自己用 git 或备份。

## 4. 与其他部分的关系

- `DESKTOP.md`:内核作为私有子进程怎样启动与退出,用户与项目的配置从哪里读。
- `GEOENGINE.md`:地理工具接到调用之后的执行、检查与询问。
- `PATHS.md`:内核在用户电脑上的配置、数据与快照的位置。

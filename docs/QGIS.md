# QGIS

QGIS 能力域让 GeoAgent 用用户安装的 QGIS 读取地理数据、查阅与执行空间处理算法。框架(进程、通道、配置与状态)在 `GEOENGINE.md`,这里只写 QGIS 自己的部分。

## 1. 定位与范围

执行载体只有 QGIS 自带的 Python。算法、PyQGIS 脚本与数据读取都要在这个解释器里运行;只用它,就只需维护一套环境组装与一套验证。同一安装里的 `qgis_process` 不另外支持。

范围是 QGIS 内置的 native、qgis、gdal 三个提供方的算法,第三方插件的算法不在其中。这三个提供方里剔除两类:QGIS 标为不能在独立工具中运行的算法,它们要用 QGIS 的界面或打开的项目;以及 `native:openurl`,它用系统默认的程序打开文件或网址,GeoAgent 用不着,也不该借它启动别的程序。

GeoAgent 得到三个工具:

| 工具 | 做什么 | 权限参照的自带工具 |
|---|---|---|
| `readgeodata` | 读一份地理数据:坐标系、范围、字段、统计与要素,栅格可以出预览图 | `read` |
| `qgisdoc` | 查本机 QGIS 的算法目录:分组、算法、文档与搜索 | `grep`、`glob` |
| `qgisrun` | 执行一个 QGIS 算法 | 见第 4 节 |

工具名照 OpenCode 自带工具的写法:全小写,不用下划线(下划线是命名空间的标记),也不以 `geocode` 开头,以免与壳交给 agent 的 `geocode_web` 等工具混淆。它们直接列在模型的工具清单上,不收进 Code Mode。

## 2. 安装与环境

支持 QGIS 官方的安装包:macOS 上的应用包,Windows 上的独立安装包与 OSGeo4W;conda、Homebrew 等来源不支持。目标是两个平台上的大多数版本,但 GeoCode 不按版本号判断能不能用:能不能运行由检查与执行说明,遇到的问题原样交给 GeoAgent。不同版本运行时会出各种意想不到的问题,只能逐个版本验证、逐个解决。

环境采用 QGIS 自己的答案,GeoCode 只叠加 QGIS 不会替它设置的几项。两个平台都叠加输出编码与关掉 Qt 的日志,其余各不相同:

- macOS:以应用包里官方的 `python` 启动脚本运行解释器。投影与 GDAL 的数据目录显式给出,否则 GDAL 找不到投影数据库,坐标变换静默失败;从登录 shell 继承来的 `PYTHONPATH` 清空,它常由 conda 设置,会让 QGIS 的 Python 导入别的 Python 的包。
- Windows:一套 QGIS 是根目录下的 `apps\<名字>` 与它的启动脚本 `bin\python-<名字>.bat`,名字以 `qgis` 开头;独立安装包的根目录里只有一套,OSGeo4W 里可以并存几套。每次都经启动脚本运行,环境全由它组装。GeoCode 不自己组装环境,也不留环境的快照:Qt、GDAL 与各个依赖的位置随版本而变,自己组装就要跟着每个版本追,漏一项就是 Qt 找不到或 DLL 加载失败。

脚本与请求经标准输入交给 QGIS 的 Python,不放在命令行上:Windows 的启动脚本要经命令解释器运行,它会改写命令行里的引号与 `%`、`^`、`&`、`!`,截断多行内容。两个平台用同一种传法。

QGIS 启动时在系统的临时目录建几个文件,只在它自己收尾时删掉,所以启动了 QGIS 的脚本送出结果之后要走 QGIS 的收尾再退出。QGIS 的配置与缓存位置也不改:定制得越多,兼容的版本越少。

### 2.1 配置与发现

`machine.json` 的 `qgis` 块记一个路径。macOS 上它指向应用包,落在应用包内部时取它所在的应用包。Windows 上它可以是 QGIS 根目录里的任何位置,GeoEngine 往上找到根目录:路径指明了哪一套(落在 `apps\<名字>` 里,或是它的启动脚本、桌面快捷方式启动的程序)就用那一套;没有指明时,根目录里只有一套能启动的就用它,有几套就报告为一个文件夹里有多套,由用户或 GeoAgent 指定,不替用户挑。

设置里列出的安装这样找:

- macOS:按应用的身份找,不按名字,因为应用可以改名、放在别处。范围是 `/Applications`、`~/Applications` 下的应用包,加上 Spotlight 按包标识(`org.qgis.` 开头)找到的;磁盘映像、外接磁盘与废纸篓里的不列。
- Windows:按安装程序的目录布局找,即每块固定硬盘上安装程序放 QGIS 的位置(`Program Files\QGIS*`,根目录下的 `OSGeo4W*` 与 `QGIS*`),一个根目录里的每一套各列一项。不查注册表:独立安装包不在里面记安装位置,文件关联只记最后装的那一套。

装在别处的,由用户在设置里指定,或由 GeoAgent 去找。

## 3. 检查、状态与提示

检查由一段探针在组装好的环境里依次完成:导入 GDAL,做一次真实的坐标变换,导入 QGIS 核心,初始化处理框架;前一步失败就不往下查。坐标变换单独一步,因为投影库在数据库缺失时照样能导入,要到真正变换时才失败。

除了框架共有的状态(`GEOENGINE.md` 第 3.3 节),QGIS 还有平台不支持、路径不存在、不是 QGIS、一个文件夹里有多套、找不到 QGIS 的 Python、探针各步骤的失败、探针超时或崩溃,以及就绪。检查在 GeoEngine 启动时、`qgis` 块变化时与用户要求时进行。看 QGIS 得出的失败,在每次工具调用时再检查一次,因为在原处重装 QGIS 不改动配置文件;就绪时调用不再检查,不拖慢调用。

诊断带上配置的路径、用的是哪一套与它的版本、检查运行的启动脚本与探针的输出(某一步失败时是 Python 的错误回溯)。探针某一步失败时,另附 Python 实际拿到的几项环境变量(QGIS 的前缀、Python 的位置、Qt 的插件目录与前缀、`PATH`),用户贴回诊断就看得出是哪一项不对。只附这几项,其余环境变量可能带着密钥;这几项也只进诊断、不进提示,因为提示会发给模型的服务商,而 `PATH` 里有用户的文件夹名。

给 GeoAgent 的提示让它自己动手配置:写明配置文件的绝对路径与写法、在这台电脑上找 QGIS 的位置与命令;找到多套时先问用户用哪一套,写好之后调用 `qgisdoc` 验证。QGIS 坏了时,提示附上启动脚本与输出的最后 20 行,请用户重装或改用另一套。提示不提设置页,那是用户自己的路。提示还要求 GeoAgent 不安装 QGIS、不写包装脚本、不自己运行 QGIS 的 Python 去试探:安装由用户决定,后两件只会添乱。

## 4. 权限

三个工具的权限逻辑与它们参照的自带工具一致,在设置的工具权限里同样管理,「始终允许」同样由内核按项目保存。

`readgeodata` 把数据内容交给模型,所以照 `read` 询问,没有自己的一条规则,由读取的规则管:会话目录与项目以外的文件先按访问项目外目录的规则判断(默认放行),再按读取的规则判断。一份数据常要分几次读(图层、翻页、预览),所以同一会话里每份数据只检查一次。放行只记在内核的内存里,工具表重建或闲置的项目被回收时清空,之后再读重新检查;拒绝不记住。`qgisdoc` 只读应用自己掌握的信息,照 `grep`、`glob` 默认放行。

`qgisrun` 按整个工具询问,不按算法逐个设权限:算法有数百种,逐个授权既不合理,也容易在少数算法上出意外。输入不检查,读数据的是 QGIS,数据内容不经过模型。要守住的是写到哪里,以及少数后果不可逆的算法:

- 输出按算法的参数定义认出。写到会话目录与项目之外,或写进数据库、网络服务这类不是文件的位置时询问:几乎每个算法的输出都能写进数据库,同名的表被直接替换,也不经过项目内外的判断。
- 后果不可逆的算法列成一份名单:清空要素、往已有的栅格里烧值、改写坐标系、执行 SQL、写入数据库、把文件上传到网址或 GPS 设备。名单只求挡住主要的危险;「没有输出参数就当作会修改」这样的通则会误伤一半无害的算法。

规则是询问时照常询问,点过对整个工具的「始终允许」之后与规则是允许时相同。规则是允许时,上面这些情况仍然询问,除非其中的算法、目录与数据库各自有过「始终允许」;对整个工具的「始终允许」不算,否则放行工具之后名单就形同虚设。规则按算法标识求值,所以按算法写的拒绝与询问(如拒绝 `gdal:*`)在任何情况下都成立。OpenChamber 的全部接受模式一律放行。一次执行至多一张询问卡片,要问的几件事合在一起;「始终允许」把算法、目录与数据库分别按项目记住,同一个库的各张表算一处。目录只记卡片上写的那个,连同其中的子文件夹;访问项目外目录的规则记的是它所在的整个仓库,这里不同。

权限只决定问不问,所以一次执行分三步:GeoEngine 先认出参数里的文件,内核把它们解析成绝对路径后交回;GeoEngine 检查数据、定下输出,不执行算法;内核据此询问,得到允许后 GeoEngine 按检查过的参数执行。

## 5. 执行算法

每次执行是一个独立的任务进程,当前目录是会话目录。执行中按处理框架报告的进度回报。

无界面运行时没有 QGIS 项目,项目带来的测量椭球随之缺失:按椭球测量的算法(字段计算器的 `$area`、线长求和、距离矩阵等)改在图层的坐标上按平面量,经纬度数据得到以度为单位的数,不报错。所以运行脚本一律设 WGS 84 椭球,与桌面版按椭球测量的结果一致。

算法要运行多久无从预估,GeoEngine 不计时。`qgisrun` 由模型按数据规模给出 `timeout`(有默认值与下限),内核按连续多久没有新进度计算,到时中止,持续报告进度的算法因此不会被误杀。QGIS 冷启动时什么也不报告,所以时限从算法开始执行算起,在那之前至少等两分钟。调用 GDAL 命令行的算法,只在命令自己打印进度时才有进度,有的直到结束才有输出,时限对它们就是整个运行时间,工具说明要求模型在大数据上给足。

### 5.1 执行前的检查

`qgisrun` 把请求原样交给 QGIS,取值与必填参数由 QGIS 自己检查,它在算法开始前就会清楚地报错。GeoCode 只在判断确定、而执行只会白跑或悄悄得出错误结果时,才在询问之前拦下,不让用户批准一个注定失败的请求:

- 算法不在目录里:区分被剔除的与不存在的,后者给出相近的候选。
- 参数名不属于这个算法:QGIS 会忽略它而改用默认值。
- 输入的图层混合了点、线、面与几何集合中的两类以上:无界面运行时图层的类型取第一个要素的,产出的数据是错的。答复说明怎样在路径后加 `|geometrytype=` 取其中一类。
- 输出写成 `TEMPORARY_OUTPUT`、`memory:` 或 `/vsimem/`:结果随任务进程消失,或留在无人清理的临时目录。
- 坐标系类参数的值 QGIS 读不出:QGIS 当作没给,照常运行,输出没有投影。最常见的是不带 `PROJ:` 前缀的 PROJ 字符串。答复列出 QGIS 自己写的可接受写法。

算法、参数名与临时输出只对照目录。混合几何只在图层不声明单一几何类型时,由 QGIS 自带的 Python 用 GDAL 清点要素;单份数据读不通当作不知道,照常执行,清点本身没有答复时才不执行。坐标系只有 QGIS 读得准,所以启动 QGIS,用它读取这类参数的同一个函数判断;这项检查出错时照常放行,由执行说明问题。

### 5.2 路径与输出

参数里的路径按参数的类型认出:只有输入类与输出类参数的值可能是路径,其中 `TEMPORARY_OUTPUT`、GDAL 的虚拟路径、`postgis:` 这类数据源写法与网址不算。认出的路径交给内核解析成绝对路径,规则与 `read`、`write` 相同;其余参数原样交给 QGIS,其中的相对路径经任务进程的当前目录同样落在会话目录。

QGIS 遇到已有的输出文件时直接覆盖,不报错:写到含多个图层的 GeoPackage 时整份文件被替换,输出就是输入时数据被清空。地理数据没有撤销,所以输出撞名时在文件名后加 `_1`、`_2`,取最小的空号。判断的是 QGIS 实际会写的名字,包括它自动补的扩展名、Shapefile 的附属文件与 GeoPackage 里的表,不分大小写。询问与执行的都是编号后的路径,答复结尾列出的输出位置带着编号,不另外说明。定下的名字保留到这次执行结束,同时检查的两次执行不会写到同一个名字;检查过而没有执行的(如用户拒绝),一小时后放开。

### 5.3 答复

答复逐段累加,无论怎样结束,前面的内容都保留(中段过长时除外,见下):

- 开头是执行前定下的事实:QGIS 的版本、算法、按默认值运行的参数与取值。
- 中段按收到的顺序转达运行中的信息:QGIS 处理框架的各级反馈只转文字,级别只在界面上用来着色;任务进程自己写到标准输出与标准错误的行原样转达,PROJ 与 GDAL 直接打印的报错就在这里,QGIS 的反馈里没有它们。中段过长、整份答复超出内核的上限时,只留中段的结尾并注明,开头与结尾完整。内核自己的截断只留开头,会丢掉怎样结束。
- 结尾写怎样结束:成功时列出 QGIS 报告的每个输出;失败时补上 QGIS 报错点名的参数的说明;超时时写连续多久没有进度;失败、超时与崩溃都列出可能不完整的输出。

中段的信息只按来源与时间转达,不按文字过滤或分级:要支持两个平台与各个版本,针对文字的规则必然在别处出错。唯一的例外是 QGIS 自己附在最后的输出汇总,结尾已经列出输出,中段不重复。从算法开始执行起的行属于这次执行;之前是 QGIS 启动时的输出,不转达。Qt 自己的诊断用 Qt 的日志开关在来源处关掉,不影响 QGIS、GDAL 与 PROJ 的消息。

调用 GDAL 命令行的算法,命令以错误码退出时 QGIS 只报告这个错误码,照常以完成结束;`qgisrun` 把它当作失败,因为输出并没有写出。

用户在对话里停止执行时,内核直接中断工具,答复不送到模型。

## 6. 读取数据

`readgeodata` 读 GDAL 打得开的一切数据。事实由 QGIS 自带的 Python 取出,不启动 QGIS 本身;给模型的文字由 GeoEngine 写。读取不在数据旁边留下任何东西,如统计缓存与 GeoPackage 的 `-wal`、`-shm`。文件有多个图层而没有指定时,照 QGIS 的列法列出,由模型选一个再读。

- 矢量:几何类型(照 QGIS 的叫法)、坐标系、范围、每个字段的统计,与可以翻页的样本要素。不声明单一几何类型的图层逐个要素清点,几何混合时按点、线、面与几何集合分开统计与取样,因为不同几何的要素往往连字段都不同。样本里的数字照写入时的样子,超长的整数也不失真。
- Shapefile 的编码:先看文件的声明,声明 UTF-8 而文字不是 UTF-8 的当作没有声明,因为有的工具对没转换过的文字也这样声明;没有声明时,能完整解成 UTF-8 就是 UTF-8,否则在 GB18030、CP950 与 Windows-1252 之间识别,对应 GeoCode 面向的中国大陆、台湾与英文世界。识别不对时由模型指定编码重读。
- 栅格:尺寸、坐标系、地理参照、像元大小(经纬度的同时换算成米)与每个波段的统计。统计从全部像元精确算出,因为文件里缓存的近似统计可能差得很远。取值不多,或带色表、类别名的整数波段当作分类数据,给出每个值的占比。没有地理参照的图片答以不是地理数据。
- 坐标系声称是经纬度而坐标超出经纬度的范围时,坐标系报告为未知。

预览图与描述分开读,模型多数时候只读描述。图片缩到内核对图片的边长上限以内;拉伸照 QGIS 的默认。显示哪些波段由模型选:一个波段为灰度,三个波段合成彩色;不选时照文件标明的红绿蓝,没有标明就显示第 1 个波段,不按波段名或波段数猜传感器。取值不多的分类数据逐值上色并附图例,无数据处透明。预览图只给模型,不在对话里显示。

答复按内核给工具结果的上限裁剪,依次少列常见值、样本、字段与波段,字段与波段说明省略了多少,不让内核从中截断。

读取与执行前的清点都不限总时长,连续一段时间没有输出才中止,所以脚本里耗时的循环(逐要素、逐像元与统计)要定时报活。

## 7. 查阅算法

`qgisdoc` 的内容全部来自本机 QGIS 自己的算法定义,不附 GeoCode 手写的说明与示例:各版本的算法与参数不同,手写的内容总会在某个版本上出错。目录在第一次用到时(查阅或执行)导出,换一套 QGIS,或检查发现版本变了之后重新导出,剔除的算法与 `qgisrun` 相同。

四个动作:`groups` 列出分组,`algorithms` 列出一个分组里的算法,`help` 读一个算法的文档,`search` 按英文词搜索(目录是英文的,模型读英文也更准)。算法名的大小写、空格与标点不影响查找,但不猜:一个名字对应多个算法时,列出全部候选。

文档以 `qgis_process help` 为底稿,补上调用需要而它没写的三样(能否多选、字段与波段属于哪个图层、高级参数),删去或改正在 GeoEngine 的运行方式下会失败的写法。文档开头带 QGIS 的版本,末尾给出对应版本官方手册里这个算法那一节的链接。

官方手册一个分组一页,大的超过内核给工具结果的上限,模型只能看到开头。所以 `webfetch` 读 QGIS 官方手册(`docs.qgis.org`)时,链接带锚点就只返回那一节,否则只返回正文;找不到那一节时返回正文并说明。别的网站照 OpenCode 原样。

## 8. 界面

询问卡片的外框与设置里的工具权限沿用 OpenChamber 的组件,GeoCode 补上自己的图标、随界面语言切换的标题与 QGIS 工具自己的卡片内容;对话里三个工具的行由 GeoCode 自己绘制。算法的名称与描述取 QGIS 自带的翻译,与用户自己的中文版 QGIS 叫法一致;标题与 `qgisrun` 的询问卡片不显示算法标识;`qgisdoc` 设为询问时,卡片照上游写出它要查的内容,查某个算法的说明时就是这个算法的标识。

`qgisrun` 由模型写一句这一步的用途,显示在对话与询问卡片上。询问卡片列出请求原因(即模型写的用途)、算法自己的描述、需要时的警示(项目外的目录、不是文件的输出、名单上的算法),以及输入、参数与输出。输出写到项目外时也用这张卡片,而不是上游访问外部目录的卡片,让用户看到是哪个算法要在那里写文件。批准也只在这张卡片上:托盘菜单显示不了这些内容,所以在托盘里只能拒绝或打开对话。对话里的一行是用途,运行中加上算法名称、计时与百分比:进度不一定有(第 5 节),所以计时始终显示,百分比有才显示,不做估算的进度条。展开是答复的节选。

`qgisdoc` 与 `readgeodata` 只是查阅,同一个工具相邻的调用在对话里合成一行,中间隔着任何显示出来的内容才分开;出错的调用不另外显示,由 GeoAgent 告诉用户。新出现的地理行照上游的工具行浮现,合成的一行在一串调用里只浮现一次,不为每次接上的调用重放。`readgeodata` 那一行展开后列出这一行各次调用要读的文件与图层,出错的也在内。`webfetch` 读 QGIS 官方手册时,卡片里显示手册网页本身,停在链接所指的那一节;网页加载不了时仍显示 `webfetch` 返回的文字。

## 9. 验收

- 3.44 与 4.x 的官方应用包配置后状态变为就绪,内置算法都能执行;含中文与 `%`、`^`、`&`、`!` 的路径与属性原样到达 QGIS。Windows 上的独立安装包与 OSGeo4W 同样如此,路径写成根目录、`bin`、启动脚本或快捷方式启动的程序都认得出。
- 设置里列出本机的每一套 QGIS 与版本,包括 macOS 上改过名的与 Windows 上装在 C 盘以外的。路径不存在、不是 QGIS、找不到 QGIS 的 Python、缺少投影数据各自报告为对应的状态并带有诊断;原地重装或改动配置之后,不用重启应用就看到新的状态。
- 没有配置 QGIS 时,GeoAgent 照提示自己找到 QGIS、写好配置并用 `qgisdoc` 确认就绪,找到多套时先问用户。
- 执行中进度持续回报;执行结束时无论成败,系统的临时目录里都不留下 QGIS 的文件(超时与停止时进程被直接结束,来不及收尾)。
- 按椭球测量的算法在经纬度与 Web 墨卡托的数据上,得到与 WGS 84 椭球一致的面积与距离。
- 第 5.1 节的五类请求在询问之前被拦下;输出撞名时写到 `_1`,已有的数据不被覆盖;GDAL 命令出错时 `qgisrun` 以失败结束。
- 规则允许 `qgisrun` 时,输出在会话目录或项目里就直接执行,写到外面、写进数据库或算法在名单上时弹出一张卡片,一次执行不出现第二张。
- `readgeodata` 读不声明编码的中文 Shapefile、混合几何的 GeoJSON、WAL 模式的 GeoPackage 与带近似统计缓存的 GeoTIFF,文字与统计正确,读取前后目录里的文件逐字节不变。
- `qgisdoc` 在 3.44 与 4.x 上都能列出分组、算法与文档;被剔除的算法答以不可用,有歧义的名字给出候选。

# 测试

GeoCode 自己的测试怎样运行、结果怎样读,打包版的检查与写入检测怎样用,以及写测试时常见的坑。要守的规则(测什么、放在哪、什么改动做什么检查)见 `CONVENTIONS.md` 第 6、7 节。

测试只有一个入口:仓库根目录的 `scripts/test.mjs`。它给每次运行一个临时的主目录,让测试碰不到用户的文件,并从各测试工具的报告里核对跑了多少、跳过了什么、失败在哪。

## 1. 三层

- 单元测试:只碰替身与假对象,只写临时目录,不联网。
- 真实软件的测试:接本机真实的 QGIS、真实的 Earth Engine 与装好的内置 Python 环境,测替身证明不了的。它们慢,GEE 的还用账号的额度,所以和单元测试分开成套件。
- 打包版的检查:在全新的沙箱里启动打包出的应用,把日常功能与地理工具真实地走一遍,并检查它没有写进别的产品的目录(第 7、8 节)。

## 2. 运行

```bash
node scripts/test.mjs --file <测试文件>   # 改代码、反复试时:只跑这一个文件,像它的套件那样跑
node scripts/test.mjs changed            # 完工前:工作区的改动要求的套件
node scripts/test.mjs geoengine qgis     # 指名的套件
node scripts/test.mjs geoengine/osm      # GeoEngine 单元测试里一个能力域的
node scripts/test.mjs all                # 全部套件
node scripts/test.mjs --list changed     # 只列出要跑什么与原因,不运行
```

`changed` 看的是工作区相对 `HEAD` 的改动,包括还没加入 git 的文件;已经提交的不算。它按改动的路径挑选套件,规则在脚本的 `calledFor` 里,拿不准时用 `--list` 看它挑了什么、为什么。大致是:

- 内核与桌面的四个套件(`kernel`、`ui`、`web`、`electron`)几乎每次都跑;只改 GeoEngine 的测试文件、打包版检查的脚本或写入检测时不跑。
- GeoEngine 的改动另加涉及的能力域的单元测试与真实软件测试;改了引擎本身或各能力域共用的部分(内置环境、启动解释器的方式)跑得更多。
- `src/`、`test/` 以外的 Markdown 不挑套件,`PATHS.md` 例外(打包版的检查读它);改了运行器自己就跑全部。

没有要跑的套件时,它打印「nothing to run」,退出码为 0。

只经这个运行器跑测试(`AGENTS.md`):包目录里的测试命令不换主目录,有的会写真实的主目录,上游的测试也会一起跑。

## 3. 套件

| 套件 | 内容 | 前提 |
|---|---|---|
| `kernel` | 内核各包里 GeoCode 的测试:GeoCode 自己的测试文件整份运行,上游测试文件里只运行名称含 `GeoCode:` 的用例 | 无 |
| `ui`、`web`、`electron` | 桌面端这三个包 `geocode/` 目录下的测试 | 无 |
| `geoengine` | GeoEngine 的单元测试;`geoengine/<能力域>` 只跑 `engine`(引擎本身)、`python`、`qgis`、`gee` 或 `osm` 目录下的 | `PATH` 里的 `python3`,没有时相关的用例跳过 |
| `qgis` | 在本机每一套 QGIS 上运行 | macOS 上的 QGIS |
| `gee` | 在真实 Earth Engine 上运行 | `GEOENGINE_GEE_PROJECT=<项目 ID>`、登录过 Earth Engine、装好的内置环境 |
| `osm` | 在装好的内置环境上运行 OSM 下载,服务是本机的假服务 | 装好的内置环境 |
| `scripts` | `scripts/` 下脚本自己的测试 | 无(写入检测的只在 macOS 上跑) |

GeoEngine 的单元测试慢在 OSM 与 GEE:它们验证暂停、重试、每秒一次请求这类与时间有关的行为,测试里真的等这些时间;`changed` 只在改到它们的能力域或引擎本身时才挑它们。

新的测试文件放在约定的位置(`CONVENTIONS.md` 第 6 节)就会被运行。在那几个目录里,文件名像测试、却没有套件运行的文件,运行器报用法错误;约定目录以外的测试既不运行,也不报出。

## 4. 隔离

每一次运行有一个新建的临时主目录,运行结束就删掉。`HOME`、`TMPDIR`(Windows 上还有 `USERPROFILE`、`APPDATA` 等)指向它;会把测试指向用户自己的目录、账号、仓库或上游应用的变量,应用自己也去掉的运行时开关,以及密钥与令牌,都被去掉。清单在 `scripts/test.mjs`。

真实软件的测试另外拿到运行器在换主目录之前定下的东西:

- 内置环境:`GEOENGINE_DATA` 指向 GeoCode 的数据目录,默认是真实主目录下的那个。测试不往里装东西。它的启动文件与 `geocodekit` 不是当前代码写的时,GEE 的测试失败并说明(改了之后启动一次开发版);没有装好的环境时这些用例跳过。
- Earth Engine 的凭据:复制一份进临时主目录,随它删掉。
- QGIS:`/Applications` 下的应用包,或 `GEOENGINE_QGIS_APPS` 列出的(以冒号分隔)。

隔离只管环境变量。写到绝对路径、或不看 `HOME` 直接问系统要主目录的,拦不住,打包版的检查也一样:真实的 QGIS 在 macOS 上照它的默认位置写自己的配置(`~/Library/Application Support/QGIS`);应用的偏好设置照样写进用户的 `~/Library/Preferences`(`PATHS.md` 第 5 节)。别的产品的目录由写入检测把关。

## 5. 结果

每个套件(或 `--file` 给的每个文件)报一行,状态是下面之一:

| 状态 | 含义 |
|---|---|
| `PASS` | 有用例通过,没有失败;另列跳过了几个与原因 |
| `FAIL` | 有用例失败,测试工具异常退出或超时,给的文件一个用例都没跑或留着 `.only`,或一个测试文件都没找到 |
| `NOT RUN` | 没有运行:缺前提(没设 GEE 项目、没有 QGIS、没装内置环境),或全部用例都跳过了,附原因 |

退出码:有失败为 1;没有失败、但有没运行的为 3;参数错误为 2;否则为 0。`NOT RUN` 与跳过都不是通过。

## 6. 替身与真实软件

单元测试里换成替身的,与只有真实软件或应用里才验证得到的:

- QGIS:单元测试用假的应用包,其中的解释器是一段 shell 脚本,只在 macOS 上跑。Windows 上认路径与发现安装的逻辑在任何平台上都测,用照 OSGeo4W 搭出的假目录树;经启动脚本运行 QGIS 只能在 Windows 上验证。
- 内置的 Python 环境:单元测试用一个很小的假包与替身 pixi-unpack,转去运行 `PATH` 里的 `python3`;真实的环境要在应用里验证。
- GEE:单元测试不联网,earthengine-api 与 Google 的库换成替身,脚本用 `PATH` 里的 `python3` 真实执行。存资产的 `gee.save` 不在其中(改了它要另试,`CONVENTIONS.md` 第 7 节)。真实软件的测试只查询、下载到临时目录,不存资产。
- OSM:都不联网,公共服务换成本机回环地址上的一个假服务。下载要 shapely 与 GDAL,由 `osm` 套件在装好的内置环境上运行。对真实公共服务的检查不做成自动测试(`CONVENTIONS.md` 第 7 节)。

内核的 `packages/core` 有自己的测试脚本,它在运行器给的主目录里再换一层;上游测试文件里的 GeoCode 用例按名称挑选,其余用例不运行,但文件本身的准备代码照常执行。

## 7. 打包版的检查

单元测试与真实软件的测试碰不到的,由这两个检查在打包出的应用上确认:内核、壳、界面与 GeoEngine 装在一起之后能不能用,全新安装能不能把内置环境装好,退出后有没有留下进程,有没有写进别的产品的目录,写下的文件是不是都在 `PATHS.md` 里,连了哪些外部地址。什么改动要跑它们,见 `CONVENTIONS.md` 第 7 节;它们不在 `changed` 里。

```bash
node scripts/app/smoke.mjs                          # 日常功能
node scripts/app/geo.mjs                            # 地理工具,用 /Applications 下的 QGIS
node scripts/app/geo.mjs --qgis <QGIS.app> --gee <项目 ID>   # 另加 GEE,用这台电脑登录的账号与它的额度
```

每项检查什么、用法与退出码,写在两个脚本的开头。它们默认检查 `bun run package -- --dir` 打出的应用(`DEVELOPMENT.md` 第 6 节),`--app` 指定别的。每次在系统临时目录里建一个全新的沙箱,模型是检查自己开的一个本机假接口,不用真实的模型。新沙箱第一次启动要装内置环境,要几分钟。`--keep` 留下沙箱以便查看,失败时总是留下;留下的沙箱里有装好的内置环境,占几百 MB,看完自己删。

检查对照 `PATHS.md` 查沙箱里新出现的文件:查出来的,就是应用写了而文档没写的地方,要么文档补上,要么应用不该写。外联经检查开的本机代理记下,只看得到经代理的请求;窗口经 Chromium 联网,跟随系统的代理设置,这里看不到。

界面上的部分这两个检查测不到,由人在打包版上手动过一遍(`CONVENTIONS.md` 第 7 节)。

### 改动前后的对照

屏蔽一项功能、换一批名字或图标时,在改动前后的打包版上各看一次。两边各用一个全新沙箱、按同样的顺序操作:同一个沙箱里先后看,前一轮留下的界面状态和启动快慢会造成假差异。`dist` 里只有一份包,对照组要单独留:改动前先打包,或 `git stash push -u` 后打包,把 `.app` 复制出来,再 `git stash pop`。沙箱里先放好能触发这个功能的数据,对照组才会真的走到那条路径。会真的向外发请求的操作只对改动后的版本做。

## 8. 写入检测

安装依赖、启动应用这类可能写盘的操作,前后各运行一次:

```bash
./scripts/foreign-writes.sh before
# 安装、构建、启动应用并操作
./scripts/foreign-writes.sh after
```

它检查 OpenCode、OpenChamber 的目录、Claude 的技能、`CLAUDE.md` 与凭据,以及通用的 `~/.agents` 目录有没有被写入。无论在沙箱里还是在真实主目录下启动,结果都应当是干净的。它只在 macOS 上运行。

退出码:0 干净;1 发现写入;3 需要人确认,表示变动全在 OpenChamber 与 OpenCode 自己的目录里,而本机的 OpenChamber 在这段时间里运行过,多半是它自己写的,关掉它重跑才能得出结论;参数错误为 2。`FOREIGN_WRITES_EXTRA_ROOTS` 加上要一起监视的目录(以空格分隔)。

## 9. 写测试的坑

### 证明一道保护会失败

新测试要先证明会失败(`CONVENTIONS.md` 第 6 节)。做法:把源文件与测试复制到临时目录,在副本上撤掉那一处(如用 `perl -0pi -e`),跑副本的测试看它变红;先跑一次不改的副本作对照。不要在仓库里的文件上这样改。`kernel/` 与 `desktop/` 带着依赖,在 macOS 上用 APFS 克隆整个目录(`cp -cR`,几秒钟)。改完核对文件的校验和确实变了:`perl` 的转义写错时,替换会静默落空。

- 先确认失败真的造出来了(`git diff --stat`、文件内容),夹具也真的走到了那条路;撤掉一道保护不变红时,先找有没有重复的保护。
- 改「只用某个东西」的边界时,把那个东西拿掉再跑一次:上游在失败路径上常有兜底的默认值。
- 相信「查无」之前,先喂一个已知的命中,确认检查会响;按名字或形状给文件归类之前,逐个看一眼命中的文件。
- 探测脚本的结论要在真实的代码路径上再看一次。

### 不确定会不会写真实目录的命令

不确定一条命令会不会写真实的数据目录时,把 `HOME`、`XDG_*`、`TMPDIR` 指到临时目录再跑。写入检测只能事后发现,防不住。

### 时间、进程与替身

- 测试里同步写进去的「晚到」输出并不晚,先 `await` 一轮 `setImmediate` 再写;两条管道之间没有先后,跨管道的顺序靠 `sleep` 拉开。
- `node --test` 没有默认超时,要带 `--test-timeout`;假对象要像真的一样回应,否则测的是超时那条路。
- `Bun.serve` 的 `idleTimeout` 默认 10 秒,模拟长时间没有输出的应答要设为 0。
- Effect 的测试里,`yieldNow` 不等真实的 I/O;`it.effect` 用测试时钟,`sleep` 不会醒。等真实的进展用 `it.live` 加按条件的轮询。

### 平台分支

按平台走不同逻辑的代码,把平台当作参数传进来(如 `geoengine/src/runtime.ts` 的 `overlay`),不在函数里读 `process.platform`,测试在 macOS 上就能走 Windows 那条分支。处理 Windows 路径的代码用 `path.win32`(如 `geoengine/src/qgis/windows.ts`),不用跟着本机走的 `path`;要目录树时照 Windows 的布局搭假的(第 6 节的 QGIS)。在 macOS 上测不了的,如真实的 `cmd.exe`、进程树与文件占用,测试里不假装测过,汇报里列为没有验证。

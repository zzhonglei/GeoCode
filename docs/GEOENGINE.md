# 地理引擎

GeoEngine(地理引擎)是 GeoCode 自己的组件,提供应用的全部地理能力。本文档讲各能力域共用的框架;能力域各成一篇:`QGIS.md`、`GEE.md`。

## 1. 定位

GeoEngine 做两件事:管理用户电脑上的地理执行环境,执行地理任务。

管理环境指发现、验证与诊断。GeoEngine 找到用户装好的 QGIS、Python 等软件,列给用户选择;它不替用户选,只找到一套也不自动采用,配置由用户在设置里选定,或由 GeoAgent 照提示写入。它验证这些软件能否真正运行,把问题整理成给用户的诊断与给 GeoAgent 的提示(第 3.3 节)。GeoEngine 不安装软件,也不改动用户已有的环境。怎样补齐由 GeoAgent 决定:它引导用户安装,或经内核的权限规则执行命令去处理。

地理任务与 agent 平常的工作不同:一次空间分析可能运行几十分钟、占用大量内存,调用的外部程序也可能卡住或崩溃。所以地理能力不放进内核或壳服务端,而是单独成为一个进程,任务出了问题不会拖垮界面、壳服务端与内核。

## 2. 在应用中的位置

```
Electron 主进程
 ├─ 壳服务端
 │    └─ 子进程:内核
 ├─ 辅助进程:GeoEngine
 │    └─ 任务子进程:QGIS、Python 等外部程序
 └─ 界面(渲染进程)
```

GeoEngine 运行在 Electron 的辅助进程里,由主进程启动与监管,随应用启动、随应用退出。它不单独构建可执行文件,在进程列表里显示为 GeoCode 的辅助进程。主进程与内核同时启动它,不耽误窗口出现。

GeoEngine 只与主进程通信。内核交来的工具任务与界面对环境的查询与设置,都经壳服务端转达,先过壳服务端的访问控制(`DESKTOP.md` 第 4 节)。

两种失败要分开。外部程序失败、卡住或崩溃,只是一次任务失败,结果照常返回给 GeoAgent。GeoEngine 自己起不来或异常退出,说明应用本身出了问题:应用显示出错页(`DESKTOP.md` 第 6 节),恢复的办法只有重启应用。它不被自动拉起,正在执行的任务以失败结束、不重试,因为执行到一半的任务未必能安全地重跑。

## 3. 结构

代码在仓库根目录的 `geoengine/`,用 TypeScript 与 Effect 编写,构建成一个文件打进应用。它分两层:

- 基础设施层:与地理领域无关的机制。环境配置读写 `machine.json`,在它变动时通知受影响的能力模块;进程执行启动外部程序、交付输出、处理中断与结束;状态记账存储与发布各能力域的环境状态。
- 能力层:每个能力域一个模块,模块之间互不依赖,共同需要的机制下沉到基础设施层。

GeoEngine 对外有两个出口:工具,即内核里的地理工具交来的任务,执行中回报进度,结束时返回结果;状态,即各能力域的环境状态,变化时推给界面。

### 3.1 通道

GeoEngine 与主进程之间只有一条消息通道,走五类消息:请求与应答、进度、中断、状态推送、生命周期的通知。

请求带编号,应答按编号对应,内容是结果或结构化的错误;长任务在应答之前按同一编号回报进度。中断按编号叫停一个任务:GeoEngine 结束它,仍然给出应答,因为主进程等到这个应答才了结这次请求。生命周期的通知包括启动完成、退出前的清扫,以及每个任务进程的登记与注销;主进程据此在 GeoEngine 崩溃时结束它留下的任务。

通道本身不设超时。任务运行多久由能力域按任务的性质判断,或交给调用方;只有启动(第 5 节)与退出前的清扫有时限;清扫超时就直接退出,应用不能因此退不出去。

地理工具到达这条通道之前,经过壳服务端里 GeoCode 自己的流式接口。它不设超时,逐段转回进度;工具调用被取消时请求断开,壳服务端把它转成一条中断。它只用回调令牌确认来电的是这个应用自己的内核,不做权限判断(第 4 节)。agent 执行的命令也读得到这个令牌、能直接调用它,这与 agent 直接运行 QGIS 等价,同样归 `shell` 的权限管,所以不另设防。

### 3.2 环境配置

环境信息都记在配置目录的 `machine.json` 里(`PATHS.md` 第 2 节),每个能力域一块,记外部软件的位置与所需的标识。它不并进内核的 `geocode.json`:后者在加载时读取,`machine.json` 保存即生效;它记的全是本机的绝对路径,换一台电脑就不再成立。

用户在设置里的选择由 GeoEngine 写进文件,发现的结果不写。用户手改与 GeoAgent 改同样生效:GeoEngine 监听这个文件,变动后只重新检查变了的那几块。文件不支持注释,因为 GeoEngine 也写它,写回时注释留不住。文件被改得无法解析时,各能力域都进入配置错误的状态并给出出错的位置;GeoEngine 不覆盖它,以免抹掉用户手写的内容。

### 3.3 环境状态

每个能力域有一份环境状态,取值是几种状态之一,整体替换,变化时推送。检查中也是正式的状态。各能力域都有未配置与配置错误,其余状态由能力域自己定义。

失败时有两类信息,给不同的读者:

- 诊断给用户:定位问题所需的事实,如路径、版本、各检查项的结果与原始错误。它与状态名一样是日志式的信息,只用英文;界面只显示它,不附建议。
- 提示给 GeoAgent:下一步该做什么,在工具因环境没有就绪被拒时由能力模块按状态生成,写明 GeoAgent 能自己做什么、哪些要请用户做。

界面在标题栏为每个能力域显示一个指示灯:就绪为绿色,检查中为黄色,未配置与设置还没走完的为灰色,其余失败为红色。未配置不是故障,刚装好应用的用户不该看到红灯。点开指示灯显示状态与诊断,可以整份复制;给 GeoAgent 的提示不显示。

设置里的「地理环境」页集中管理各能力域的环境,一行一个能力域。点进去列出在这台电脑上找到的安装与版本,用户点选一套即写入配置并重新检查,也可以指定别处的安装,或要求重新检查。列出安装只读安装包自带的信息,不启动软件;完整的验证只对选中的那一套做。界面平时不显示 `machine.json` 的位置,只在它无法解析时写进诊断:用户在设置里配置,或交给 GeoAgent,不需要去找这个文件。

地理工具执行之前先看环境:检查中就等它落定,等待有上限;没有就绪就不执行,把提示返回给 GeoAgent。有的改变不经过配置文件(如在原处重装软件),所以各能力域决定工具调用时要不要再检查一次。

### 3.4 给 GeoAgent 的文字

工具的答复只陈述事实:执行了什么、得到了什么、怎样结束。下一步由 GeoAgent 判断,答复不替它决定,也不写「告诉用户」这类话;它解决不了的自然会告诉用户,用户在对话里也看得到同样的内容。环境没有就绪时的提示是例外,引导 GeoAgent 动手正是它的用途。另有两处同样写明下一步:GeoCode 内部出错时只有重启应用可能恢复,而这只有用户能做,答复请 GeoAgent 告诉用户;后台运行开始时,答复照内核 shell 命令的写法,说明怎样等待结果。

GeoAgent 不是开发者。工具说明、答复与出错的说明只告诉它做事需要的,不讲 GeoCode 的内部实现。

## 4. 边界

GeoEngine 只执行任务、管理执行环境。agent、工具的定义与权限都在内核:地理工具与 OpenCode 自带的工具一样作为内置插件编进内核,直接用内核的权限服务,由权限规则决定是否询问,在设置里同样管理。它们不经插件 API 提供,因为插件 API 交给工具的上下文发不起询问。执行任务的请求都已经过这一关;询问之前到达 GeoEngine 的只是环境与参数的检查,不执行任何东西。GeoEngine 自己不做权限判断。

## 5. 约束

- 不开端口。与外界的全部通信经过主进程;以后加任何通道,都不能让本机的其他程序直接连到 GeoEngine。唯一的例外是在设置里登录 GEE 时的临时端口(`GEE.md` 第 7 节)。
- 任务要能长时间运行:执行中回报进度,能被用户中断;从内核到 GeoEngine 的整条链路上,没有比任务更短的超时。内核回收空闲工作目录的服务时,正在前台执行地理任务的不算空闲。
- 启动不能卡住。能力模块按顺序注册,全部注册完才报告启动完成,主进程等 30 秒没等到就显示出错页;所以环境检查放到后台,用状态推送报告进展。注册时出错的能力模块被跳过,引擎照常启动。
- 一个任务不能拖垮引擎。能力模块里意外的错误转成这一次请求的错误应答;大块数据交给外部程序处理,不整块读进引擎的内存,因为引擎本身崩溃就是出错页。
- 管好进程的生命周期。外部程序不会随 GeoEngine 退出,要由它结束:任务被中断、应用正常退出时(主进程先等它清扫完),结束的都是整棵进程树;GeoEngine 崩溃时,由主进程结束它留下的任务。整个应用被强制结束、崩溃或断电时,留下的任务会自己跑完,不做补救:它不损坏数据、不会累积,而补救要在每次启动里长期维持正确。
- Windows 没有进程组,也没有先礼后兵的信号:任务在运行时按进程树强制结束;任务退出之后,它留下的子进程不再结束,因为退出后的进程号可能已被复用,按进程号结束会误伤。内核执行命令时也这样处理。
- 输出按 UTF-8 读取。Windows 上的命令行程序默认用系统的本地代码页输出,启动外部程序时要让它以 UTF-8 输出,否则中文的报错与路径会变成乱码。
- 用户环境与内核相同:GeoEngine 拿到的是并入登录 shell 之后的环境,用户装在 conda 或系统里的软件能被找到。`DESKTOP.md` 第 5 节所列前缀的变量都去掉,开发版也一样,因为开发时主进程的环境里就有启动脚本传参用的这类变量。访问外网同样跟随用户自己的网络配置,不设 GeoEngine 自己的出口。
- GeoEngine 自己写的文件只放在 GeoCode 的目录里(`PATHS.md`)。外部软件运行时写它自己的配置与缓存,照它的默认位置,不归 GeoCode 管。
- macOS 与 Windows 同等对待,两个平台的安装布局与路径规则都要覆盖。

## 6. 验收

- 应用正常退出之后,没有残留的 GeoEngine 进程与任务子进程(Windows 上任务自己退出后留下的除外);应用被强制结束之后,GeoEngine 随之结束。
- GeoEngine 崩溃或被结束时,主进程不受影响,它留下的任务子进程被结束,应用显示出错页;重启应用后恢复正常。
- 运行期间 GeoEngine 不监听任何端口,第 5 节所说的例外除外。
- 一个运行超过十分钟的任务能完整跑完,期间进度持续回报;中途中断时任务停止,它启动的外部程序随之结束。
- 写入检测干净,GeoEngine 自己写的文件都落在 `PATHS.md` 列出的位置。

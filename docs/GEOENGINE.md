# 地理引擎

GeoEngine(地理引擎)是 GeoCode 自己的组件,为整个应用提供地理数据相关的能力。本文档说明它的定位、在应用中的位置、结构、边界、约束与验收。各能力域共用一套框架,逐个接入,各自的设计做到那一个时补进本文档;仍未决定的问题列在第 8 节。

## 1. 定位

GeoEngine 做两件事:管理用户电脑上的地理执行环境,执行地理任务。能力域按 QGIS、Google Earth Engine、OpenStreetMap、GDAL 的顺序接入。

管理环境指发现、验证与诊断:GeoEngine 在常见的安装位置找到用户装好的 QGIS、Python 等软件,列给用户在设置里选择,找不到时由用户指定位置,用哪一套总是由用户决定,GeoEngine 不替用户选;它验证这些软件能否真正运行,把缺什么、出了什么问题整理成提示信息交给 GeoAgent。GeoEngine 不安装软件,也不改动用户已有的环境;怎样补齐由 GeoAgent 决定,它引导用户安装,或经内核的权限规则执行命令去处理。QGIS、Google Earth Engine、GDAL 与 Python 的环境各有各的发现与验证方式,在做到对应的能力域时决定。

地理任务与 agent 平常的工作不同:一次空间分析或遥感计算可能运行几分钟甚至更久,占用大量内存,调用的外部程序也可能卡住或崩溃。所以地理能力不放进内核,也不放进壳服务端,而是单独成为一个进程:任务出了问题,不会拖垮界面、壳服务端与内核。

## 2. 在应用中的位置

```
Electron 主进程
 ├─ 壳服务端
 │    └─ 子进程:内核
 ├─ 辅助进程:GeoEngine
 │    └─ 任务子进程:QGIS、Python 等外部程序
 └─ 界面(渲染进程)
```

GeoEngine 由主进程启动与管理,随应用启动、随应用退出,启动时检查各能力域的执行环境。主进程在并入登录 shell 的环境之后启动它,与内核同时启动,不耽误窗口出现;它在限定的时间里报告启动完成,之前到达的请求先挂着。它与内核一样是应用的私有组件,只为这个应用服务。外部程序失败、卡住或崩溃,都只是一次任务失败,结果返回给 GeoAgent;GeoEngine 自己起不来或异常退出,说明应用本身出了问题,所以不自动重新拉起,也不提供重试,应用显示出错页(见 `DESKTOP.md` 第 6 节),恢复的办法只有重启应用。正在执行的任务以失败结束,不自动重试,因为执行到一半的任务未必能安全地重跑。

GeoEngine 不监听任何端口,只与主进程通信:agent 调用的地理工具与界面都经壳服务端转达到它,本机的其他程序连不到它,能到达它的请求都先经过壳服务端的访问控制(见 `DESKTOP.md` 第 4 节)。

GeoEngine 运行在 Electron 的辅助进程里,不单独构建可执行文件,所以在进程列表里显示为 GeoCode 的辅助进程(macOS 上是「GeoCode Helper」)。它启动的外部程序显示各自的名字。

## 3. 结构

GeoEngine 分两层。基础设施层提供与地理领域无关的机制:环境配置(读写 `machine.json`,在它变动时通知受影响的能力模块)、进程执行(启动外部程序、交付输出、超时与中断、结束整棵进程树)、状态记账(各能力域的环境状态的存储、发布与快照),以及访问外网的网络出口(做到第一个需要外网的能力域时建立)。能力层在其上实现各个能力域。能力模块之间互不依赖,共同需要的机制下沉到基础设施层。

GeoEngine 对外有三个出口,都经主进程:

- 工具:内核里的地理工具经壳服务端把任务交给 GeoEngine,执行中回报进度,结束时返回结果;环境没有就绪时,GeoAgent 得到下一步的提示,诊断记入内核的日志。
- 状态:各能力域的环境状态,注册时与每次变化时整体推送给主进程;界面从主进程一次取全并接收变化,据此显示环境是否就绪。
- 数据:界面要显示的预览数据,经壳服务端的接口按请求取得。

代码在仓库根目录的 `geoengine/`,与 `kernel/`、`desktop/` 并列,用 TypeScript 与 Effect 编写,打包时编进应用。

### 3.1 与主进程的通道

GeoEngine 与主进程之间只有一条消息通道,上面走五类消息:请求与应答、进度、中断、状态推送、生命周期的通知。

每个请求带一个编号,应答按编号对应,内容是结果或结构化的错误;长任务在应答之前按同一编号回报进度。中断按编号叫停一个任务:GeoEngine 结束它的整棵进程树,仍然给出应答,标明已中断,并带上已经产生的输出,因为这时已有的输出正是调用方最需要的。生命周期的通知包括 GeoEngine 启动完成、退出前的清扫与清扫完毕,以及每个任务进程的登记与注销,主进程据此在 GeoEngine 崩溃时结束它留下的任务。任务进程一退出就注销,不等它的输出读完:退出后的进程号可能已被别的进程复用。

通道本身不设超时,任务运行多久由 GeoEngine 按任务的性质判断;只有退出前的清扫有时限,超时就直接退出,应用不能因此退不出去。GeoEngine 崩溃时,主进程把未完成的请求以错误结束。各能力域的最新状态由主进程统一接收并保存。收到的消息在接收的一端校验一次,预览这类二进制数据随消息直接转移,不另做编码。

外部的两条链路接在这条通道上。地理工具向壳服务端发出的请求不设超时、带着中断信号,壳服务端以流式应答逐段转回进度,工具调用被取消时请求断开,壳服务端把它转成一条中断。接收工具请求的是壳服务端里 GeoCode 自己的接口,它只确认来电的是这个应用自己的内核,不做权限判断:到达它的任务已经过内核的权限规则(见第 4 节)。界面的快照与数据经壳服务端的接口取得,状态的变化经壳服务端已有的推送通道送达。

### 3.2 环境配置

环境信息都记在 `machine.json` 里:各外部软件的位置与所需的标识。它与内核的 `geocode.json` 放在同一个配置目录(见 `PATHS.md`),但不合成一个文件:`geocode.json` 在加载时读取,`machine.json` 保存即生效;它记的全是本机的绝对路径,换一台电脑就不再成立。

文件是一个 JSON 对象,每个能力域一块,块里记什么在做到那个能力域时决定。块是变化的单位:某一块变了,只重新检查那个能力域;是否变化按解析后的值比较,调整格式与键的顺序不算变化。不认识的键忽略,一块写错只影响这一块。文件不支持注释:GeoEngine 也写这个文件,写回时注释留不住。

用户在设置里的选择由 GeoEngine 写进文件,它是唯一的写入方,发现的结果不写进文件;写入先写临时文件再改名,文件不会停在写了一半的状态。用户手改同样生效:GeoEngine 监听配置目录,文件变动后重读。文件被改得无法解析时,各能力域都进入配置错误的状态,带着出错的位置,GeoEngine 不覆盖它,以免抹掉用户手写的内容。

### 3.3 环境状态

每个能力域有一份环境状态,取值是以状态标识区分的几种状态之一,每次整体替换,没有变化就不推送。检查中这类中间态也是正式的状态;每个能力域的状态都包含未配置与配置错误,其余由能力域自己定义。旧一轮检查的结果不会覆盖新一轮的。

失败的状态带两类信息,给不同的读者。给界面的是诊断,即定位问题所需的事实:路径、版本、各检查项的结果、原始错误,界面按自己的语言呈现。给 GeoAgent 的是提示,即下一步该做什么,由能力模块自己生成;不同的错误给出不同的提示,具体内容写在各能力域里。

界面在标题栏为每个有状态的能力域显示一个指示灯,颜色按状态归类:就绪为绿色,检查中为黄色,未配置为灰色,其余的失败为红色。未配置不是故障,刚装好应用、还没有配置的用户不该看到红灯。点开指示灯,显示状态的说明与诊断,诊断可以整份复制;给 GeoAgent 的提示不显示。界面不显示 `machine.json` 的位置:环境在设置里配置,也可以交给 GeoAgent,用户不需要去找这个文件。界面打开时先读一次快照,之后接收变化,推送通道断线重连后再读一次;晚到的快照不会盖掉已经收到的变化。

设置里的「地理环境」一页集中管理各能力域的环境,与指示灯读同一份状态。页面先是各能力域的列表,一行一个,一眼看到各自的状态,点进去是这个能力域的详情;加一个能力域只是多一行。详情里列出在这台电脑上找到的安装与各自的版本,用户点选一套即写入配置并重新检查,也可以指定别处的安装;另有重新检查,软件原地重装或升级之后不必重启应用。列出安装只读安装包自带的信息,不启动软件,完整的验证只对选中的那一套做。

地理工具执行之前先看环境:还在检查中,就等它落定,等待有上限;没有就绪,就不执行,把提示返回给 GeoAgent;就绪才执行。

## 4. 边界

GeoEngine 只负责执行任务与管理执行环境。agent、工具的定义与权限都在内核:地理工具是内核的内置工具,与 OpenCode 自带的工具一样,由内核的权限规则决定执行前是否询问用户;每个地理工具的权限各不相同,写在各能力域里(QGIS 见第 7.5 节)。到达 GeoEngine 的任务都已经过这一关,GeoEngine 自己不做权限判断。

界面要显示的地理状态与数据(执行环境是否就绪、数据的预览)同样经壳服务端从 GeoEngine 取得,界面不直接与它通信。

## 5. 约束

- 不开端口。GeoEngine 与外界的全部通信经过主进程;以后加任何通道,都不能让本机的其他程序直接连到它。
- 任务要能长时间运行。执行中要能回报进度、能被用户中断;从内核到 GeoEngine 的整条链路上,不能有比任务更短的超时。
- 管好进程的生命周期。GeoEngine 随应用退出,但它启动的外部程序不会自动跟着退出,要由 GeoEngine 负责结束:任务被中断时,应用正常退出时(主进程先等 GeoEngine 清扫完再退出),结束的都是整棵进程树。GeoEngine 自己崩溃时无法清扫,由仍在运行的主进程结束它留下的任务。整个应用被强制结束、崩溃或断电时,进程内无从清理,留下的任务会自己跑完,不做补救:它不损坏数据、也不会累积,而补救要在每个脚本或每次启动里长期维持正确。Windows 没有进程组,也没有可以先礼后兵的信号:任务在运行时,按进程树强制结束;任务退出之后,它留下的子进程不再结束,因为退出后的进程号可能已被别的进程复用,按进程号结束整棵树会误伤。内核执行命令时也是这样处理的。
- 输出按 UTF-8 读取。Windows 上的命令行程序默认用系统的本地代码页输出(如简体中文系统的 GBK、繁体中文系统的 Big5),能力模块启动外部程序时要让它以 UTF-8 输出,否则中文的报错与路径会变成乱码。
- 用户环境与内核相同。GeoEngine 拿到的环境是登录 shell 的变量按 `DESKTOP.md` 第 5 节清理之后的那一份,用户装在 conda 或系统里的 QGIS、GDAL、Python 能被找到。应用为壳与内核写入的同前缀变量也不交给它,地理任务看不到它们。
- GeoEngine 自己写的文件只放在 GeoCode 自己的目录里(见 `PATHS.md`),新增的目录在实现时补进 `PATHS.md`。外部软件运行时写它自己的配置与缓存(如 QGIS 在用户目录下的配置与缓存),照它的默认位置,不归 GeoCode 管。
- macOS 与 Windows 同等对待,两个平台的安装布局与路径规则都要覆盖。
- 对内核与壳的上游代码,只改接入所需的几处(见 `CONVENTIONS.md` 第 3 节)。

## 6. 验收

框架的验收如下,各能力域的验收做到时补充。

- 应用正常退出之后,没有残留的 GeoEngine 进程与任务子进程(Windows 上任务自己退出后留下的除外,见第 5 节);应用被强制结束之后,GeoEngine 随之结束。
- GeoEngine 崩溃或被结束时,主进程不受影响;它留下的任务子进程被结束,正在执行的任务以失败结束,应用显示出错页并给出原因,重启应用后恢复正常。
- 运行期间,GeoEngine 没有监听任何端口。
- 一个运行超过十分钟的任务能完整跑完,期间进度持续回报;中途中断时任务停止,它启动的外部程序随之结束。
- 写入检测干净,GeoEngine 自己写的文件都落在 `PATHS.md` 列出的位置。

## 7. QGIS

QGIS 能力域让 GeoEngine 在用户安装的 QGIS 里执行空间处理算法。执行载体只有 QGIS 自带的 Python:算法、PyQGIS 脚本与数据读取都要在这个解释器里运行,只用它就只需维护一套环境组装与一套验证;`qgis_process` 同在这个安装里,不另外支持。范围是 QGIS 内置的算法,第三方插件提供的算法不在其中。

### 7.1 支持的安装

支持 QGIS 官方的安装包:macOS 上的应用包,Windows 上的独立安装包与 OSGeo4W,版本覆盖 4.x 与 3.x 的长期支持版。conda、Homebrew 等其他来源的 QGIS 不支持。两个平台的安装布局与环境组装方式完全不同,各自单独实现。

macOS 只支持与 3.44、4.x 相同的应用包布局:解释器在应用包的可执行目录里,旁边有官方的 `python` 启动脚本。更早的版本是另一种布局,遇到时报告为不支持的版本,不去猜测它的结构。应用包的路径里不能有空格:官方的 `python` 启动脚本没有给路径加引号,路径带空格时它自己就启动不了解释器;这是 QGIS 打包的问题,GeoCode 不绕开它,这样的安装检查时报告为出错,原始输出里有原因。

### 7.2 配置与环境组装

`machine.json` 的 `qgis` 块记一个路径,GeoEngine 用的就是它指向的那一套 QGIS。macOS 上路径指向应用包,落在应用包内部时取它所在的应用包。

列给用户选的安装按应用的身份找,不按名字:应用包可以被改名或放在别处。macOS 上取 `/Applications` 与 `~/Applications` 下的应用包,再加上 Spotlight 按包标识找到的,包标识以 `org.qgis.` 开头的都算,版本取自应用包的信息文件。`/Volumes` 下的不列出,即磁盘映像与外接磁盘上的:推出之后它就不存在了,要用时仍可以手动指定;废纸篓里的也不列出。布局不是 3.44、4.x 的照样列出,标明不支持,不能选。

环境采用 QGIS 自己的答案:macOS 上以官方的 `python` 启动脚本运行解释器,只叠加 GeoCode 的场景需要、而 QGIS 不会替它设置的几项。投影与 GDAL 的数据目录要显式给出:官方脚本只设了 Python 的位置,缺了它们 GDAL 找不到投影数据库,坐标变换静默失败。从登录 shell 继承来的 `PYTHONPATH` 要清空:它常由 conda 这类工具设置,会把另一个 Python 的包排到 QGIS 自带的包前面,让 QGIS 的 Python 连 numpy 都导入不了;从访达打开的 QGIS 本来就看不到它。

脚本输出结果之后直接结束进程,跳过 QGIS 的退出清理:有的版本在清理时崩溃,会把一次成功的执行报成失败。

### 7.3 验证与状态

验证由一段探针脚本在组装好的环境里完成,依次检查 GDAL 能否导入、能否完成一次真实的坐标变换、QGIS 核心能否导入、处理框架能否初始化,前一步失败就不再往下查。坐标变换单独成一步,因为投影库在数据库缺失时照样能导入,要到真正变换时才失败。

状态除了各能力域共有的未配置与配置错误,还有平台不支持、路径不存在、不是 QGIS、不支持的版本、检查中、探针各步骤的失败、探针超时或崩溃,以及就绪。检查在 GeoEngine 启动时、`qgis` 块变化时与用户要求重新检查时进行,被中途停下(如应用退出)的检查不改变状态。失败的状态带上诊断(配置的路径、应用包与版本、解释器、探针的原始输出)与给 GeoAgent 的提示。

### 7.4 执行算法

每次执行算法是一个独立的任务进程:在就绪的环境里由运行脚本承载,算法标识与参数随请求传入,执行中按处理框架报告的进度回报,中断时结束整棵进程树,结束时返回结果与输出。算法要运行多久无从预估,所以不设总时限,只按空闲时间计算;运行脚本按处理框架报告的进度逐个百分点回报,让空闲计时重新开始。

### 7.5 工具

QGIS 能力域给 agent 三个工具。它们是内核的内置工具,与 OpenCode 自带的工具同样注册、同样询问,直接列在模型的工具清单上,不收进 Code Mode。名字照自带工具的写法:全小写,不用下划线(下划线是命名空间的标记),也不以 `geocode` 开头,以免与壳的 `geocode_web` 等工具混淆。

| 工具 | 做什么 | 权限参照的自带工具 |
|---|---|---|
| `readgeodata` | 读一份地理数据:坐标系、范围、字段、统计与要素,栅格可以出预览图 | `read` |
| `qgisdoc` | 查本机 QGIS 的算法目录:分组、算法、帮助与搜索 | `grep`、`glob` |
| `qgisrun` | 执行一个 QGIS 算法 | 按整个工具询问,另查输出的位置 |

权限的逻辑与自带工具一致,设置里的工具权限管理它们,与管理自带工具相同;「始终允许」同样由内核按项目保存。`readgeodata` 把数据内容交给模型,所以与 `read` 完全相同:工作区以外的文件先问能否访问项目外的目录,再按读取的规则判断,读取的规则同时管着这两个工具。`qgisdoc` 只读应用自己掌握的信息,与 `grep`、`glob` 一样每次检查、默认放行。

`qgisrun` 按整个工具询问,不按算法逐个设权限:QGIS 的算法有数百种,逐个授权既不合理,也容易在少数算法上出意外。它的输入不检查,读数据的是 QGIS,数据内容不经过模型;要守住的是输出写到哪里,输出落在会话目录与项目之外时,先问能否访问项目外的目录。输出按算法的参数定义认出:QGIS 的输出类参数同属一类(`QgsProcessingDestinationParameter`),不必为每个算法写规则。认不出的参数类型、拆不开的写法,以及临时输出、数据库、网络服务这类不是文件的值,都当作不是路径,不询问,照常执行。权限只决定问不问,不改动参数,也不自己拦下执行,所以执行分三步:GeoEngine 先解析算法与参数、列出输出,不执行任何东西;内核据此询问;得到允许后,GeoEngine 按检查过的参数原样执行。

`qgisdoc` 的内容全部来自本机 QGIS 自己的算法定义,不靠 GeoCode 手写:各版本的算法与参数不同,手写的说明与示例总会在某个版本上出错。目录只含 native、qgis、gdal 三个提供方,并剔除 QGIS 标为不能在独立工具中运行的算法,它们要用 QGIS 的界面或打开的项目,`qgis_process` 同样不列它们;目录在第一次查询时导出,换一套 QGIS 后重新导出。四个动作:`groups` 列出分组,`algorithms` 列出一个分组里的算法,`help` 读一个算法的文档,`search` 按英文词搜索(目录是英文的,模型读英文也更准)。算法的写法可以有出入,大小写、空格与标点都不影响查找,但不猜:一个名字对应多个算法时,列出全部候选让模型选。算法文档以 `qgis_process help` 为底稿,这是 QGIS 为命令行写的帮助,只补上它没写而调用需要的三样:能否多选、字段与波段等属于哪个图层、高级参数;删去或改正在 GeoEngine 的运行方式下会失败的写法;QGIS 没给说明的就不写。每份有内容的答复开头带 QGIS 的版本,文档末尾给出同一版本的官方手册里这个算法那一节的链接,提示有疑问时用 `webfetch` 去读。

官方手册一个分组一页,大的有上百 KB,超过内核给工具结果的上限,模型只能看到开头一段;所以 GeoCode 让 `webfetch` 读 QGIS 官方手册(`docs.qgis.org`)时像浏览器跳到锚点一样,链接带锚点就只返回那一节;不带锚点或找不到这一节时只返回正文,不含网站的导航与页脚,找不到时另加说明。别的网站照 OpenCode 原样返回。

`qgisrun` 由模型写一句这一步的用途,与 `subagent` 的 `description` 相同,显示在对话与询问卡片上;没写也照常执行。运行中界面显示计时,收到进度时一并显示百分比:QGIS 自身的算法逐步报告进度,调用 GDAL 命令行的算法在无界面运行时直到结束才有输出,没有百分比可显示。所以计时始终在,百分比有才显示,不做估算出来的进度条。

界面沿用 OpenChamber 显示自带工具的方式,对话里的工具行、询问卡片与设置里的工具权限都用同一套组件(`qgisdoc` 的工具行除外,见下)。GeoCode 只补上自己的内容:彩色的图标(QGIS 的工具用 QGIS 的标志),随界面语言切换的标题,以及 QGIS 工具自己的卡片正文,即算法的名称与标识、用途,按输入、参数与输出分开列出的参数,项目外的输出单独标出。`readgeodata` 的预览图在对话里显示。

`qgisdoc` 只是查阅,对话里不逐次列出:相邻的调用合成一行,中间隔着文字、思考、别的工具等任何显示出来的内容才分开,跨步也照样合并。这一行只有 QGIS 的标志与「正在阅读 QGIS 文档」或「已阅读 QGIS 文档」,不能展开:模型可能还会接着读时(这一行仍在本轮末尾、本轮还在进行)显示前者,并在右侧逐个显示最近一次读的分组、算法或搜索词;读完之后不列读了什么。出错的调用不另外显示,由 GeoAgent 告诉用户。`webfetch` 读 QGIS 官方手册时,展开它的卡片看到的是手册网页本身,缩小显示并停在链接所指的那一节;网页加载不了(没有网络、出错或超时)时仍显示 `webfetch` 返回的文字。别的网站的卡片照 OpenChamber 原样。

### 7.6 验收

- 配置指向 3.44 与 4.x 的官方应用包后,状态变为就绪;内置算法在两个版本上都能执行,含中文的路径与属性正确无误。
- 执行中进度持续回报;中断后任务进程与它启动的程序都结束。
- 路径不存在、不是 QGIS、不支持的版本、缺少投影数据,各自报告为对应的状态,并带有诊断。
- 界面的 QGIS 指示灯随状态变化:改动 `qgis` 块后先变为检查中,再落到新的状态;打开新窗口或推送断线重连后,显示的仍是当前状态。
- 设置里列出本机安装的每一套 QGIS 与版本,包括改过名的;选中一套后,设置页与指示灯一起先变为检查中,再落到新的状态。原地替换 QGIS 之后,重新检查得到新的结果。
- `qgisdoc` 在 3.44 与 4.x 上都能列出分组、算法与文档,文档里标出能否多选与所属图层;被剔除的算法答以不可用,不说成不存在;有歧义的名字给出候选。文档末尾的链接经 `webfetch` 打开,得到的是同一版本手册里这个算法那一节。
- 三个工具在设置的工具权限里都有对应的规则(`readgeodata` 归读取),把规则设为询问或拒绝,行为与自带工具相同。
- 规则不要求询问 `qgisrun` 时,输出写在会话目录或项目里就直接执行,写到外面时询问一次;两个版本的全部内置算法,输出参数都能认出,其余参数都不被当作输出。
- 在对话里停止 `qgisrun`,任务进程随之结束;运行中显示计时,QGIS 自身的算法同时显示百分比。

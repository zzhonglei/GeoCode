# 地理引擎

GeoEngine(地理引擎)是 GeoCode 自己的组件,为整个应用提供地理数据相关的能力。本文档说明它的定位、在应用中的位置、结构、边界、约束与验收。GeoEngine 先搭好各能力域共用的框架,再逐个接入能力域;各能力域的设计做到那一个时再写,仍未决定的问题列在第 7 节。

## 1. 定位

GeoEngine 做两件事:管理用户电脑上的地理执行环境,执行地理任务。能力域按 QGIS、Google Earth Engine、OpenStreetMap、GDAL 的顺序接入。

管理环境指发现、验证与诊断:GeoEngine 在常见的安装位置找到用户装好的 QGIS、Python 等软件,找不到或同时有多套时由用户在界面里选择或指定;它验证这些软件能否真正运行,把缺什么、出了什么问题整理成提示信息交给 GeoAgent。GeoEngine 不安装软件,也不改动用户已有的环境;怎样补齐由 GeoAgent 决定,它引导用户安装,或经内核的权限规则执行命令去处理。QGIS、Google Earth Engine、GDAL 与 Python 的环境各有各的发现与验证方式,在做到对应的能力域时决定。

地理任务与 agent 平常的工作不同:一次空间分析或遥感计算可能运行几分钟甚至更久,占用大量内存,调用的外部程序也可能卡住或崩溃。所以地理能力不放进内核,也不放进壳服务端,而是单独成为一个进程:任务出了问题,不会拖垮界面、壳服务端与内核。

## 2. 在应用中的位置

```
Electron 主进程
 ├─ 壳服务端
 │    └─ 子进程:内核
 ├─ 子进程:GeoEngine
 │    └─ 任务子进程:QGIS、Python 等外部程序
 └─ 界面(渲染进程)
```

GeoEngine 由主进程启动与管理,随应用启动、随应用退出,启动时检查各能力域的执行环境。它与内核一样是应用的私有组件,只为这个应用服务。它异常退出时,主进程自动把它重新拉起,连续失败到一定次数就停止;正在执行的任务以失败结束,原因告知 GeoAgent,不自动重试,因为执行到一半的任务未必能安全地重跑。

GeoEngine 不监听任何端口,只与主进程通信:agent 调用的地理工具与界面都经壳服务端转达到它,本机的其他程序连不到它,能到达它的请求都先经过壳服务端的访问控制(见 `DESKTOP.md` 第 4 节)。

GeoEngine 运行在 Electron 的辅助进程里,不单独构建可执行文件,所以在进程列表里显示为 GeoCode 的辅助进程(macOS 上是「GeoCode Helper」)。它启动的外部程序显示各自的名字。

## 3. 结构

GeoEngine 分两层。基础设施层提供与地理领域无关的机制:环境配置(读写 `machine.json`,在它变动时通知受影响的能力模块)、进程执行(启动外部程序、交付输出、超时与中断、结束整棵进程树)、状态记账(各能力域的环境状态的存储、发布与快照),以及访问外网的网络出口(做到第一个需要外网的能力域时建立)。能力层在其上实现各个能力域。能力模块之间互不依赖,共同需要的机制下沉到基础设施层。

GeoEngine 对外有三个出口,都经主进程:

- 工具:内核里的地理工具经壳服务端把任务交给 GeoEngine,执行中回报进度,结束时返回结果;环境没有就绪时,返回诊断与下一步的提示,由 GeoAgent 处理。
- 状态:各能力域的环境状态,注册时与每次变化时整体推送给主进程;界面从主进程一次取全并接收变化,据此显示环境是否就绪。
- 数据:界面要显示的预览数据,经壳服务端的接口按请求取得。

代码在仓库根目录的 `geoengine/`,与 `kernel/`、`desktop/` 并列,用 TypeScript 与 Effect 编写,打包时编进应用。

### 3.1 与主进程的通道

GeoEngine 与主进程之间只有一条消息通道,上面走五类消息:请求与应答、进度、中断、状态推送、生命周期的通知。

每个请求带一个编号,应答按编号对应,内容是结果或结构化的错误;长任务在应答之前按同一编号回报进度。中断按编号叫停一个任务:GeoEngine 结束它的整棵进程树,仍然给出应答,标明已中断,并带上已经产生的输出,因为这时已有的输出正是调用方最需要的。生命周期的通知包括 GeoEngine 启动完成、退出前的清扫与清扫完毕,以及每个任务进程的登记与注销,主进程据此在 GeoEngine 崩溃时结束它留下的任务。任务进程一退出就注销,不等它的输出读完:退出后的进程号可能已被别的进程复用。

通道本身不设超时,任务运行多久由 GeoEngine 按任务的性质判断;只有退出前的清扫有时限,超时就直接退出,应用不能因此退不出去。GeoEngine 崩溃时,主进程把未完成的请求以错误结束。各能力域的最新状态由主进程统一接收并保存;GeoEngine 重新启动后,各能力域在注册时重新推送,主进程先清空旧值再接收。收到的消息在接收的一端校验一次,预览这类二进制数据随消息直接转移,不另做编码。

外部的两条链路接在这条通道上。地理工具向壳服务端发出的请求不设超时、带着中断信号,壳服务端以流式应答逐段转回进度,工具调用被取消时请求断开,壳服务端把它转成一条中断。界面的快照与数据经壳服务端的接口取得,状态的变化经壳服务端已有的推送通道送达。

### 3.2 环境配置

环境信息都记在 `machine.json` 里:各外部软件的位置与所需的标识。它与内核的 `geocode.json` 放在同一个配置目录(见 `PATHS.md`),但不合成一个文件:`geocode.json` 在加载时读取,`machine.json` 保存即生效;它记的全是本机的绝对路径,换一台电脑就不再成立。

文件是一个 JSON 对象,每个能力域一块,块里记什么在做到那个能力域时决定。块是变化的单位:某一块变了,只重新检查那个能力域;是否变化按解析后的值比较,调整格式与键的顺序不算变化。不认识的键忽略,一块写错只影响这一块。文件不支持注释:GeoEngine 也写这个文件,写回时注释留不住。

自动发现的结果与用户在界面里的选择都由 GeoEngine 写进文件,它是唯一的写入方;写入先写临时文件再改名,文件不会停在写了一半的状态。用户手改同样生效:GeoEngine 监听配置目录,文件变动后重读,另有一个立即重读的请求,供界面写完之后与监听失效时使用。文件被改得无法解析时,各能力域都进入配置错误的状态,带着出错的位置,GeoEngine 不覆盖它,以免抹掉用户手写的内容。

### 3.3 环境状态

每个能力域有一份环境状态,取值是以状态标识区分的几种状态之一,每次整体替换,没有变化就不推送。检查中这类中间态也是正式的状态;每个能力域的状态都包含未配置与配置错误,其余由能力域自己定义。旧一轮检查的结果不会覆盖新一轮的。

失败的状态带两类信息,给不同的读者。给界面的是诊断,即定位问题所需的事实:路径、版本、各检查项的结果、原始错误,界面按自己的语言呈现。给 GeoAgent 的是提示,即下一步该做什么,由能力模块自己生成;不同的错误给出不同的提示,具体内容在做到对应的能力域时决定。

地理工具执行之前先看环境:还在检查中,就等它落定,等待有上限;没有就绪,就不执行,把状态与提示返回给 GeoAgent;就绪才执行。

## 4. 边界

GeoEngine 只负责执行任务与管理执行环境。agent、工具的定义与权限都在内核:地理工具是内核的内置工具,与 OpenCode 自带的工具一样,由内核的权限规则决定执行前是否询问用户;每个地理工具的权限各不相同,在把它接入内核时决定。到达 GeoEngine 的任务都已经过这一关,GeoEngine 自己不做权限判断。

界面要显示的地理状态与数据(执行环境是否就绪、数据的预览)同样经壳服务端从 GeoEngine 取得,界面不直接与它通信。

## 5. 约束

- 不开端口。GeoEngine 与外界的全部通信经过主进程;以后加任何通道,都不能让本机的其他程序直接连到它。
- 任务要能长时间运行。执行中要能回报进度、能被用户中断;从内核到 GeoEngine 的整条链路上,不能有比任务更短的超时。
- 管好进程的生命周期。GeoEngine 随应用退出,但它启动的外部程序不会自动跟着退出,要由 GeoEngine 负责结束:任务被中断时,应用正常退出时(主进程先等 GeoEngine 清扫完再退出),结束的都是整棵进程树。GeoEngine 自己崩溃时无法清扫,由仍在运行的主进程结束它留下的任务。整个应用被强制结束、崩溃或断电时,进程内无从清理,留下的任务会自己跑完,不做补救:它不损坏数据、也不会累积,而补救要在每个脚本或每次启动里长期维持正确。Windows 没有进程组,也没有可以先礼后兵的信号:任务在运行时,按进程树强制结束;任务退出之后,它留下的子进程不再结束,因为退出后的进程号可能已被别的进程复用,按进程号结束整棵树会误伤。内核执行命令时也是这样处理的。
- 输出按 UTF-8 读取。Windows 上的命令行程序默认用系统的本地代码页输出(如简体中文系统的 GBK、繁体中文系统的 Big5),能力模块启动外部程序时要让它以 UTF-8 输出,否则中文的报错与路径会变成乱码。
- 用户环境与内核相同。GeoEngine 拿到的环境是登录 shell 的变量按 `DESKTOP.md` 第 5 节清理之后的那一份,用户装在 conda 或系统里的 QGIS、GDAL、Python 能被找到。
- 文件只放在 GeoCode 自己的目录里(见 `PATHS.md`),新增的目录在实现时补进 `PATHS.md`。
- macOS 与 Windows 同等对待,两个平台的安装布局与路径规则都要覆盖。
- 对内核与壳的上游代码,只改接入所需的几处(见 `CONVENTIONS.md` 第 3 节)。

## 6. 验收

框架的验收如下,各能力域的验收做到时补充。

- 应用正常退出之后,没有残留的 GeoEngine 进程与任务子进程(Windows 上任务自己退出后留下的除外,见第 5 节);应用被强制结束之后,GeoEngine 随之结束。
- GeoEngine 崩溃或被结束时,界面与内核照常工作;它留下的任务子进程被结束,它被自动重新拉起,正在执行的任务以失败结束并说明原因;反复崩溃时到上限停止,不无限重启。
- 运行期间,GeoEngine 没有监听任何端口。
- 一个运行超过十分钟的任务能完整跑完,期间进度持续回报;中途中断时任务停止,它启动的外部程序随之结束。
- 写入检测干净,GeoEngine 产生的文件都落在 `PATHS.md` 列出的位置。

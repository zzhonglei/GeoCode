# 项目开发与代码规范

**这里大半的规矩只为一件事:我们要能长期、持续地合并上游的 OpenCode 与 OpenChamber。**

GeoCode 是两棵 vendored 上游树上的薄 fork。这个能力还在,升级内核就约等于换一个依赖版本;它一旦
丢了,产品就退化成「每次都把定制重新缝回新源码」——而**丢它的那一刻不会有任何报错**,只会一次比
一次贵。下面凡是看起来琐碎的讲究,代价基本都是这么来的。

据此分两类读:

- **保护合并能力的**:§1 的总纲、**§5 全节**、§7 的绊线判据与那两道门、§10 的不写行号;
- **产品自己的约定**,与上游无关:§2 代码风格、§3 依赖方向、§4 Git 流程、§6 工具设计、§8 平台边界、
  §9 安全红线。

## 1. 语言与总则

文档用中文;代码、注释、提交信息一律英文。TypeScript 全栈,包管理与测试用 bun,格式交给
prettier(无分号、宽行),不做人肉排版。

**写代码的总纲:读起来像仓库里已有的代码。** 风格一致性优先于个人偏好——这不是审美,是上面那条:
写得越像上游,补丁在合并时的冲突面越小。

**规范从简。** 规矩、检查、清单每多一条,就多一份要人记得、要随上游一起维护的负担。新增之前先问
现有规则能不能覆盖。代码的行为可以接受、只是文档说得比它多时,**改文档**,不为贴合文档去加代码。

## 2. 代码风格

**函数组织**:逻辑保持在一个函数里,除非确实可组合或可复用;不为单次使用预先抽助手函数。分支多的函数让主体读起来是「幸福路径」,支撑细节放到主函数下方的小助手里——只在助手能命名一个真实概念(如 `requireConfig`)时才抽。

**变量与控制流**:`const` 优先,用三元或早返回代替重赋值;避免 `else`,用早返回;只用一次的值就地内联,减少变量总数;避免 `try/catch` 与 `any`;优先函数式数组方法(map / filter / flatMap),filter 用类型守卫保住下游推断。

```ts
// Good
const journal = await Bun.file(path.join(dir, "journal.json")).json()
if (condition) return 1
return 2

// Bad
const journalPath = path.join(dir, "journal.json")
const journal = await Bun.file(journalPath).json()
if (condition) return 1
else return 2
```

**导入与访问**:不给导入起别名,不用星号导入;需要命名空间就导入模块自己导出的命名空间。避免无谓解构,用点号访问保留上下文(`obj.a` 而非 `const { a } = obj`)。启动敏感路径上的重模块用动态导入,且放在需要它的最窄分支里。

**注释**:只为不明显的约束和出人意料的行为写,不解释显而易见的赋值与控制流。why 是**一句从句,挂在
那行否则会被改错的代码上**,不是压在它头上的段落。密度与块长的基准取上游自己(2026-08-24 实测,方法:
对 `kernel-upstream` 的 `packages/{opencode,core}/src/**/*.ts` 统计):注释占源码 **2%**,**92%** 的块
≤5 行,`**加粗**` 6 处/10.8 万行,emoji **0 处**。

**写与删,逐句问:删掉它,读代码的人会做错什么?** 答得上来就留,写成一句从句;答不上来就删;答案是
「他不知道我们当初为什么这么决定」**也删**——那归 `docs/`。三条推论:**每条声明从代码推导,不从旧注释
改写**,验不了就别写——**一句短而假的注释比一句长而真的更糟**;**删事实前先查谁还持有**(测试、类型、
`docs/`);**注释描述代码,不描述项目状态**——「还没在 X 上测过」会随进度无声失效,那归
`.artifacts/OPEN.md`。

**测试文件多一条**:绊线注释只说出**它防的是哪种失败**,好让将来的人判断它还该不该在。怎么发现的、
测了什么数,都是审阅者材料;测试名已经说了的不要再写一遍。

## 3. 依赖方向

依赖只许单向流动,违反即架构腐蚀。当前生效的两条:

- **地理内核零依赖 Electron 与界面。** 它住在 `kernel/packages/opencode/src/geo/` 而不是独立包,边界因此靠依赖方向维持、不靠目录维持:它只经包的公开入口(`@opencode-ai/core/*`、`@opencode-ai/schema/*`)取用引擎能力,不触碰引擎内部模块。这是「地理内核可脱离桌面环境单独测试」的落地保障。
- **引擎对地理内核的引用只出现在注入点上**:服务图、路由挂载、数据面处理器、进程回收、工具注册。清单在 GEOKERNEL.md §10.1,每一处配一个绊线测试;不在清单上的引用即欠账。

界面与桌面壳的依赖方向:React UI 只依赖同源 SDK、RuntimeAPIs、
HTTP 与 preload 类型契约,绝不 import 内核或地理内核的任何模块;Shell Runtime 只经 HTTP
代理内核;桌面壳可依赖二者的构建产物,反向禁止。完整边界见 `DESKTOP.md` §3。

## 4. Git 与变更流程

分支名:三个词以内、连字符分隔、不带类型前缀(`kernel-thin`、`fix-raster-alpha`)。提交信息:conventional commit,`type(scope): summary`,类型取标准集 `feat` / `fix` / `docs` / `style` / `refactor` / `perf` / `test` / `chore` / `revert`,一到两句,不带任何 AI 署名。

**流程铁律**:

- **助手绝不擅自 commit。** push、建仓、发版同样由维护者亲自执行;
- **提交前完整 diff 审计并报告**——机械性批量修改恰恰最容易漏改;
- **每批改动以表格陈列**:位置、内容、用户可见效果、验证方法。维护者实机过目后才谈提交;
- **会随安装包分发的元信息**(author / copyright / publisher)**不得自动填真实姓名邮箱**,必须过问;
- **高风险改动配多路独立审查**;审查类子任务一律只读,任务书须写明不得修改工作树。

## 5. vendored 上游目录(kernel/ 与 desktop/)专用规范

两份上游以 vendor 方式住在本仓:`kernel/`(原味落盘在 `kernel-upstream` 分支)与 `desktop/`
(`chamber-upstream`),main 都经 subtree 合并持有,各自是独立的 bun 安装根。

**本节是这份规范的核心。** 上游每周都在动,而我们在它上面打补丁——这一节的每条规矩,都是在回答
同一个问题:**怎么让我们的改动在下一次合并中活下来,而且活得被人看得见。**

### 5.1 归属与阶梯

**定制阶梯(军规)**:配置 → 环境变量 → 外挂进程 → 界面 → 源码补丁。每处源码补丁必须书面说明为何
前四层做不到;补丁面只许收缩。

**上游的缺陷一律不修。** 判据不是「严不严重」也不是「好不好修」,是**归属**:对照原味分支确认
「上游本来就这样、我们没引入」的,等上游自己修,随下一次合并白捡。替它修等于在合并高频区堆自己的
补丁,每次都要重解冲突。⚠️ 用户看到的仍然是 GeoCode 出错,**别当成我们自己的回归去追**。
⚠️ **判完就到此为止,不要把它们编成目录**——记一堆复现路径,只会让下一个人当成待办。

三种情况不在此列,它们本来就是我们的活:我们自己引入的回归;按产品边界关入口的收口;上游按自己的
设计正常工作、而那个设计对地理用户不成立的地方。

### 5.2 补丁标记与形态

**补丁必须能被一条 grep 一网打尽。** 这是唯一的硬性要求:任何形态,只要定位命令找得到就合法,
找不到的一律不许用。

```bash
grep -rnE '// GeoCode:|--- GeoCode|"GeoCode: ' kernel/packages/ desktop/
```

- 小改动用行尾 `// GeoCode:`;
- 多行或含取舍判断的用块标记 `--- GeoCode: <why> ---`,**必写 why**——写「做了什么」不合格,要写
  「前四级阶梯为何不够」;
- 屏蔽上游代码时,**那些行必须逐字节不变**:整段包进 `/* */`,或在它前面加一句早退;
- `// --- /GeoCode ---` 标的是**上游代码从这里继续**,屏蔽块与改写块之后都用它;自有文件不必闭合;
- 引入自有模块的 `import` 行也带标记,否则解冲突的人不知道那行归谁;
- 上游测试文件里的自有用例用 `it("GeoCode: …")` 前缀,定位命令一并覆盖。

⚠️ **「留在区域内」不等于「逐字节不变」,而自动合并只归后者。** 给上游那些行加 `//` 或 ` * ` 前缀,
在 git 眼里是**改了每一行**,上游再动它照样冲突;原样留着是纯插入,上游的改动自动合入。
**逐行加 `//` 前缀是这条的陷阱**:看着也是「只加」,实则每行都被改过。

**能自动合并的前提,是段内还剩着上游这次没动的行。** 只屏蔽一行、而上游改的正是那行,包与不包一样
冲突;这时包裹换来的是**冲突可解**——删掉的那一侧在冲突里是一片空白,解的人看不出那是有意删的,
包着则理由就在眼前。块注释包不住含 `*/` 的区域,那种情形用早退。

### 5.3 绊线

**配给谁。** 不是每处改动都配。判据是**这处改动会不会被静默破坏**:git 能保护的不需要(同一文件、
改动会撞成冲突、冲突看得见),**git 结构上看不见的才需要**,典型是跨文件的拷贝——上游改它那份,
我们的副本原地不动,不冲突、不报错、全绿。其中也只给后果要紧的配:毁坏用户数据、写进别的产品的
目录、越过安全红线;其余交给合并时的逐项审阅。

**断言后果,不断言措辞**,否则下一次改写会顺手把它放宽。「文件里不许出现某个上游字面量」也是断言
措辞,而且它会逼着我们去删改上游的行,与 §5.2 的「逐字节不变」直接冲突。

⚠️ **手写清单是最常见的漏法,判据是它能不能看见一个没人列过的文件。** 改法是把默认值翻过来:
**扫全树,每一处命中都必须被显式豁免**,豁免带理由。

⚠️ **豁免本身要能被反查。** 每条记下「哪个文件的哪一行让它够不着」,那一行没了就红。反例是只断言
「这个键还在字典里」——那对任何情况都成立,等于没断言。

⚠️ **判「够不着」要一路追到最后一个过滤器。** 中途任何一层都可能已经关掉它,也可能没有。

### 5.4 载不动标记的文件

有几类文件没有注释语法(`.txt` 提示词、JSON、图像资产、翻译字典),合并时只能手工过。
**完整清单不在本文维护**——它就是门里那份白名单(`patch-surface.sh --check`),清单写两份必漂。
这道检查**在门里自动跑**,不靠人记得:「改过但定位命令找不到」的文件只放行白名单里的那几类,其余
即红;白名单按后缀逐个列举而不是「凡二进制皆放行」,这样新冒出来的一种格式会先红一次,由人决定它
能不能带标记。
⚠️ **`.svg` 不在其内**:XML 载得动注释,改过的 SVG 必须带标记。

**翻译字典还多一条**:上游合并会**静默改写**它。所以改过的键由绊线按**后果**绑定,不断言措辞——
比如「描述已改行为的字符串不得再描述上游行为」。

**不为补丁另建索引。** 索引会漂,而它要回答的每个问题都已有更权威的来源:动了哪些地方由
`patch-surface.sh <root>` 打印,为什么前四级不够由补丁旁的 why 回答,运行时保障由同名的测试回答。
**解冲突的人需要的是「这一处为什么这样改」,那句话就在冲突的正中间,比任何索引都近。**

### 5.5 闭包:原味分支与圈选清单

**原味分支是一串孤儿快照,不是上游的历史。** 根提交没有父,分支上只有我们自己造的快照;升级是用脚本
把上游的新版本重新圈选一次,**不走 `git merge` 上游**——排除项在这条分支上从不存在,merge 会把它们
读成「上游修改了我们删掉的文件」并带回来。⚠️ 直接 `git fetch` 上游来建这条分支行得通,而且一切看
起来都正常,直到某次改用 merge 升级、或有人对着几千个上游提交找 merge-base。

⚠️ **原味分支必须推到远端。** merge-base 就在那条分支上,它只存在于本机时,任何新 clone(包括换机器
后的自己)都做不了三方合并,而**失去这个能力不会有任何报错**,只会安静地退化成人肉 diff。

**清单即闭包。** 改它一行就是改「下次合并把什么读成上游的增删」:少一行读作「上游删了这些文件」并把
它们从 main 上移除,多一行读作「上游加了」。**两个方向都不产生冲突,都是静默的。** 所以**收窄闭包是
这套机制唯一没有自动防护的操作**——默认全取,只排除验证过的项;而**排除项的理由写进清单本身,不写
进文档**,清单是可执行的,文档会漂。圈选错了的修正渠道是**再 merge 一次原味分支,绝不在 main 上手
改**:手改会让两侧文件集永久错位,对账从此每次都报差。

**首次导入与后续升级不是同一条命令。** 孤儿分支与 main 没有共同祖先,`-X subtree=<目录>` 的路径偏移
是**猜**出来的;猜不出时它不报错,只是把整棵上游树铺到仓库根,而冲突只有 `.gitignore`、`LICENSE`、
`.gitattributes` 三处 add/add。**手一快把那三处解掉再提交,得到的是一棵内容全错、外表正常的树。**
所以首次走两步:

```bash
git merge -s ours --no-commit --allow-unrelated-histories <原味分支>   # 只记父子关系,不动树
git read-tree --prefix=<目录>/ -u <原味分支>                           # 内容读进子目录
git commit
```

此后目录映射已经建立,升级就是下面那条普通的 subtree 合并。两次的验收一样:
`git diff <原味分支> main:<目录>` 必须为空。

### 5.6 合并一次上游:按这个顺序走

低频,但一次做错代价极大,所以当清单用,别跳步。**一次只升级一个上游**——同时移动两端会让 API 变化、
上游回归与我们的补丁失效混在一起,无法归因;单侧恢复基线之后才处理另一侧。

**第 0 步:决定升不升。** 先做一次不落地的试合并,产出是冲突文件数与冲突块数——那个数字应当是
**决定的依据**,不是升完才发现的代价。

```bash
git merge --no-commit --no-ff -X subtree=<目录> <原味分支>
git diff --name-only --diff-filter=U                       # 冲突落在哪些文件
git merge --abort                                          # 不满意:工作树原样退回
```

更便宜的一种连工作树都不碰,把三方合并整个算在对象库里,退出码 0 即无冲突:

```bash
git merge-tree --write-tree -X subtree=<目录> main <原味分支>
```

**第 1 步:在原味分支上圈选新版本落盘。** 脚本按清单从上游取文件、整棵替换,最后做文件集对账。
两个坑都出过事:

- ⚠️ **`git add --force` 不是保险而是必需。** 上游各级 gitignore 会静默吞掉它自己强制跟踪的文件,
  少一个文件落盘,下次合并就读作「上游删了它」。
- ⚠️ **文件集对账的两侧排序与比较都要在 `LC_ALL=C` 下做。** 只给 `sort` 设而漏掉 `comm`,`comm` 会用
  调用者的 locale 判断输入是否有序(`zh_TW.UTF-8` 下实测即失准),把两侧都存在的路径**同时报成两侧
  独有**——照那份报告去改清单,会真的删掉一个从未缺失的文件。**两个 vendor 脚本都犯过这个错。**

**第 2 步:合并进 main。** `git merge -X subtree=<目录> <原味分支>`,**解冲突逐处手解,绝不整文件取
某一方**——`--theirs` 会静默丢掉散落在同一文件里的其它补丁。

**第 3 步:处理锁文件。** 两棵树的闭包策略不同,做法跟着它走:

| | 闭包 | `bun.lock` 与上游 | 冲突时 |
|---|---|---|---|
| `kernel/` | 圈最小子集 | 差着一半(上游 872 KB,我们 384 KB)——上游那份覆盖着我们根本没有的包 | 删掉重新生成 |
| `desktop/` | 包层面全取 | 几乎一致(相差 206 字节) | **先取上游那一侧,再让 `bun install` 调和** |

```sh
git show chamber-upstream:bun.lock > desktop/bun.lock
bun install
```

desktop 那条不能反过来做:删掉重生成会让 `bun install` 做一次全新解析,把一大批传递依赖解到范围内的
最新版,而那与这次合并无关。v1.23.1 → v1.23.2 实测两种做法——重生成离上游 **1677** 行,先取上游再
调和离上游 **9** 行(5 行是我们钉的 SDK,4 行是 `bun install` 纠正上游自己发歪的锁文件)。

**第 4 步:重装依赖,不要增量。** ⚠️ `bun install` 会按新锁文件补齐缺的包,却**不清掉不再被引用的旧
版本**——同一个包的两个版本从此并存,而 TypeScript 把它们当成两个不同的类型。症状是几十条 `TS2322` /
`TS2345`,报的是 `.bun/<包>@<旧版>` 与 `@<新版>` 之间不兼容。⚠️ **它读起来像是某处补丁被上游重构架
空了**——而那正是下一步该抓的东西,极易误判成真问题。v1.18.4 → v1.21.0 实测过:增量安装后
`@codemirror/language` 留下两份,`bun run build` 退出码 2;清掉重装全绿。

**第 5 步:对两次账。** 文件集对账由脚本做,补丁面对账要人看:

```bash
git diff --name-status <原味分支> main:<目录>                              # 补丁面全集,不依赖标记
grep -rlE '// GeoCode:|--- GeoCode|"GeoCode: ' <目录>/ | wc -l
```

前者是唯一看得见载不动标记那几类补丁的手段;后者数的是可审计的那一部分。**任一数字变小就有补丁不见
了,而它未必伴随任何冲突**——上游删掉或改名一个我们打过补丁的文件时,git 不报冲突,只是让那处补丁
随文件一起消失。

**第 6 步:跑绊线套件。** 它回答的是另一个问题——**补丁还在,但还起作用吗**。上游重构会让补丁语法
完好而语义被架空,只有运行时测试看得见。

**第 7 步:把这个目录上的全部改动逐项审阅一遍。** 清单用第 5 步那条 `git diff --name-status` 取,
它不依赖标记,一处都漏不掉。

## 6. 工具设计

- **返回原子事实,不预分类、不预建议**——给 agent `coverage: 0.42`,而不是 `quality: "low"`;阈值判断是 agent 的工作;
- **描述简短**,只写最关键的事实,边界情况靠运行时错误信息暴露;
- **描述里的限制数字故意比代码常量更严**,给 agent 留余量。这种「不一致」是设计不是缺陷;
- **错误处理按场景分三种模式,不追求统一**:用户必须知情的抛出;检索类失败写入输出让 agent 自行处理;执行类失败返回诊断旗标供 agent 决策;
- **执行失败时已写盘的部分输出保留**,用户有权检查半成品;
- **提示词模板整句一行,不软换行。**

## 7. 测试

### 7.1 测试纪律

⚠️ **一条只会说 clean 的检查等于没有检查。** 加进门的每一条都要先做反证:把它防的那个改动撤回、
重跑,确认它真的变红。没做过这一步的检查,绿灯什么也不证明。

尽量不用 mock,测试真实实现,不把业务逻辑复制进测试里。测试从各包目录运行,不从仓库根跑。地理内核的业务逻辑(探测状态机、预览管线、技能商店)必须可脱离 Electron 单测;界面单测需预载 DOM 环境。绊线测试是运行时验证,编译通过不算数——历史上最痛的事故全是「typecheck 与测试全绿、运行时静默失效」;凡「写下配置期望被某服务读到」的改动,必须追到读取方并用运行时测试锁定。发版前两平台实机、双档案(全新 + 存量)各过一轮。

### 7.2 门与参考是两件事

`scripts/test-gate.sh` 是**门**:我们自己的代码加上绊线,必须全绿,约两分钟。提交前跑它。

它按包分节,每节**点名我们自己的文件**而不是跑那个包的整套——上游的套件是参考不是门,里面有先于我们就红的用例。⚠️ 代价是**一个包整个不在门里,从门内部看不出来**:渲染进程自己拼的存储路径没有任何绊线,壳的数据根搬走时它们照样留在别人的目录上,不会有东西响。**往一个新包里打补丁时,同时给门加一节。**

### 7.3 门已知的四种静默

这四种的共同形状是**输出看起来和通过一模一样**。

⚠️ **按名字过滤的那一步会空跑。** 门里有一步是 `bun test -t "GeoCode:" test/skill/skill.test.ts`——只跑上游文件里我们加的用例。
实测 `-t` 匹配不到任何东西时只打一句「matched 0 tests」,**退出码仍是 0**;也就是说一次合并把那几条抹回上游,这一步会
零断言地变绿,而 `patch-surface.sh --check` **看不见一个被抹回上游的补丁**。所以这一步数跑过的用例数,
为 0 就拒绝。⚠️ **下界取 1,而不是「今天有几条」**:从同一份文件里数出来的期望值会跟着用例一起归零,那种断言对任何
情况都成立(`.artifacts/LESSONS.md` §5 那条的又一次)。

⚠️ **门里的 `skipIf` 同样会静默。** `kernel-packaging.test.mjs` 在内核没有暂存时整段 `describe.skipIf` 跳过,
输出里既没有失败也没有覆盖,读起来和通过一模一样。所以门在跑 electron 那一节之前先查前置条件在不在,
不在就拒绝并给出那一条命令;文件名取自壳自己用的 `kernel-paths.mjs`,改名会一起动。

⚠️ **测试里起的服务器,绑的地址族和拨的必须一致。** supertest 默认 `listen(0)` 绑 `::`(IPv6)
却明确去连 `127.0.0.1`(IPv4),两个族的端口分开分配,所以请求可能落到别人的服务器上——门因此
偶发变红过,三种面孔出现在三个文件里,单独跑必过。修法是让它连服务器**真正绑的**那个地址
(`server/geocode/loopback-listen.js`,经 vitest `setupFiles` 装上),绊线故意制造一次撞号。
⟹ **一次「随机」的失败,状态码往往不是随机的,它是另一台服务器的回答**(诊断经过在
`.artifacts/LESSONS.md` §八)。

⚠️ **桩里的缺陷可能是生产缺陷的镜像。** 桩照着生产写,所以在桩里修掉一个形状之后,拿同一个形状
去生产代码里找一遍;同一个桩有两份拷贝时,两份一起修,否则抖动只是换个文件继续出现
(`.artifacts/LESSONS.md` §五)。

### 7.4 设置往返:壳写到这里、内核读那里

门的最后一节按每个面向内核的设置页写一条:走路由真正调用的那些服务端函数写进去,再用**内核自己的
loader、常量与 schema** 读回来。两个包各是一个 bun 安装根,所以这件事哪一边的套件都答不了——而
「壳写到这里、内核读那里」正是反复咬人的形状。它跑两遍,因为壳选哪个配置文件取决于**哪个已经
存在**,两种起始状态都要绿。

它**不覆盖**「按钮有没有调那条路由」——那是渲染进程接线,要么读代码要么实机。

⚠️ **写完之后数一遍断言,别数需求。** 这一节翻过两次车:一条断言号称比「两半的根一致」,实际只比了
内核的根和临时目录;文档写着覆盖七类,断言表里只有六条。两次都是变异测试当场暴露的。

### 7.5 第二道门:断言磁盘,不断言源码

`scripts/foreign-writes.sh` **断言的是磁盘而不是源码**:`before` 记快照、跑要验的东西、`after` 报
差异,盯着 GeoCode 绝不该碰的那几个位置,**任何变化即失败**。

为什么要第二道门:源码层的断言看不见这几类——**补丁写对了但是死代码**(上游一个默认值让回退分支
永不执行)、**路径编译进了 vendor 产物**(源码里 grep 不到)、**开发脚本的分叉**(那条路上的壳没有
内核注入)、**共享的进程注册表**(孤儿回收在任何分支判断之前无条件运行)。

**门自己也被它围着**,并把 GeoCode 自己的四个根一并纳入监视:**门不该碰用户数据**,别家的不该碰,
我们自己的也不该碰——一旦碰了,下游没有任何东西能把那次写入和应用自己的写入分开。收尾放在 `EXIT`
陷阱里而不是脚本末尾:某一节红了就退出,而**会写盘的用例恰恰也是容易红的那一类**。

⚠️ **这道门只看写,不看读。** 它比对 mtime 与大小,而读取不留痕——「GeoCode 读了别人的凭据」这一类
它一个也抓不到,那要靠代码审查。

⚠️ **凡是要被别的脚本调用的脚本,退出码就是接口的一部分。** 这条是被 `before` 咬出来的:它曾以
`[ -s … ] && echo …` 结尾,在没跑过 OpenChamber 的机器上返回 1,门在 `set -e` 下当场死掉且零输出。

### 7.6 真实会话:套件照不到的

**套在测试套件上还不够,要套一次真实应用会话。** 前端自己拼的存储路径没有任何测试会走到:

```sh
./scripts/foreign-writes.sh before
(cd desktop && bun run electron:dev:bundled)   # 起来后点几下,至少建一个 chat
./scripts/foreign-writes.sh after
```

⚠️ 用 `electron:dev:bundled` 而**不是** `electron:dev`——后者的壳是 dev 脚本单独起的进程,主进程探到
它就不再注入内核,那个壳会去磁盘上拉起用户自装的 OpenCode。⚠️ 退出码 **3 是「要人确认」而不是
「干净」**:用户自己的 OpenChamber 若在这段时间里跑过,它的写入会被单独报出来,要一个干净结论就
关掉它重跑。

**读侧也要一次**(`ENVIRONMENT.md` §7):从一个下了毒的终端起同一个命令,旁边 `nc -l` 接 OTLP 端口。
应用要正常起来、有内核、`nc` 收不到任何连接、设置页仍落在 GeoCode 的根下。内核那一半有自动形式,
`scripts/kernel-env-probe.sh`,不开窗口。

### 7.7 参考,不是门

**上游的测试不归我们维护**,两个上游都一样。我们有意改掉的东西——磁盘身份、只留 GeoAgent 一个主
agent、关掉的那些入口——正是其中一批用例断言的内容,所以它们**按设计就会红**。⚠️ **不为让它们变绿
去改写上游用例**:那些改写不在门里、不提供任何保护,每一行却都是合并时的冲突面。

`scripts/dead-code.mjs` 抓的是**这次编辑的残渣**——最后一处用法被替换掉的导入、唯一调用方搬进屏蔽
块的助手。改完对动过的文件跑一遍。它永远会报出一些东西(上游自带死代码),所以是参考不是门。

`scripts/test-upstream.sh` 按成因分堆后**报告而不拦截**,不在任何流程里。要看就只看一件事:
**unexplained 那一堆有没有变大**。基线与读法在 `.artifacts/METHOD.md`。

## 8. 平台边界

只支持 macOS arm64 与 Windows x64。QGIS 的安装与重装永远由用户在官网完成,应用只探测与引导。macOS 上 QGIS 子进程引起的 Dock 图标闪烁是已知现象,接受不修。

Windows 上的 shell 应当只允许 cmd / powershell / pwsh:GIS 工具链装在 Windows 原生路径,混入 WSL 或
Git Bash 的路径风格会让 agent 处理路径出错。⚠️ **这条是目标,不是现状**——上游的选择顺序把 Git Bash
排在前面,而这件事改得了、在没有 Windows 实机之前验不了。

## 9. 安全红线

- **本地服务只听 127.0.0.1**,每次启动换随机口令;
- **渲染进程零特权**,凭据经 preload 下发;
- **权限在内核层强制**,界面过滤只是体验;
- **应用退出必须回收全部子进程**;崩溃与强制结束留下的地理子进程不补救,理由见 `GEOKERNEL.md` §12;
- **冻结区永久逐字保留**:内核的 provider / auth / account 区里模型厂商及其 OAuth 通道收得到的一切(请求头、User-Agent、Referer、授权地址参数、客户端身份)与认证逻辑本身,以及 wire 指纹(`@opencode-ai/*` 包名、`OPENCODE_*` 环境变量)。用户与上游生态共用同一套 OAuth 通道,这些是通道的身份凭据。区内**只给用户看的文字**(授权完成页、授权说明、报错提示)可以换商标,逐处加标记并配绊线(2026-09-17 用户定)。

## 10. 文档

三条,都是这个项目独有的。

**分层:`docs/` 写给要做判断的人,`.artifacts/` 写给要动代码的人。** 每一段过一次:一个刚接手的人
读它,是为了**做判断**,还是为了知道**我们做过**?后者搬去 `.artifacts/` 或者删。

**不写行号,指符号名。** 我们有两棵 vendored 上游树,行号随每次合并漂,而**漂了什么都不会发生**
——它只是安静地指向另一句代码。符号名才是代码的身份:改名会有编译错误、会有测试红。要计数就给
一条命令让人现数。

**现状归一处,正本是 `OVERVIEW.md` §7。** 设计文档写「应当是什么样、为什么」,规范文档写「该怎么
做」,**都不在论证里夹进度句**。两种例外位置固定、可一眼对账:文档顶部的范围声明,以及迁移账本里
独立的状态列。

# 项目开发与代码规范

这些规范不是仪式,每条背后都有真实事故或明确的产品判断。

## 1. 语言与代码风格

文档用中文;代码、注释、提交信息一律英文。TypeScript 全栈,包管理与测试用 bun。风格跟随仓库现有代码:优先 `const`、少 `else`、不滥用解构与 try-catch、类型能推断就不标注;格式交给 prettier(无分号、宽行),不做人肉排版。新功能优先独立文件、清晰模块边界,避免巨型文件。

## 2. Git 与变更流程

提交由维护者掌控:助手绝不擅自 commit,提交前必须完整 diff 审计并报告——机械性的批量修改恰恰最容易漏改。提交信息用简洁的 conventional commit(一到两句),不带任何 AI 署名。push、建仓、发版由维护者亲自执行。会随安装包分发的元信息(author、copyright、publisher)不得自动填入真实姓名或邮箱,这是隐私决策,必须过问。

每一批改动以表格陈列(位置、内容、用户可见效果、验证方法),经维护者实机过目后才谈提交。高风险改动配多路独立审查;审查类子任务一律只读,任务书须写明不得修改工作树。

## 3. 定制阶梯(军规)

对 Agent 内核的一切定制,严格按"配置 → 环境变量 → 外挂进程 → 界面 → 源码补丁"的优先级实现(KERNEL.md)。每一处源码补丁必须书面说明为何前四层做不到,并配一个运行时绊线测试。补丁面只许收缩,不许膨胀。

## 4. 工具设计

工具返回原子事实,不预分类、不预建议——给 agent `coverage: 0.42`,而不是 `quality: "low"`;阈值判断是 agent 的工作。工具描述简短,只写最关键的事实,边界情况靠运行时错误信息暴露;描述中的限制数字故意比代码常量更严,给 agent 留余量,这种"不一致"是设计不是缺陷。错误处理按场景分三种模式,不追求统一:用户必须知情的抛出;检索类失败写入输出让 agent 自行处理;执行类失败返回诊断旗标供 agent 决策。执行失败时已写盘的部分输出保留,用户有权检查半成品。提示词模板整句一行,不软换行。

## 5. 测试

地理内核的业务逻辑(探测状态机、预览管线、技能商店)保持可单测,不依赖 Electron 环境。每处内核源码补丁配一个运行时绊线测试(编译通过不算数——历史上最痛的事故全是"typecheck 与测试全绿、运行时静默失效")。界面单测需 DOM 环境预载。发版前必须两平台实机、双档案(全新 + 存量)各过一轮。

## 6. 平台边界

只支持 macOS arm64 与 Windows x64。Windows 上只允许 cmd / powershell / pwsh——GIS 工具链装在 Windows 原生路径,混入 WSL 或 Git Bash 的路径风格会让 agent 处理路径出错。QGIS 的安装与重装永远由用户在官网完成,应用只探测与引导。macOS 上 QGIS 子进程引起的 Dock 图标闪烁是已知现象,接受不修。

## 7. 安全红线

本地服务只听 127.0.0.1,每次启动换随机口令;渲染进程零特权;权限在内核层强制。内核的 provider / auth / account 区与 wire 指纹(`@opencode-ai/*` 包名、`OPENCODE_*` 环境变量、User-Agent、Referer)永久冻结、逐字保留——用户与上游生态共用同一套 OAuth 通道,这些是通道的身份凭据(KERNEL.md)。

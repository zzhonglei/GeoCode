# 项目开发与代码规范

这些规范不是仪式:代码风格来自我们代码库的血统(与内核同源),流程规则背后都有真实事故。

## 1. 语言与总则

文档用中文;代码、注释、提交信息一律英文。TypeScript 全栈,包管理与测试用 bun,格式交给 prettier(无分号、宽行),不做人肉排版。写代码的总纲:**读起来像仓库里已有的代码**——风格一致性优先于个人偏好。

## 2. 代码风格

**函数组织**:逻辑保持在一个函数里,除非确实可组合或可复用;不为单次使用预先抽助手函数。分支多的函数让主体读起来是"幸福路径",支撑细节放到主函数下方的小助手里——只在助手能命名一个真实概念(如 `requireConfig`)时才抽。

**变量与控制流**:`const` 优先,用三元或早返回代替重赋值;避免 `else`,用早返回;只用一次的值就地内联,减少变量总数;避免 `try/catch` 与 `any`;优先函数式数组方法(map / filter / flatMap),filter 用类型守卫保住下游推断。

```ts
// Good
const journal = await Bun.file(path.join(dir, "journal.json")).json()
if (condition) return 1
return 2

// Bad
const journalPath = path.join(dir, "journal.json")
const journal = await Bun.file(journalPath).json()
if (condition) return 1
else return 2
```

**导入与访问**:不给导入起别名,不用星号导入;需要命名空间就导入模块自己导出的命名空间。避免无谓解构,用点号访问保留上下文(`obj.a` 而非 `const { a } = obj`)。启动敏感路径上的重模块用动态导入,且放在需要它的最窄分支里。

**注释**:只为不明显的约束和出人意料的行为写注释;不解释显而易见的赋值和控制流,不写"给审阅者看"的注释。

**注释的形态**:why 是**一句从句,挂在那行否则会被改错的代码上**,不是压在它头上的段落——`// Custom servers must declare extensions because the runtime cannot infer them.`。密度与块长的基准取上游自己(2026-08-24 实测,方法:对 `kernel-upstream` 的 `packages/{opencode,core}/src/**/*.ts` 统计):注释占源码 **2%**,**92%** 的注释块 ≤5 行,JSDoc 密度 **2.6/千行**,`**加粗**` 6 处/10.8 万行,emoji **0 处**。

**写与删的判据**,逐句问:*删掉它,读代码的人会做错什么?* 答得上来就留,写成一句从句;答不上来就删;答案是"他不知道我们当初为什么这么决定"**也删**——那归 `docs/`。据此四条:**先问这个块该不该存在,再问怎么写**(把段落压成短段落不算改好;同构的两处只有一处带注释,通常说明那处也不需要);**每条声明从代码推导,不从旧注释改写**(句中点到的字段、函数、类型要打开核对,涉及库或平台行为的要跑一遍,验不了就别写——**一句短而假的注释比一句长而真的更糟**);**删事实前先查谁还持有**(测试、类型、`docs/`),本文件是唯一持有者且丢了会诱发错误改动的,压成一句留下;**注释描述代码,不描述项目状态**("还没在 X 上测过""某消费方还没建"会随进度无声失效,归 `docs/` 与 `.artifacts/OPEN.md`;但解释**代码里某个值为什么是那样**的是代码事实,留)。

**测试文件多一条**:绊线注释只负责说出**它防的是哪种失败**,好让将来的人判断它还该不该在;怎么发现的、测了什么数、断言为何写成这样,都是审阅者材料。测试名已经说了的不要再写一遍。

**改注释的收口**:风险在手滑不在语义,所以要有一道能一票否决的检查——用 `Bun.Transpiler` 抹掉类型与注释后哈希,改前改后必须相同;`prettier --check` 用 `kernel/` 锁定的版本而非 `bunx` 默认;行宽按**字符**不按字节(中文 3 字节会误报);最后跑 `scripts/test-gate.sh`。⚠️ **字符串里的注释是数据**:嵌入脚本的 `#`、URL 里的 `//`、夹具 JSON,都不许当注释处理。

**运行时 API**:能用 Bun 原生就用(`Bun.file()` 等);类型能推断就不标注,显式类型留给导出边界。

## 3. 依赖方向

依赖只许单向流动,违反即架构腐蚀。当前生效的两条:

- **地理内核零依赖 Electron 与界面。** 它住在 `kernel/packages/opencode/src/geo/` 而不是独立包,边界因此靠依赖方向维持、不靠目录维持:它只经包的公开入口(`@opencode-ai/core/*`、`@opencode-ai/schema/*`)取用引擎能力,不触碰引擎内部模块。这是"地理内核可脱离桌面环境单独测试"的落地保障。
- **引擎对地理内核的引用只出现在注入点上**:服务图、路由挂载、数据面处理器、进程回收、工具注册。清单在 GEOKERNEL.md §10.1,每一处配一个绊线测试;不在清单上的引用即欠账。

界面与桌面壳的依赖方向:React UI 只依赖同源 SDK、RuntimeAPIs、
HTTP 与 preload 类型契约,绝不 import 内核或地理内核的任何模块;Shell Runtime 只经 HTTP
代理内核;桌面壳可依赖二者的构建产物,反向禁止。完整边界见 `DESKTOP.md` §3。

## 4. Git 与变更流程

分支名:三个词以内、连字符分隔、不带类型前缀(`kernel-thin`、`fix-raster-alpha`)。提交信息:conventional commit,`type(scope): summary`,类型取标准集 `feat` / `fix` / `docs` / `style` / `refactor` / `perf` / `test` / `chore` / `revert`,一到两句,不带任何 AI 署名。

**流程铁律**:

- **助手绝不擅自 commit。** push、建仓、发版同样由维护者亲自执行;
- **提交前完整 diff 审计并报告**——机械性批量修改恰恰最容易漏改;
- **每批改动以表格陈列**:位置、内容、用户可见效果、验证方法。维护者实机过目后才谈提交;
- **会随安装包分发的元信息**(author / copyright / publisher)**不得自动填真实姓名邮箱**,必须过问;
- **高风险改动配多路独立审查**;审查类子任务一律只读,任务书须写明不得修改工作树。

## 5. vendored 上游目录(kernel/ 与 desktop/)专用规范

两份上游以 vendor 方式住在本仓:`kernel/`(原味落盘在 `kernel-upstream` 分支)与 `desktop/`(`chamber-upstream`),main 都经 subtree 合并持有,各自是独立的 bun 安装根。对它们的规则:

**定制阶梯(军规)**:配置 → 环境变量 → 外挂进程 → 界面 → 源码补丁。每处源码补丁必须书面说明为何前四层做不到;补丁面只许收缩。

**上游的缺陷一律不修**(2026-09-09 用户定,产品级长期约束)。判据不是「严不严重」也不是「好不好修」,而是**归属**:凡对照 `kernel-upstream` / `chamber-upstream` 确认「上游本来就这样、我们没引入」的,一概等上游自己修好,随下一次合并白捡。理由是我们会长期持续合并上游更新,替它修等于在合并高频区堆自己的补丁,每一次都要重新解冲突,而收益上游迟早会免费给。已按此判决的:09-07 那五处会破坏用户数据的缺陷(技能重命名必崩、删技能与删命令跨作用域删光、Agent 权限存错项目、项目级 MCP 不可见),09-09 界面欠内核的四条(待办不初次拉取、SSE 无事件 id 因而重连补发拿不到、`@file` 缩略图发 `file://`、撤销依赖 `vcs === "git"`)。⚠️ 用户看到的仍然是 GeoCode 出错,复现路径记在 `.artifacts/AUDIT-0907.md`,**别当成我们自己的回归去追**。

这条规则**不覆盖**三种情况,它们本来就是我们的活:①我们自己引入的回归;②按 §7.3「关入口」做的收口——那不是修 bug,是产品边界;③上游按它自己的设计正常工作、但那个设计对地理用户不成立的地方——那是产品缺口,要单独判。

**绊线配给谁**:不是每处改动都配一条。判据是**这处改动会不会被静默破坏**——git 能保护的不需要(同一文件、改动会撞成冲突、冲突看得见),**git 结构上看不见的才需要**。典型是**跨文件的拷贝**:上游改它自己那份,我们的副本原地不动,不冲突、不报错、全绿,两边从此各说各话。绊线也不该断言措辞,只断言后果,否则下一次改写会顺手把它放宽。

**补丁标记**:留守的源码补丁必须可被一条 grep 一网打尽。这是唯一的硬性要求——**任何形态,只要定位命令找得到就合法;命令找不到的一律不许用**(中文冒号、缺冒号一类的笔误因此自动出局)。

三条:

- **小改动**用行尾 `// GeoCode:`;
- **多行或含取舍判断**用块标记 `--- GeoCode: <why> ---`,必写 why。定界符随所在位置的自然形态取:自有文件的头部说明用 `/* --- GeoCode: … --- */`,插在上游代码之间的用行注释;
- **屏蔽一段上游代码时,那些行必须逐字节不变**,再用 `// --- /GeoCode ---` 标出区域结束。两种手法:整段包进 `/* */`,或在它前面加一句早退。自有文件里没有上游原码可锚,不必闭合。

⚠️ **"留在区域内"不等于"逐字节不变",而自动合并只归后者。** 给上游那些行加 `//` 或 ` * ` 前缀,在 git 眼里是**修改了每一行**,上游再动它照样冲突;原样留着则是纯插入,上游的改动自动合入并留在原处可读。同一处上游改动实测过两次:删掉整段——冲突;只加两行包住——自动合并。

**能自动合并的前提,是段内还剩着上游这次没动的行。** 屏蔽整段时这样的行充足;只屏蔽一行、而上游改的正是那行,包与不包一样冲突(四组三方合并实测)。这时包裹换来的是**冲突可解**:删掉的那侧在冲突里是一片空白,解的人看不出那是有意删的;包着则理由就在眼前。

块注释包不住含 `*/` 的区域(嵌套不合法),那种情形用早退。**逐行加 `//` 前缀是这条的陷阱**:看着也是"只加",实则每行都被改过,收益全无还多一堆噪音。

**两类文件载不动标记**,合并时只能手工过。它们的**可审计性**由下面那条差集命令给出,不靠绊线;绊线在这里防的是另一件事——手工解冲突时选错边:

- 提示词与描述文件(kernel 的 `.txt`)——内容原样送进模型,注释会污染指令(KERNEL.md §5.3);
- `package.json` 一类的 **JSON**——没有注释语法。树上有三处:`kernel/package.json` 的闭包圈选、`opencode/package.json` 的构建脚本与新依赖、`desktop/packages/electron/package.json` 的打包脚本与 extraResources。

**这两类的完整清单不在本文维护**,因为手工维护的清单会漂(KERNEL.md §4.1 记过一次:一份点名清单曾把六处健康补丁判成欠账,其中一处根本不存在)。它由一条命令给出——`git diff --name-status kernel-upstream main:kernel`(desktop 换成 `chamber-upstream main:desktop`)与上面那条 grep 的**差集**,就是"改过但查不到"的全部(KERNEL.md §4.4 第 3 步)。命令是代码,不会漂。

kernel 的 `bun.lock` 与上游差着数千行,但它**不是补丁**,是闭包圈选后 `bun install` 的产物。它不需要审计,也不该手工解冲突——重新生成即可(KERNEL.md §4.4)。

上游测试文件里的自有用例改用名字前缀 `it("GeoCode: …")`,定位命令一并覆盖。

引入自有模块的 `import` 行同样带标记(行尾 `// GeoCode: own module`,连续多行用块),否则解冲突的人在导入区
看到一行陌生的 import 时,要翻到几百行外才知道它归谁。

**翻译字典是第三类载不动标记的文件**,而且它与前两类不同:上游合并会静默改写它。所以改过的键由绊线按**后果**
绑定,不断言措辞:`ui/src/geocode/locale-paths.test.ts` 扫上游路径的拼写,`locale-behaviour.test.ts` 断言「描述已改
行为的字符串不得再描述上游行为」(例如应用配置的那组键不得出现「重启」)。

**差集检查在门里跑**,不靠人记得:`test-gate.sh` 调 `patch-surface.sh <root> --check`,「改过但定位命令找不到」的文件
只放行 JSON、lock、`.txt` 与翻译字典,其余即红。它量的是工作树,所以提交前就能看见。

定位命令:

```bash
grep -rnE '// GeoCode:|--- GeoCode|"GeoCode: ' kernel/packages/ desktop/
```

**合并纪律**:解冲突逐处手解,绝不整文件取某一方(`--theirs` 会静默丢掉散落同文件的补丁);合并后跑绊线套件,红了就是有补丁被上游重构架空。

## 6. 工具设计

- **返回原子事实,不预分类、不预建议**——给 agent `coverage: 0.42`,而不是 `quality: "low"`;阈值判断是 agent 的工作;
- **描述简短**,只写最关键的事实,边界情况靠运行时错误信息暴露;
- **描述里的限制数字故意比代码常量更严**,给 agent 留余量。这种"不一致"是设计不是缺陷;
- **错误处理按场景分三种模式,不追求统一**:用户必须知情的抛出;检索类失败写入输出让 agent 自行处理;执行类失败返回诊断旗标供 agent 决策;
- **执行失败时已写盘的部分输出保留**,用户有权检查半成品;
- **提示词模板整句一行,不软换行。**

## 7. 测试

尽量不用 mock,测试真实实现,不把业务逻辑复制进测试里。测试从各包目录运行,不从仓库根跑。地理内核的业务逻辑(探测状态机、预览管线、技能商店)必须可脱离 Electron 单测;界面单测需预载 DOM 环境。绊线测试是运行时验证,编译通过不算数——历史上最痛的事故全是"typecheck 与测试全绿、运行时静默失效";凡"写下配置期望被某服务读到"的改动,必须追到读取方并用运行时测试锁定。发版前两平台实机、双档案(全新 + 存量)各过一轮。

**门与参考是两件事,不要混用。**

`scripts/test-gate.sh` 是**门**:我们自己的代码加上绊线,必须全绿,约两分钟。提交前跑它。

它按包分节,每节**点名我们自己的文件**而不是跑那个包的整套——上游的套件是参考不是门。`packages/ui` 到 2026-08-30 为止**整个不在门里**,而这个缺口从门内部看不见:渲染进程自己拼两条存储路径,壳的数据根搬走时它们还留在 OpenChamber 的目录上,没有任何东西会响。它自己的套件里另有两个先于我们就红的用例(`SessionAuthGate`、`shortcuts`),这也是不整套拉进来的理由。

内核那条抖动已定位并修掉:代理桩用 `socket.once("data")` 读 CONNECT,而 `once` 不会让流停下——回调返回后 socket 仍在 flowing,`pipe` 挂上之前到达的字节被发给「没有人」并丢弃。客户端一看到 200 就发 ClientHello,负载高时它比上游连接更快到,握手于是等满探测超时。**这个桩有两份拷贝,两份都带同一个缺陷**,只修一份的结果是抖动换个文件继续出现;现在合并成 `test/geo/fake-proxy.ts` 一份。**同一类问题在生产的 `tunnel.ts` 里也有**(读到 `\r\n\r\n` 之后 socket 照样 flowing,且同一 chunk 里终止符之后的字节被丢),已一并修好并配绊线。

web 包还剩一条**未定位**的:`project-context/routes.http.test.js` 的「accepts a plan pin patch」偶尔收到 **401**。能确证的是它**不来自被测 app**——那是个裸 express 加桩 runtime,依赖图里没有任何鉴权代码,所以请求到了别人的服务器上,是端口串号而不是逻辑错。macOS 上 ControlCenter 与若干后台进程正好占着临时端口段并对未鉴权请求回 401。**机制尚未复现,不要据此改代码;记在这里是为了下次见到时知道它不是新问题,也不是为了当作可以忽略。** 观察到的频率约六轮一次。

门的最后一节是**设置往返**(`scripts/settings-roundtrip.sh`):它按每个面向内核的设置页写一条,走的是路由真正调用的那些服务端函数,再用**内核自己的 loader、常量与 schema** 读回来。两个包各是一个 bun 安装根,所以这件事哪一边的套件都答不了——而「壳写到这里、内核读那里」正是本阶段反复咬人的形状。

它跑两遍,因为壳选哪个全局配置文件取决于**哪个已经存在**:真机上内核在用户保存任何设置之前就已经播下了一个。两种起始状态都要绿。

⚠️ **写完之后要数一遍断言,别数需求。** 这一节两处都是这么翻的车:「两半的根一致」那条实际只比了内核的根和临时目录,壳跑偏了它照样绿;文档写着覆盖七类,而断言表里只有六条——plugins 一条都没有,页数是变异输出里数出来的,不是读需求读出来的。两处都是变异测试当场暴露的。

**证明过会红**(2026-08-31 实测):把壳的配置根改回 `opencode`,七类连同根比对一起转红;只把技能目录名改成内核不扫的写法,**只有 skills 一行红**;只把插件目录名改掉,**只有 plugins 一行红**。逐页粒度成立。

它**不覆盖**「按钮有没有调那条路由」——那是渲染进程接线,要么读代码要么实机。路由挂到哪个函数上是查过的,链条从路由往下全在门里。

`scripts/foreign-writes.sh` 是**第二道门,断言的是磁盘而不是源码**。用法是 `before` 记快照、跑一遍要验的东西、`after` 报差异;它盯八个 GeoCode 绝不该碰的位置(OpenCode 的四根、`~/.opencode`、`~/.config/openchamber`、`~/.agents`、`~/.claude` 里我们够得到的几处、`$TMPDIR/opencode`),**任何变化即失败**。

**门自己也被它围着**(2026-09-09 起)。`test-gate.sh` 开头 `before`、经 `EXIT` 陷阱收尾 `after`,并用 `FOREIGN_WRITES_EXTRA_ROOTS` 把 GeoCode 自己的四个根(config / data / cache / state)一并纳入监视:**门不该碰用户数据**,别家的不该碰,我们自己的也不该碰,而一旦碰了,下游没有任何东西能把那次写入和应用自己的写入分开。09-05 抓到过 `managed-kernel.test.js` 的对照组把假进程记录写进真实的 `managed-opencode/`(壳启动时会按这个目录杀 pid),当时没有任何东西看着。收尾放在陷阱里而不是脚本末尾,是因为某一节红了就退出,而**会写盘的用例恰恰也是容易红的那一类**;放末尾等于在最需要答案的时候把答案丢掉。

⚠️ 接上这一步时顺带修掉一个潜伏的坑:`before` 分支原本以 `[ -s ... ] && echo ...` 结尾,于是**在没跑 OpenChamber 的机器上返回 1**。以前没人看它的退出码,所以一直无害;门在 `set -e` 下调用它的那一刻,门当场死掉且零输出。凡是要被别的脚本调用的脚本,退出码就是接口的一部分。

为什么需要第二道门:2026-08-30 的全面审计查出四类问题,**没有一类是源码层断言能发现的**——

- **补丁写对了但是死代码**:`mdns.ts` 的 `?? Brand.mdnsHost` 是对的、绊线也钉住了它,而 `cli/network.ts` 的一个 yargs 默认值让它永远走不到,GeoCode 照旧广播 `opencode.local`;
- **路径编译进了 vendor 产物**:`gitlab-ai-provider` 的 bundle 里带着 `~/.cache/opencode` 的路径代码,源码里搜不到;
- **开发脚本的分叉**:`electron:dev` 由我们的 dev 脚本另起一个 web 服务器进程,主进程在 5 秒健康探测里探到它的 HMR 端口就不再走 `spawnLocalServer()`,于是那个壳没有内核注入,去磁盘上找到并拉起了用户自己安装的 OpenCode。产品路径上这条路现已封死(`ENVIRONMENT.md` §5.6:Electron 里的壳一律拒绝托管启动),但那个单独的 dev 服务器进程不在 Electron 里,分叉本身还在;
- **共享的进程注册表**:孤儿回收在任何分支判断之前无条件运行,读的是与用户 OpenChamber 共用的目录。

`~/.claude` 只盯 GeoCode 真能够到的几个子路径。盯整个目录没有用——Claude Code 自己在持续写会话记录,那些噪音会把真命中埋掉。

⚠️ **一条只会说 clean 的门等于没有门。** 加进门的每一条都要做反证:把改动撤回、重跑,看它是否变红。本文记的这条实测过:撤回十二处 fallback 后跑 web 包测试,门立刻报出对 `~/.config/openchamber/managed-opencode` 的写入。

**套在测试套件上还不够,要套一次真实应用会话。** 前端自己拼的存储路径没有任何测试会走到,套件跑一万遍也照不到:

```sh
./scripts/foreign-writes.sh before
(cd desktop && bun run electron:dev:bundled)   # 起来后点几下,至少建一个 chat
# 关掉应用
./scripts/foreign-writes.sh after
```

用 `electron:dev:bundled` 而不是 `electron:dev`——后者的壳是 dev 脚本单独起的进程,主进程探到它就不再注入内核,那个壳会去磁盘上找并拉起用户自装的 OpenCode(阶段 3)。用户自己的 OpenChamber 若在这段时间里跑过,**包括窗口中间开、跑完前关**,它与它自带的 OpenCode 的写入会被单独报成退出码 3 并附归因线索,不混进红报;退出码 3 是「要人确认」而不是「干净」,要一个干净结论就关掉它重跑。

**读侧也要一次真实会话**(`ENVIRONMENT.md` §7)。写入检测看不见读取,所以再从一个下了毒的终端起同一个命令:`export OPENCODE_CONFIG_DIR=/tmp/poison OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318 OPENCHAMBER_SKIP_LOCAL_SERVER=1`,旁边 `nc -l 4318`。应用要正常起来、有内核、`nc` 收不到任何连接、设置页仍落在 GeoCode 的根下。内核那一半有自动形式,`scripts/kernel-env-probe.sh`,不开窗口。

2026-08-30 实测过一对:修复前那次运行往 `~/.config/openchamber/projects/` 落了三个文件,修复后同样一次运行把同样形状的文件写进 `~/.config/GeoCode/desktop/projects/`,而 `~/.config/openchamber` 下快照之后**零新增**。

⚠️ **这道门只看写,不看读。** 它比对的是文件的 mtime 与大小,而读取不留痕——所以「GeoCode 读了别人的凭据」这一类它一个也抓不到。实例:打包进产品的内核里,`gitlab-ai-provider` 的 `loadApiKey()` 在没有显式 apiKey 时读 `~/.local/share/opencode/auth.json`;源码 grep 看不见(字符串在 vendor 产物里),这道门也看不见。**跨产品的读取要靠代码审查,不能指望这道门。**

`kernel/` 里那套 vendored 的上游测试**不是门**。我们有意改掉了两样东西——磁盘身份、以及只留 GeoAgent 一个主 agent——上游有一批测试断言的正是这两样,它们按设计就会红。**一个失败堆到看不清的套件给不出任何信号**:新增的回归混在里面看不见。

`scripts/dead-code.mjs` 是**参考,不是门**:抹掉块注释与行注释后,列出一个文件里定义了却没人调的函数(`function` 声明与函数值的 const 都算),以及没人用的默认导入。改完对动过的文件跑一遍。`grep` 在这里会骗人——被屏蔽的整块里每个模式它都照样匹配。

它永远会报出一些东西,所以不能当门:上游自己就带着死代码,而被我们屏蔽掉调用方的上游函数留着比删掉暴露面更小。它要抓的是**这次编辑的残渣**——最后一处用法被替换掉的导入、唯一调用方搬进屏蔽块的助手函数。这类残渣每一批都出现过。

⚠️ **它漏过一次自己声称要抓的那一类,还一直在误报。** 原本只认 `function` 声明,而箭头 const 写法的助手一个也看不见——2026-08-31 那批里「唯一调用方搬进屏蔽块」的助手正是这个形状,它报了 ok。补上 const 之后,同一批里冒出两个明显的假阳性,顺藤查出一个更早就在的缺陷:为了不让 `import os from 'os'` 把自己的模块说明符算成一次使用,它把**所有**引号串抹空,于是**正则字面量里的引号也被当成串**,`/NAME = "([^"]+)"/` 之后的代码整段被吃掉,后面的助手全报成死的——脚本自己就是受害者之一,基线版本对着自己就误报。现在只抹 import 行上的说明符,正则原样留着。

**加检查时要同时喂它五个夹具**:原来那条防的形状、新加的形状,以及三个必须**不**报的——模板串里的调用、正则字面量之后的定义、只被用了一次的导入(最后这个防的是「把整行 import 抹掉」这种过头的修法)。

上游套件用 `scripts/test-upstream.sh` 跑,它按成因分堆后**报告而不拦截**。**该关注的不是失败总数,而是"unexplained"那一堆有没有变大**——那一堆里才是真问题。每次上游合并后跑一次。

**当前基线**(2026-08-18 实测,内核 v1.18.18,方法即跑一次 `scripts/test-upstream.sh`):**88 个失败,unexplained 8 个**——opencode 包 85、core 包 3。按成因分堆:磁盘身份 36 · 堆栈帧存疑 38 · 已移除功能 4 · agent 阵容 1 · 地理交接 1 · unexplained 8。

⚠️ **`unexplained` 那一堆会在 7–9 之间浮动,浮动的是同一批时序敏感的用例**(并跑时的重试退避、进度计数、监听端口复用)。看到 9 不等于出事:先问**这次改动碰过那段代码吗**,再单跑那个文件——两条证据都指向别处,才是波动。其余各堆是稳定的,它们变了才值得停下来。

**这份画像跨过一次内核升级而一字未变**(v1.18.4 → v1.18.18,14 个版本、上游 319 个 commit,见 `KERNEL.md` §4.4)。同一组数字在两个上游版本上重合,是它作为基线可信的最好证据;也意味着下次它要是动了,动的多半是我们这边。

⚠️ 读 unexplained 那一堆时先扣掉一条:`osm download > progress counts every extent that settles…` 是**我们自己的测试**,它在门里(单独跑 `test/geo/`)是绿的,只在全量并跑的负载下超时——与 `METHOD.md §4` 记的那类并跑假红同源。

「堆栈帧存疑」那 38 个是一笔明账:它们只在堆栈帧里出现旧身份,分不清是真的改名漂移还是别的原因。分类尝试过,没有便宜的归法。它不阻塞任何事,但**「unexplained 有没有变大」这个问题的可信度,受限于这 38 个还没被看过**。

agent 那一支曾占约一百个,已在 `test/preload.ts` 一处解决——**恢复上游测试的价值要从接缝下手,不要逐条改断言**。`GeoCodeConfig.base()` 与 `Brand.*` 都在合并链最底层、配置可覆盖,所以一份全局配置就能让整批复活。同类问题再出现时先找那个接缝。

## 8. 平台边界

只支持 macOS arm64 与 Windows x64。QGIS 的安装与重装永远由用户在官网完成,应用只探测与引导。macOS 上 QGIS 子进程引起的 Dock 图标闪烁是已知现象,接受不修。

Windows 上的 shell 应当只允许 cmd / powershell / pwsh:GIS 工具链装在 Windows 原生路径,混入 WSL 或 Git Bash 的路径风格会让 agent 处理路径出错。**这条约束尚未落实**——`core/src/shell.ts` 与上游零差异,`gitbash` 仍排在 `cmd.exe` 之前。实施时机待定,不属当前阶段。

## 9. 安全红线

- **本地服务只听 127.0.0.1**,每次启动换随机口令;
- **渲染进程零特权**,凭据经 preload 下发;
- **权限在内核层强制**,界面过滤只是体验;
- **应用退出必须回收全部子进程**;崩溃与强制结束留下的地理子进程不补救,理由见 `GEOKERNEL.md` §12;
- **冻结区永久逐字保留**:内核的 provider / auth / account 区,以及 wire 指纹(`@opencode-ai/*` 包名、`OPENCODE_*` 环境变量、User-Agent、Referer)。用户与上游生态共用同一套 OAuth 通道,这些是通道的身份凭据。

## 10. 文档

四条,针对文档最常见的四种腐烂方式:

**同一个事实只留一份。** 需要在别处提到它,写指引而不是抄一份副本。三份互不指向的副本,读者无从判断哪份还算数——上游套件的失败基线一度同时活在三个文件里,三个数字互不相同。

**只有人兜底的数字,必须带量词、日期与取得它的方法。** 反例就在 §7:此前记的"约 30"取自一个匹配不到任何失败行的分类器,它对每次运行都报零失败,而句子里没有日期也没有方法,读到的人无从起疑(缘由记在 `scripts/classify-failures.mjs` 的头注释)。

**新知识先找主题文档,不轻易另起一篇。** 一件事的长期归宿多半已经有归处:壳与内核两套根属于 `PATHS.md` 的路径体系,注入时机属于它已有的"写入方与读取方必须成对"。判据是**去掉过渡文字后还剩多少**——桌面路径迁移一度写成 170 行的专文,并进 `PATHS.md` 与 `DESKTOP.md` 只剩 55 行,其余全是"目标状态见 PATHS.md""这里不重复它"这类交代。另起一篇的代价是每次重述背景、交叉引用容易悬空、而迁移类内容做完即失效。撑不进去再另起,并在主题文档里留指引。

**现状归一处。** 建成到什么程度,正本是 `OVERVIEW.md` §7。设计文档写"应当是什么样、为什么",规范文档写"该怎么做"——**都不在论证里夹进度句**。"已接线""已写入"混在契约正文中间,既检索不到也没人维护:`GEOKERNEL.md` §11 一度有七处这样的句子,而同一份文档 §10.1 的表里有一项标着未完成、实际早已落地,没人察觉。

两种写法不受这一条约束,因为它们位置固定、可一眼对账:**文档顶部的范围声明**(告诉读者哪几节写的是"应当"而非"现在"),以及**迁移账本里独立的状态列**(`KERNEL.md` §4.1)。

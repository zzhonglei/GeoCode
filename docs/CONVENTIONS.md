# 项目开发与代码规范

这些规范不是仪式:代码风格来自我们代码库的血统(与内核同源),流程规则背后都有真实事故。

## 1. 语言与总则

文档用中文;代码、注释、提交信息一律英文。TypeScript 全栈,包管理与测试用 bun,格式交给 prettier(无分号、宽行),不做人肉排版。写代码的总纲:**读起来像仓库里已有的代码**——风格一致性优先于个人偏好。

## 2. 代码风格

**函数组织**:逻辑保持在一个函数里,除非确实可组合或可复用;不为单次使用预先抽助手函数。分支多的函数让主体读起来是"幸福路径",支撑细节放到主函数下方的小助手里——只在助手能命名一个真实概念(如 `requireConfig`)时才抽。

**变量与控制流**:`const` 优先,用三元或早返回代替重赋值;避免 `else`,用早返回;只用一次的值就地内联,减少变量总数;避免 `try/catch` 与 `any`;优先函数式数组方法(map / filter / flatMap),filter 用类型守卫保住下游推断。

```ts
// Good
const journal = await Bun.file(path.join(dir, "journal.json")).json()
if (condition) return 1
return 2

// Bad
const journalPath = path.join(dir, "journal.json")
const journal = await Bun.file(journalPath).json()
if (condition) return 1
else return 2
```

**导入与访问**:不给导入起别名,不用星号导入;需要命名空间就导入模块自己导出的命名空间。避免无谓解构,用点号访问保留上下文(`obj.a` 而非 `const { a } = obj`)。启动敏感路径上的重模块用动态导入,且放在需要它的最窄分支里。

**注释**:只为不明显的约束和出人意料的行为写注释;不解释显而易见的赋值和控制流,不写"给审阅者看"的注释。

**运行时 API**:能用 Bun 原生就用(`Bun.file()` 等);类型能推断就不标注,显式类型留给导出边界。

## 3. 包边界与依赖方向

monorepo 的依赖只许单向流动,违反即架构腐蚀:

- `packages/geo-kernel` **零依赖** Electron 与界面;可独立编译、独立测试(这是"地理内核是独立系统"的落地保障);
- `packages/app`(界面)只依赖 SDK 与 HTTP,**绝不 import 内核或 geo-kernel 的内部模块**;
- `apps/desktop`(壳)可依赖 app 与 geo-kernel 的构建产物,反向禁止;
- 共享类型放 `packages/shared`,它不依赖任何其他包。

## 4. Git 与变更流程

分支名:三个词以内、连字符分隔、不带类型前缀(`kernel-thin`、`fix-raster-alpha`)。提交信息:conventional commit,`type(scope): summary`,类型限 `feat` / `fix` / `docs` / `chore` / `refactor` / `test`,一到两句,不带任何 AI 署名。

流程铁律:助手绝不擅自 commit;提交前完整 diff 审计并报告——机械性批量修改恰恰最容易漏改;每批改动以表格陈列(位置、内容、用户可见效果、验证方法),维护者实机过目后才谈提交。push、建仓、发版由维护者亲自执行。会随安装包分发的元信息(author / copyright / publisher)不得自动填真实姓名邮箱,必须过问。高风险改动配多路独立审查;审查类子任务一律只读,任务书须写明不得修改工作树。

## 5. 内核工厂仓专用规范

内核瘦身与薄补丁维护发生在内核工厂仓(独立于本仓),那里的规则:

**定制阶梯(军规)**:配置 → 环境变量 → 外挂进程 → 界面 → 源码补丁。每处源码补丁必须书面说明为何前四层做不到,并配一个运行时绊线测试;补丁面只许收缩。

**补丁标记**:留守的源码补丁必须可被 grep 一网打尽。两级标记:小改动用行尾 `// GeoCode:`;多行或含取舍判断的用块标记 `// --- GeoCode: <why> --- ... // --- /GeoCode ---`(heavy 必写 why,并保留上游原码作合并锚点)。禁止自造变体(全大写、无冒号、中文冒号都不合法)。定位命令:

```bash
grep -rnE "// GeoCode:|/\* --- GeoCode|// --- GeoCode" packages/
```

**合并纪律**:解冲突逐处手解,绝不整文件取某一方(`--theirs` 会静默丢掉散落同文件的补丁);合并后跑绊线套件,红了就是有补丁被上游重构架空。

## 6. 工具设计

工具返回原子事实,不预分类、不预建议——给 agent `coverage: 0.42`,而不是 `quality: "low"`;阈值判断是 agent 的工作。工具描述简短,只写最关键的事实,边界情况靠运行时错误信息暴露;描述中的限制数字故意比代码常量更严,给 agent 留余量,这种"不一致"是设计不是缺陷。错误处理按场景分三种模式,不追求统一:用户必须知情的抛出;检索类失败写入输出让 agent 自行处理;执行类失败返回诊断旗标供 agent 决策。执行失败时已写盘的部分输出保留,用户有权检查半成品。提示词模板整句一行,不软换行。

## 7. 测试

尽量不用 mock,测试真实实现,不把业务逻辑复制进测试里。测试从各包目录运行,不从仓库根跑。地理内核的业务逻辑(探测状态机、预览管线、技能商店)必须可脱离 Electron 单测;界面单测需预载 DOM 环境。绊线测试是运行时验证,编译通过不算数——历史上最痛的事故全是"typecheck 与测试全绿、运行时静默失效";凡"写下配置期望被某服务读到"的改动,必须追到读取方并用运行时测试锁定。发版前两平台实机、双档案(全新 + 存量)各过一轮。

## 8. 平台边界

只支持 macOS arm64 与 Windows x64。Windows 上只允许 cmd / powershell / pwsh——GIS 工具链装在 Windows 原生路径,混入 WSL 或 Git Bash 的路径风格会让 agent 处理路径出错。QGIS 的安装与重装永远由用户在官网完成,应用只探测与引导。macOS 上 QGIS 子进程引起的 Dock 图标闪烁是已知现象,接受不修。

## 9. 安全红线

本地服务只听 127.0.0.1,每次启动换随机口令;渲染进程零特权,凭据经 preload 下发;权限在内核层强制,界面过滤只是体验。应用退出必须回收全部子进程,并有崩溃后的孤儿清理兜底。内核的 provider / auth / account 区与 wire 指纹(`@opencode-ai/*` 包名、`OPENCODE_*` 环境变量、User-Agent、Referer)永久冻结、逐字保留——用户与上游生态共用同一套 OAuth 通道,这些是通道的身份凭据。

# GeoCode 的 Python 包

`geocodekit` 是 GeoCode 自带的 Python 包,装在内置 Python 环境里。它把各能力域常见的地理操作做成标准的函数:GeoCode 的工具(如 `geerun`)在运行的脚本里用它,GeoAgent 自己写的脚本也可以用它。

## 1. 定位

没有标准的函数,同样是读一个研究区、存一个结果,每个脚本的写法、出错的方式与打印都不一样,GeoCode 也无从知道脚本做到了哪一步。标准化带来三点:

- 做对:常见的步骤有现成的函数,模型不必知道每个坑。直接写的细节容易出错,错了又常常不报错,只是结果不对。函数用错时报错,并说明怎样改。
- 可管理:关键的步骤经过 GeoCode 自己的函数,GeoCode 就知道每一步在做什么,例如存进任务的资产带着标题、说明与指纹,能被下一次运行沿用。
- 及时的反馈:在 GeoCode 的工具里,函数告诉工具行它在做什么;结局打印给模型。

GeoCode 的地理能力多半以这个包的新函数出现,所以它的结构与约定先定下:新的能力域与专题照着加,不必改动已有的部分。

## 2. 结构

包按能力域分子包,一个能力域一个:

```
geocodekit/
├── gee/      Google Earth Engine
└── _*        各子包共用的内部模块
```

以后的能力域各加一个子包,以能力域的简称命名,已预留 `osm`(OpenStreetMap)与 `carto`(制图)。制图不用 `map`:`from geocodekit import map` 会盖掉 Python 自带的 `map`。

脚本按能力域导入子包,用简短的名字:

```python
import geocodekit.gee as gee

region = gee.region("数据/台北.geojson")
```

按能力域分,是因为各能力域的函数处理的对象与能用的场合可以不同:`gee` 的函数进出 Earth Engine 在云端的对象,只能在 `geerun` 里用;处理本地数据的能力域,函数在哪里都能用。同一个概念在两个能力域里可以各有一个同名的函数(返回的对象不同),不会混淆。GeoEngine 的代码、测试与文档也按能力域分,改一个能力域只动包里它那一块。

一个子包里分两层:

- 核心链路的函数直接放在子包里,如 `gee.region`、`gee.composite`、`gee.download`:几乎每个脚本都用到,不该藏深。
- 专题各开一个命名空间,如 `gee.water`、`gee.landcover`:一个专题有了几个函数才开,只有一两个时先放在子包里。层次最多到专题这一层(`gee.water.extent`),再深,模型与人都难记。

专题之间、子包之间都不互相调用公开的函数;要共用的(读本地研究区、向工具行报告、输出文件的命名)放进下划线开头的内部模块。这样每个专题都能单独改动,共用的部分只有一份。

包名不叫 `geocode`:PyPI 上已有一个同名的地理编码包,「geocode」在地理学里又本来就是地理编码的意思,模型会误解它,也可能为了地理编码把那个包装进工作环境,盖过 GeoCode 的。

## 3. 公开的接口

公开的接口是子包与专题的 `__all__` 列出的名字,其余都是内部的,可以随时改动。公开的名字会写进工具说明与技能,进入模型的用法:

- 改名或删除公开的名字与参数时,同一批改动里改掉工具说明与技能里的写法。
- 公开函数的说明(docstring)是交给模型的文字:GeoAgent 可以用 `help()` 读到。它与工具说明一样用英文,照 `GEOENGINE.md` 第 3.4 节撰写与定稿。
- 工具说明只列核心链路的函数,各有一行签名与说明;专题与可选参数的用法写进技能,不让工具说明越写越长。

## 4. 函数的约定

每个公开的函数都照下面的约定写,新能力域的函数也一样。约定在内部模块里各实现一次,各子包共用。

- 进出:函数进出的是这个能力域通用的对象(Earth Engine 的 `ee` 对象、GeoPandas 的 GeoDataFrame、文件路径),模型随时可以与标准写法混用。函数的价值放在标准写法难做对的地方,不把标准写法再包一层。
- 参数:同一个概念在各子包里用同一个参数名;函数建在某个库之上时,参数名、默认值与算法照那个库(GEE 照 geedim)。
- 出错:用错时报错,说明怎样改;不吞掉错误,不返回空的结果。
- 打印:只陈述事实(存了什么、在哪、用了多久、沿用了什么),不替模型下判断。
- 进度:在 GeoCode 的工具里,函数用一句英文告诉工具行它在做什么,知道进度的带上百分比(第 5 节)。
- 输出文件:不覆盖已有的文件,撞名时在文件名后加 `_1`、`_2`,取最小的空号;不留半截文件。

## 5. 运行的场合

函数在两种场合里运行:

| | GeoCode 的工具 | GeoAgent 自己的脚本 |
|---|---|---|
| 环境 | `base`(结果确定,`PYTHON.md` 第 8 节) | 工作环境 |
| 谁启动 | GeoEngine | GeoAgent 在 shell 里 |
| 进度 | 报给工具行 | 不报 |
| 能用的子包 | 全部 | 不依赖工具场合的子包 |

工具的运行脚本在 GeoAgent 的脚本开始之前设好场合:报告进度的出口,以及能力域要的准备(GEE 初始化 Earth Engine、设好任务)。没有设好场合时,函数照常运行,只是不报进度:GeoAgent 的脚本在 shell 里运行,它的输出全部进了模型的上下文,进度行对模型写脚本没有用。

依赖工具场合的子包(如 `gee`,`GEE.md` 第 5 节)在场合之外导入即报错,说明它只能在哪个工具里用。

导入要轻:导入 `geocodekit` 不加载任何子包,导入子包不加载它的专题,用到才加载。子包再多,导入也不变慢;`gee` 也不会在没有 Earth Engine 的地方被意外加载。

## 6. 安装与更新

源码在 `geoengine/python/`:一个标准的 Python 项目,`pyproject.toml` 写明包名;它不经 pip 构建与安装(见下),所以不声明构建后端。版本就是 GeoCode 的版本号(`DESKTOP.md` 第 6 节),`pyproject.toml` 只声明它是动态的,不另写一份:GeoEngine 写安装记录时从 GeoCode 的版本号取,改了 GeoCode 的版本号,包的版本随之改,没有第二处要对齐。构建 GeoEngine 时包的文件原样编进它的代码,随它分发:打包版里 GeoEngine 在应用的归档中,Python 读不到那里的文件,编进代码的文件 GeoEngine 随时取得到。构建因此不需要 Python。

GeoEngine 自己把包的文件写进 `base` 的 `site-packages`(每次启动核对,见下),并写下标准的安装记录(`dist-info`):`pip show geocodekit` 看得到它,`importlib.metadata` 读得到版本,报错的 traceback 指向磁盘上的文件。`base` 的 `EXTERNALLY-MANAGED` 标记照旧挡住 pip 与 uv,GeoAgent 与任何运行都不往 `base` 里装包;装这个包的只有 GeoEngine,方式与它写启动文件相同(`PYTHON.md` 第 6 节)。

工作环境继承 `base`(`--system-site-packages`),所以 GeoAgent 的脚本直接导入就能用;GeoCode 的工具在 `base` 里运行,同样直接导入。

包没有自己的版本记录,跟着 GeoCode 走:每次启动时,GeoEngine 把磁盘上包的每个文件(连同安装记录)与这一版 GeoCode 自带的逐个比较内容,不同的与缺了的重写,多出来的删掉,与启动文件一样(`PYTHON.md` 第 6 节)。包很小,比较很快,比的又是文件本身:用到的总是这一版 GeoCode 的包,开发时改了包,下次启动用的就是改过的;中途退出留下的半截包、被改坏的包,下次启动同样被换掉。环境只在锁定清单变了时才重装。核对在预热之前,窗口与工具碰到的总是这一版的包。

开发版与打包版共用数据目录时,后启动的那个换上自己的包;两个同时开着,先开的那个会用到另一个的包。开发时在沙箱主目录里启动(`DEVELOPMENT.md` 第 5 节),碰不到这种情况。

没有采用的做法:

- 随每次运行把包的源码交给 Python:只到得了 GeoCode 的工具,GeoAgent 自己的脚本用不上。
- 做成 conda 包写进锁定清单:包每改一次,环境的标识就变,环境整个重装。
- 只装进工作环境:GeoCode 的工具在 `base` 里运行,用不到;工作环境又会被 GeoAgent 改动。
- 按 GeoCode 的版本号判断要不要重写:开发时版本号不变,改了包也不会重写。
- 每次启动先删掉整个包再写:删与写之间,别的 GeoCode 或还没结束的运行可能导入到缺了的文件。

## 7. 依赖

包只用 `base` 里预装的包。新函数要用新的包,同一批改动里把它加进锁定清单(`PYTHON.md` 第 4 节);用户更新到这一版时环境随之重装。

在 GeoAgent 的脚本里,函数用的是工作环境里的包。GeoAgent 照规范不用 pip 重装预装的包(`PYTHON.md` 第 5 节)时,它们与 `base` 里的版本一致;重装过的,函数可能出错。

## 8. 测试

测试照 `DEVELOPMENT.md` 第 7 节分层,每个子包对应自己的一组:

- 单元测试:只用替身,不需要装好的环境,包从 `geoengine/python/` 的源码导入。GEE 的函数用替身的 earthengine-api,在 `PATH` 里的 `python3` 上运行(`CONVENTIONS.md` 第 2.3 节)。
- 真实软件的测试:接真实的服务,如 Earth Engine。

## 9. 约束

- 包只由 GeoEngine 装进 `base`;GeoAgent 不往任何环境里装 `geocodekit`。
- 公开的接口只是 `__all__` 列出的名字(第 3 节)。
- 子包之间、专题之间不互相调用公开的函数。
- 导入 `geocodekit` 与它的子包不加载暂时用不到的部分。
- 包只依赖 `base` 里预装的包。

## 10. 验收

- `base` 与工作环境的 Python 都能 `import geocodekit`,`pip show geocodekit` 显示与 GeoCode 相同的版本;往 `base` 装别的包仍被拒绝。
- 只改了这个包时,启动时不重装环境,工具与 GeoAgent 的脚本用到的是改过的包。
- 在 `geerun` 之外导入 `geocodekit.gee`,报错说明它只能在 `geerun` 里用。
- GEE 照常运行:第 4 节的约定、`GEE.md` 第 10 节的验收不变。

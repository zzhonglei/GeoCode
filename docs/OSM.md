# OpenStreetMap

OpenStreetMap 能力域让 GeoAgent 从 OpenStreetMap(OSM)下载干净的矢量数据:按名字找到地物,查看一片区域里有什么、有多少,再把边界或一类要素下载成文件。框架(进程、通道、配置与状态)在 `GEOENGINE.md`,这里只写 OSM 自己的部分。

## 1. 定位与范围

OSM 能力域只负责把数据干净地取回来。裁剪、投影、改字段名、换格式、由道路建路网这些处理,由 GeoAgent 用 QGIS 或 Python 去做:它们本来就做得到,放进下载工具只会让工具越来越重,还替用户做了未必想要的决定。

GeoAgent 得到四个工具:

| 工具 | 做什么 | 权限参照的自带工具 |
|---|---|---|
| `osmsearch` | 按名字找 OSM 对象,给出 id、类别与位置 | `websearch` |
| `osmprobe` | 查看一片区域:日常说法对应的标签写法、各种标签的数量、几个键的取值分布 | `websearch` |
| `osmgetobjects` | 按 id 下载对象,如校园、湖泊与行政区的边界 | 见第 8 节 |
| `osmgetfeatures` | 按范围与标签下载一类要素,如道路、建筑、POI | 见第 8 节 |

工作的顺序是先定研究区与内容,看清有什么、有多少,再下载,最后由 GeoAgent 用 `readgeodata` 检查结果。工具名照 OpenCode 自带工具的写法(`QGIS.md` 第 1 节)。

每个工具独立完成自己那一步:结果落成文件,答复只陈述拿到了什么、缺了什么,不把数据本身交给模型。

范围是在线的公共服务承担得了的下载:一个地物、研究区里的一类要素、一套基础数据的各个主题。省级以上的大范围数据(如一个省的全部建筑)超出了公共服务的承受能力,不在这个工具的范围之内。

路网不单独做成一种产出,按范围下载的道路线就是它的原料。QGIS 的网络分析算法把每个顶点当作图的节点,合并坐标重合的顶点,所以 OSM 里在路口共用的节点被连起来,不共用节点的立交不会被误连。按出行方式筛选、整理方向与速度由 GeoAgent 处理;要中心性这类图指标时,它可以在工作环境里装 osmnx 或 networkx。下载为此守住三条:坐标原样写出,不简化、不降精度;道路单独成一个图层;能按需留下 `oneway`、`maxspeed` 这类建网要用的标签。

## 2. 执行

工具在内置 Python 环境的 `base` 里执行(`PYTHON.md` 第 3 节),链路与 `geerun` 相同:内核里的工具请 GeoEngine 确认这次调用能开始,再按权限询问(第 8 节),GeoEngine 启动 `base` 的 Python 运行 GeoCode 的运行脚本,由它调用 `geocodekit` 的子包 `osm`(`GEOCODEKIT.md`)。一次调用一个进程,结束就退出。

放在 Python 里,是因为内置环境已经只按代理变量联网(`PYTHON.md` 第 6 节),OSM 的请求照全应用的代理规则走,不必另做;GeoEngine 用的 Node 不读代理。几何的运算(凸包、带洞多面的收回、代表点)交给 shapely,写 GeoPackage 交给 GDAL,都是现成的实现。

OSM 没有要配置与检查的东西:服务是公共的,环境是内置的。所以它不登记状态,没有指示灯,也不在「地理环境」设置页里(`GEOENGINE.md` 第 3.4 节);一个指示灯只能说「公共服务此刻不顺」,用户既无从修,也不必修。工具调用时等内置环境就绪,服务答不上就在答复里如实说明。

请求与几何的装配由 GeoCode 自己写,不以 osmnx 为底:它的下载层替换整个进程的域名解析、对同一个端点无限地重试、只认一个端点、对不完整的结果只记日志、默认把缓存写进当前目录,要改就得替换它的私有函数;它还连带装上 geopandas、scikit-learn 等可选依赖。

标签的写法取自 OSM 编辑器 iD 的预设库 `id-tagging-schema`(社区维护,ISC 许可)。它记着每类东西靠哪些标签认出、新建时一并加哪些标签、哪些属性值得记录,以及英文的名称与同义词,另有弃用标签与新写法的对照。只带英文:GeoAgent 用英语工作,把用户的说法转成英文不难。预设库锁定一个版本,随 `geocodekit` 分发,用到时不联网;它的许可证声明放在发布仓库里(`DESKTOP.md` 第 6 节)。一条首尾相接的线算不算面,照另一份社区维护的规则 `osm-polygon-features`(CC0,不必署名),同样锁定版本、随包分发。地名不在此列,按当地语言检索(第 4 节)。

## 3. 公共服务

| 服务 | 用途 |
|---|---|
| Overpass | 下载与计数要素;在一个区域里按名字匹配,或名字对不上时列出一类对象;按 `wikidata` 标签取回对象 |
| Nominatim | 按名字检索地物;补全候选所在的地方;按 id 取对象的几何与标签 |
| Photon | 按名字检索地物 |
| Wikidata | 检索有名的地物的别名、正式名与各语言的名字,以及一句说明 |

Overpass 有几个公共实例,GeoCode 只问免费、覆盖全球、不用注册的三个;别的要注册取 key、收费,或只有部分地区。官方的两台服务器只问总地址:它们是同一个实例,收到 429 后要停的是整个实例(见下),紧接着改问另一台就等于没停。

一个实例此刻接不接得下请求,事先无从知道,只有真实的请求看得出来;让请求干等的实例,要等到查询的时限(下载是 3 分钟)才看得出来,一个个试下去,一个这样的实例就耗掉 5 分钟(第 7 节)的大半。所以查看与下载问 Overpass 之前先探路:同时向每个实例发一个只取一个节点的查询,声明的时限与下载的相同:服务器按查询声明的时限决定接不接,声明得短的探路在满载时也接得下,接下来的下载却会被挡回。服务器让排不上名额的请求至多等 15 秒,探路因此在 20 秒内有结果。答上了、数据也不比一周前旧的,才交给它真正的查询:上一次答上查询的先用,其次是探路最先答上的,答得快说明它此刻有空。数据旧的实例照常回答、不报错,只有答复里的数据时间看得出来。真正的查询不同时交给几个实例、谁先答用谁:没被用上的实例照样把查询算完,白占社区捐赠的服务器。

真正的查询失败时,交给探路答上的另一个实例,一个也不剩时再探路,直到这次调用连续 5 分钟没有进展,或者再没有可问的实例(第 7 节)。

答以满载(5xx 与 429)、答到一半断开、因这次调用剩下的时间不够而没等满时限,或探路时 20 秒内没有答上的实例,30 秒内不再问(官方的使用政策要求收到 429 后停 30 秒):满载的服务器过几分钟常常就空出来了,问得更勤只会添它的负担。暂停与上一次答上的实例由 GeoEngine 记住,交给之后的调用与检索:政策算的是这台电脑发出的请求,每次调用却是一个新进程。

连不上的、答以别的状态(如服务搬走了)或不成结构的东西的、数据旧的,与让真正的查询一直等着的实例,这次调用里不再问:数据旧的仍然是旧的,一直等着的再问一次又要等那么久。

查询本身写错(HTTP 400)时不换实例,把服务器说的原因交回。服务器以正常的结果说明它中途停下了(超时、内存不够)时,服务器的原话随之交回:「超时」与「查询太宽」要求的是相反的改法。响应边收边计大小,超过上限就停止。

公共的 Overpass 按 IP 分配名额,一个查询占着名额直到跑完;官方的政策也不许并行的脚本。所以查看与下载在 GeoEngine 里排成一队,一次只运行一个;一次调用里,几个实例可以同时各做一件事,每个实例一次一件(第 7 节)。一次调用自己就用得上所有有空的实例,调用之间不必再按实例分配。检索不排队(第 4 节)。

这些都是社区捐赠、免费给所有人用的服务,GeoCode 照各自的使用政策使用:

- 请求的 User-Agent 写明 GeoCode、它的版本与发布仓库的地址。各家都要求标明来自哪个应用,不带标识或用 HTTP 库默认值的请求会被拒绝。
- User-Agent 与请求里都不带用户或安装的标识。Nominatim 的上限按应用计算,所有用户加在一起,分开标识减少不了总量;一个固定的安装标识还会让第三方把同一个用户长期的检索串起来。
- 按顺序、限速地发,Nominatim 每秒至多一次,整个应用的调用一起算:检索、查看与下载都问它,可能同时在跑,每次请求之前在状态目录的一个锁文件里看过、记下上一次请求的时刻(`PATHS.md` 第 4 节)。

服务的地址写死在代码里,不做配置。Nominatim 的政策要求服务方提出时,应用不更新软件就能换用别的服务,GeoCode 不满足这一条:被要求更换或被封时靠发新版解决。检索综合几个服务(第 4 节),少了任何一个只是变差,不会失效。答复与文件的说明不提数据来自哪个服务(`GEOENGINE.md` 第 3.5 节)。

检索的名字与下载的范围交给这几个服务的运营者。这是用户要用的功能,不属于 `DESKTOP.md` 第 3 节关闭的那类请求。

OSM 的数据按 ODbL 许可提供,要求署名「© OpenStreetMap contributors」,下载的文件里写着它(第 7 节)。「OpenStreetMap」与「OSM」可以用来命名处理 OSM 数据的工具,也可以为署名而写出;工具行的图标用 OSM 的放大镜标志(第 9 节)。OSM 基金会的商标声明与许可证声明一起放在发布仓库里。

## 4. 检索

`osmsearch` 一次检索一个名字。名字优先用当地语言的正式名:OSM 的 `name` 写的是当地的名字,大陆与台湾的地物多半没有英文名。另有两个可选的参数。上下文是这个地方在哪里,用来区分同名的地方:写城市,可带国家以区分同名的城市;不写区与更小的地方,筛选按外包框,区写错或写小了,要找的对象会被当作离得远而去掉;只写国家收窄不了多少,国家的外包框常把邻近的地方也包进去。之前检索得到的区域 id 也可以作上下文。类别是一个标签过滤,如 `amenity=university`,只留下符合它的对象。简称与俗称(如「地大」)哪个服务都对不上,由 GeoAgent 先展开成全称。

检索分两段。第一段找候选:四个服务并行,各自只交出 OSM 对象与命中的依据;Wikidata 找到的条目,经 OSM 对象的 `wikidata` 标签接回 OSM;Overpass 只在给了上下文时,在那个区域里按名字匹配,不在全球扫描。第二段统一补全:所有候选一起由 Nominatim 补上名字、标签、外包框与所在的地方,再补上 Wikidata 的说明;Overpass 已给出标签的,用 Overpass 的。各服务描述同一个对象的方式各不相同,按谁找到就用谁的描述拼起来,模型无从比较候选;统一补全之后,每个候选都有同样的字段、同样的写法。Nominatim 没有回答第二段时,只有 Overpass 给了标签的候选能补全,其余的这次列不出,答复写明结果可能不全;上下文的地方没有回答时也一样,检索不按它收窄,而不说没有这个地方。

几个服务互相补位:Nominatim 按地址理解输入,索引各语言的名字,简繁不同也对得上;Photon 对得上只给出一部分、或中间多了字的名字,如「广州白云机场」与「广州白云国际机场」;Wikidata 记着有名的地物的别名与正式名,一个候选带着 Wikidata 匹配到的条目时,不论是哪个服务找到它的,条目匹配到的名字都算作它的名字;没上 Wikidata 的普通地物,靠 Overpass 在区域里逐字匹配。

检索里 Overpass 的两步是可有可无的补充:不探路,各只问两个没在暂停的实例,从上一次答上的那个开始,各等一会儿,答不上就算这部分没有完成,答以满载的同样暂停(第 3 节)。公共的 Overpass 常常满载,检索不该为它等上几分钟,也不排在几分钟的下载后面;Nominatim、Photon 与 Wikidata 照样给出候选。

排序以名字与输入有多像为主(不计大小写、全角与半角、空格与标点),其次是几个服务都找到它:名字逐字比较看不出简体与繁体是同一个名字,几个服务都找到它正好补上。再看 Nominatim 给的重要度、它是否连着 Wikidata 的条目,面先于线与点。与地物同名的公交站、车站与地名点排在后面:它们在地名检索里数量多,几乎总是噪音。找到的对象没有一个符合类别、而上下文找到了时,列出那个区域里这一类有名字的对象。

答复列出候选,每个写明 id、类别(预设的英文名与标签;多个标签时写成过滤条件的写法,如 `[leisure=pitch][sport=soccer]`,照抄就能当过滤条件用,用分号连起来会被读成一个标签的值,什么也对不上)、点线面与大致的大小、当地名与英文名、所在的地方、中心点(注明先纬度后经度),以及 Wikidata 的说明。iD 对同一种东西另有旧写法的预设(如 `amenity=university` 之于 `education=university`)时,对象带着旧写法就写旧写法:OSM 里多数数据只带旧写法,模型照抄去查看或下载,用新写法会漏掉大半。所在的地方写城市、省与国家,取 Nominatim 结构化地址里现成的字段,如「New Taipei, Taiwan」「Hongshan District, Hubei, China」。大陆的区与地级市在 Nominatim 的结构化地址里都算城市,只留下区,所以大陆写区。地级市只在完整地名里,从中推出要依赖它的输出格式,所以不推;同省同名的区靠中心点分辨。城市或区本身作为候选时,写的是它自己的名字。没有城市时取最近的上一级;没有英文名的用当地名。候选太多时写明一共多少个,按类别列出的超过 10 个时写明只列了其中 10 个。给了类别时,没找到的说法写明是哪一类:名字对上而类别不符的对象不算找到,答复不能说没有叫这个名字的对象。检索有一部分没有完成时,写明结果可能不全,没找到时说对象可能仍然存在,免得模型当作没有这个地方。答复不写候选是谁找到的,排序本身就体现了可信的程度。

## 5. 范围与标签

`osmprobe` 与 `osmgetfeatures` 以同一种写法给出范围:

- 检索得到的面状对象的 id;几个 id 以逗号连起来时取并集,如一所学校的几个校区。
- `bbox:南,西,北,东`。
- `around:纬度,经度,半径`,或 `around:id,距离`(可以是几个 id),后者是这些对象本身连同向外这么远的一圈,即它的缓冲区;单位都是米。距离在以对象为中心的等距投影里量,与 `file:` 一样先化简再按真实的形状收回。
- `file:路径`:本地边界文件里的面合在一起,文件有几个图层时以 `|layername=图层名` 指明其中一个;任何坐标系都由工具转成经纬度;相对路径与 `read` 一样落在会话目录。

坐标一律纬度在前,与 Overpass 和检索答复里的中心点一致,模型不必在两种顺序之间切换。写错的范围(纬度超出范围、南大于北、点或线的 id)在查询要素之前报错,并说明正确的写法。

范围里的 id 先向 Nominatim 取几何,与探路同时进行(第 3 节):它一秒左右就答,不占 Overpass 的名额;给的几何与 Overpass 拼出的相同,带洞的面照样有洞,大的边界也不化简。点线面仍照 GeoCode 的规则(第 2 节),首尾相接的路算不算面按 Nominatim 给的标签判断。Nominatim 没有的对象(它不收录所有对象,没有名字的常常不在其中),与它只给出一个点的关系,问 Overpass。

边界交给服务器之前可能要化简:顶点太多时换成凸包,仍太多时换成外包框;范围由超过 8 块分开的面组成时,换成包住全部的一个外包框。后者对相隔很远的几处(几个城市里的校区、多岛的县)多出的部分可能远大于范围本身,计数偏多、下载变慢,所以给模型的说明请它分开查看、分开下载。化简只能向外,下载之后再按真实的边界收回,内环(洞)里的要素不属于范围:多下载的部分事后收得回,少下载的部分永远发现不了。与边界相交的要素整个保留,不在边界处切开,切开是 GeoAgent 的处理。

标签是一组写法的并集,每个写法是 `键=值`、只写键(有这个键就算)、`键~正则`(值符合正则)或 `键!~正则`(有这个键,而值不符合正则);几个条件各放进方括号连写时要同时满足,如 `[natural=water][water=reservoir]`,与 Overpass 的写法相同。`!~` 用于「所有 POI,但不要长椅与垃圾桶」这类要求;方括号用于 iD 的预设里由两个标签合成的类别,`osmprobe` 答复里的写法可以原样用于下载。

## 6. 查看

`osmprobe` 在一个范围里回答三种问题,每次问一种:

- 一个日常说法(英文)对应哪些标签写法,各有多少:在预设库里匹配名称与同义词,至多取 6 个预设,对每个的写法、新建时一并加的标签与弃用写法各数一数。
- 一组标签各有多少,合起来有多少。
- 几个键在这里各有哪些值,各有多少。至多读 10 万个要素,读满时写明是样本。

第一种是下载时标签的来源。OSM 里同一类东西常有几种写法:医院有 `amenity=hospital` 与 `healthcare=hospital`,水库有 `natural=water` 加 `water=reservoir` 与 `landuse=reservoir`,只写一种会静默地漏掉一大块。写法取自社区的约定,而不是模型的记忆;配上研究区里的实际数量,由 GeoAgent 决定要哪几种。同义词匹配得宽(医院的同义词里有诊所),所以数量与取舍必须摆在一起看。

下载之前不必先查看,数量多时由下载自己分批(第 7 节)。查看用来选标签,也让用户知道数据的量级。数量是在交给服务器的范围里数的,不按真实的边界收回:范围化简过(第 5 节)或带洞时,数量偏多。服务器中途停下时,已经数出的照常给出,没来得及数的写法另外列出,不当作这里没有。

## 7. 下载

`osmgetobjects` 按 id 下载对象,几何随结果一次取回,不逐个取回再拼接:后者在大的关系上会静默地拼出残缺的边界。探路时没有一个实例答上,或 Overpass 一直问不下来而停下时,先写出 Nominatim 有的对象:几何与点线面同第 5 节;标签少了 `addr:*`(Nominatim 把它整理进自己的地址格式),也可能少几个 Nominatim 不收的,它自己加上的不算标签;数据时间取 Nominatim 报的,不报时取当时,它只比 OSM 晚几分钟。其余的照常等 Overpass。

`osmgetfeatures` 按范围与标签下载一类要素,几何可以原样,也可以把每个要素塌缩成一个代表点,并记下它原来是点、线还是面。POI 要用代表点,而不是只取点类型的要素:大量设施以面测绘,只取点会静默地丢掉它们,丢的往往是多数。

一次调用下载一个主题。一套基础数据(道路、水系、建筑)分几次调用,各写一个文件:一个主题失败不牵连别的,每次调用的参数、询问卡片与答复都只关于一类数据。要合进一个文件时由 GeoAgent 处理。

数据多时,下载自己分批:先数一数,多了就把范围的外包框分成四块再数,仍多的再分,直到每块都是一次请求下得了的,至多分到第 6 层。各块的计数与下载分给探路答上的几个实例同时做,每个实例一次一块,一个实例不行了,它手上的块交给别的;跨块的要素按 id 只留一份,工具行显示进度。一块在服务器上超时或答复太大时,再分成四块重下;到第 6 层仍下不全的块不再分,记为缺失。多到在线下载承担不了时不下载,答复写明大约有多少与上限是多少。数量以整片的计数为准:跨块的要素在每一块里都被数到,各块的合计偏多。整片数不出时用各块的合计;有块数不出时不给数量,但已数出的合计仍用来判断是否超过上限。GeoAgent 因此不必管容量,也不必自己按数量拆分范围。

下载不设总时限:数据多、服务器慢时要很久,只要还在动就等。连续 5 分钟没有进展,或者再没有可问的实例(都连不上或数据都旧)时才停下,与用户停止一样丢弃已经下完的部分,答复写明停下的原因;按 id 下载时 Nominatim 有的对象照常写出,答复写明哪些没能下载、为什么。收到数据(包括中途断开的回答里已经收到的)、一块下完、进入下一步算进展;探路、换实例、实例答以满载、等待时的心跳不算,否则一直答以满载的实例会让下载永远挂着。排队等前一个查看或下载的时间不算在这 5 分钟里:那段时间它还没有开始问。门槛要比 Overpass 一次查询在服务器上的时限(3 分钟)长,那段时间里服务器可能一个字节也不发。

下载的数据要干净:

- 不丢:范围的放宽与收回见第 5 节;服务器说不完整的,这一次算作不完整;部分失败时写出已经拿到的部分,并写明缺了哪些。
- 几何正确:多面的外环与内环装配正确,装配残缺的对象不交出;几何不简化,坐标不降精度;一个图层只有一种几何;坐标系为 EPSG:4326。
- 属性整洁:每个要素有 `osm_id`(如 `W245164271`,带着类型)、`name` 与 `category`(预设认出的类别,写法同第 4 节;认不出时取查询点名的第一个键与它的值);另外留下查询用到的键、预设库认为这类东西值得记录的属性,以及调用时点名要的键;要全部标签时另存进一列,上面这些列照常保留。「这类东西」先看查询的标签所对应的预设,再看各要素自己的预设,后者的键要至少有 5% 的要素带着才留:道路因此留下单行、限速、车道与路面,而校园里唯一一栋兼作餐厅的建筑,不会让所有建筑都多一列菜系。OSM 的元数据(编辑者、版本等)不当作标签。标签的值原样写出,不做解读:`maxspeed=CN:urban` 不换成数字。
- 不重、不覆盖:多个范围与分批之间按 id 去重;输出撞名时在文件名后编号,不覆盖已有的文件。

产出只有 GeoPackage:一个文件里点、线、面各一个图层,只有一种几何时只有那一个图层。GeoJSON 一个文件放不下几种几何,Shapefile 的字段名限 10 个字符;GeoPackage 在 QGIS、ArcGIS Pro、GeoPandas 与 GDAL 里都能直接打开,要别的格式时由 GeoAgent 转换。字段名照 OSM 的原样,如 `addr:street`、`name:en`。每个图层的说明写着署名、OSM 数据库的时间与下载了什么,不完整时注明缺了什么:文件过后被单独打开时不会显得是完整的,论文引用数据时也有依据。

输出的路径由 GeoAgent 给出,相对路径落在会话目录。输出的文件夹写不进(没有权限、磁盘只读)时,在下载之前就报错,不让用户等完一次注定写不出的下载。一个要素都没有时不写文件。用户停止下载时,已经下完的几批也丢弃,不留半截文件:一份下了一半、又看不出缺了哪里的文件不干净。

答复写明写出的路径、每个图层的要素数、OSM 数据库的时间、保留了哪些字段、丢弃了哪些键与各有多少要素带着它(全部列出,不截断),以及缺了什么。

## 8. 权限

四个工具在设置的工具权限里各有一行。检索与查看的「始终允许」按整个工具记住,下载的见下。

询问之前先拦下注定开始不了的请求,不让用户批准它:内核按参数的定义查个数(编号 1 到 25 个、至少一个标签、键 1 到 5 个)与检索的名字不空,`osmprobe` 要恰好给出词、标签与键中的一种;再请 GeoEngine 确认内置环境就绪(还在准备时与调用一样等它)、输出是绝对路径、边界文件存在。这一步不启动 Python,范围与标签的写法要到调用开始时才查:读一个范围常要先问 OSM 的服务。

`osmsearch` 与 `osmprobe` 只读,默认放行。范围是本地的边界文件时不按 `read` 询问:GeoAgent 没有读到文件的内容,工具只把它当作范围,而 GeoAgent 多半已经用 `readgeodata` 读过它。

两个下载工具只新建文件,不覆盖已有的数据,所以不需要 `qgisrun` 那样的算法名单。输出在会话目录或项目里时照规则判断,默认放行。写到项目外时,规则是允许也询问,除非这个目录有过「始终允许」,判断、记住与只在卡片上批准都同 `qgisrun`(`QGIS.md` 第 4、8 节):用户要在批准之前看到数据写到哪里。下载不经上游访问项目外目录的询问,免得那条规则改成询问后一次下载弹两张卡。

## 9. 界面

四个工具在对话里每次调用一行,不合并相邻的调用:检索与查看一般只有一两次,每次的结果也要单独看。

收起时的行照上游的工具行。检索与查看的标题是工具名(随界面语言),运行中变淡,出错变红;描述是检索的名字与上下文,或查看的词、标签与键。下载与 `qgisrun` 一样,标题是 GeoAgent 写的用途,运行中写当前的步骤、分批时的百分比与用时;完成后在标题后用绿色写出写入的要素数,照上游改文件的工具写增加的行数。查看与下载排在前一个后面时,行上写着在排队(第 3 节)。

点开以后不照上游:不回显行上已有的输入,内容放在与标题对齐的浅底面板里,展开与收起时滑动。

- 检索:每个候选写名字(有英文名时一并写出)、是什么与在哪里、大小与 OSM 编号,并用小图形表示它画成了点、线还是面;与地物同名的车站淡一些。只显示最好的几个,其余收起。没有找到、按类别兜底、有服务没有回答时各写一句。候选不链接到 openstreetmap.org。
- 查看:一行一种写法或一个值,带横条与数量;新建时一并加的与弃用的写法标出来,数量为 0 的合成一句放在最后;查看几个标签时写满足任一的要素数,注明不是相加;取值只显示最多的几种,其余收起。服务器中途停下时写一句数量可能偏少,没来得及数的写法另列一句。
- 下载运行中:读取范围、计数、下载、组装几何、写入文件几步(按 id 下载没有读取范围与计数),做完的写用时,下载这一步写第几块与已收到多少;服务器满载、一段时间没有进展时写出来(第 7 节)。服务器计算查询时什么也不发,或者只发出答复的开头,算完才一起发出,收到多少反映不了进度:答复还没开始传来时,步骤写服务器正在查询与已等多久,不写收到的字节。
- 下载结束后:文件名与目录、各图层的要素数、OSM 数据的时间与保留的列,缺了什么、没能下载的与 OSM 里没有的 id 写在下面。失败时写一句原因。

说给用户的话用界面语言:下载的步骤是固定的,结果与失败都是结构化的,界面能自己翻译。服务器的原话(如 Overpass 的报错)、请求写错时的具体原因与系统说的写不进的原因翻译不了,保留英文,放在说明下面。输入框上方的状态条与其他工具一样用英文。

询问卡片的外框、按钮与快捷键照上游,GeoCode 换右上角的名字与卡片的正文。右上角写要做什么;设置里两个下载按编号与按范围分开叫。正文一行一项,照 `qgisrun` 的卡片(`QGIS.md` 第 8 节),太长截断,路径折行写全:

- 下载:请求原因,写到项目外时的警示,下载的对象或标签与范围,取点时写出来,最后是输出的位置,写到项目外时用警示色。「始终」按钮写出要记住的目录。
- 检索与查看:默认放行,用户把规则改成询问才会看到。只写一行要做什么,查看再写一行范围;认不出写法的范围照原样写出。

范围翻成一句话:编号、某处周围多少米、矩形、边界文件的某个图层。编号旁写名字,名字取这个会话里之前检索到的结果,没检索过的只写编号:只写 R10958940,用户认不出是哪里。托盘、系统通知与应用内的提示怎样写这些请求,见 `QGIS.md` 第 8 节。

## 10. 验收

- 中文、英文与简繁不同的名字都找得到对象:「台湾大学」找到國立臺灣大學,「广州白云机场」找到广州白云国际机场,「中国地质大学」列出武汉与北京两个校区;同名的地方各自写明所在的城市、省与国家,与地物同名的公交站排在后面。
- 用一个日常的英文词查看,得到这类东西在研究区里的各种写法与数量,包括新建时一并加的与弃用的写法。
- 下载的边界与 OSM 一致,带洞的多面洞还在;以边界文件或放宽过的范围下载时,结果按真实的边界收回,洞里的要素不在其中,边界附近的要素一个不少。
- 用代表点下载 POI 时,以面测绘的设施也在其中;每个图层只有一种几何,坐标系为 EPSG:4326,字段照第 7 节。
- 下载的道路在 QGIS 的网络分析里在路口连通。
- 数量多到要分批的范围下载完整,结果不重复,工具行显示进度;多到在线下载承担不了的范围被拒绝,整片数不出时按各块数出的合计,并写明数量。
- `around:id,距离` 下载到对象本身连同周围这么远的要素,大对象深处的也在其中。
- 服务器说不完整或部分范围失败时,答复与文件的说明都写明缺了什么;用户停止下载时不留下文件;已有同名文件时编号,已有的数据不被覆盖。
- 慢而一直在收数据的下载不被停下;实例一直答以满载时,按范围下载在 5 分钟后停下,不留下文件,按 id 下载写出 Nominatim 有的对象,答复与工具行写明原因。
- 一个实例让请求干等、另一个有空时,查看与下载在 20 秒内交给有空的那个;要分批的下载由几个有空的实例同时下。
- 以 id 写的范围,只在 Nominatim 没有这个对象时才问 Overpass。
- 同时发起的几个查看与下载依次运行,排在后面的行上写着在排队;同时在跑的检索、查看与下载问 Nominatim 合起来每秒至多一次。
- 工具行与点开的内容照第 9 节;切换界面语言后,标题、步骤与结果的说明跟着换,服务器的原话不变。
- 一个服务不可用时,检索照常给出结果;设了代理变量时,请求都经过代理。
- 输出写到项目外时弹出 OSM 的卡片,只弹这一张,写在项目里时不问;点过这个目录的「始终允许」后不再问,对整个工具的不算。卡片照第 9 节,编号旁写着检索到的名字。
- 内置环境还在准备时先等它,准备不好就以失败结束,不弹询问。
- 写入检测干净。

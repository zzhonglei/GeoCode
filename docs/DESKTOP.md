# 桌面应用

本文档说明 GeoCode 桌面应用由什么组成,以及它遵循的几条基本约束:内核只为应用服务,应用只在本机为一个用户工作,只有应用自己的窗口能访问它,它的行为只由界面里的设置决定。

## 1. 组成

GeoCode 是一个应用,安装、启动、退出都只有一个入口,用户不需要另装 OpenCode。

```
Electron 主进程
 ├─ 壳服务端(OpenChamber 的服务端,在主进程内运行)
 │    └─ 子进程:内核(OpenCode,serve --stdio)
 └─ 界面(渲染进程)── HTTP、SSE、WebSocket ──→ 壳服务端
```

界面只与壳服务端通信,壳服务端把内核的接口代理给界面,转发时附上内核的口令,界面拿不到这个口令。两个服务都只监听 127.0.0.1,壳服务端只接受 GeoCode 自己的窗口(第 4 节)。

## 2. 内核

内核是应用的私有组件:只由这个应用启动,只为它服务,随它退出。壳以 OpenCode 为私有内核设计的 `serve --stdio` 方式启动它:每次启动随机生成口令并显式传入,内核读取后把口令从自己的环境里删掉,agent 执行的命令读不到它;内核把标准输入当作租约,应用正常退出或被强制结束时,内核随之退出,不会留下无主的进程。上游 OpenChamber 用的普通 `serve` 会把口令留给 agent 执行的命令;OpenCode 桌面版用的常驻服务在应用退出后仍在运行,还与用户自己安装的 OpenCode 共用数据。这两种方式都不采用。

安装包里的内核由本仓库的 `kernel/` 构建,对内核的修改这样才能进入安装包。应用只用安装包里的内核,不用设置、环境变量或 `PATH` 指向的 `opencode`;内核缺失时报错,不引导用户另装 OpenCode。构建方法见 `DEVELOPMENT.md` 第 4 节。

一个项目的行为只由它自己和用户的全局设置决定。内核只从两处读配置:全局配置目录,以及会话所在的目录本身,即用户添加的项目文件夹或它的 worktree,「对话」则是它自己的聊天目录。上游还会从会话目录一路往上级目录查找配置,读 Claude Code 等其他应用的技能目录,接受配置里列出的外部技能与插件,以及远程下发的配置;这些 GeoCode 都不读,插件只来自应用自己的托管配置。这样,下载来的文件夹放在哪里、本机装了哪些别的 AI 工具,都不会改变 agent 的行为。「技能」等设置页也只在这两处读写。

## 3. 边界

GeoCode 是单机、单用户的桌面应用。让其他设备连进来的机制(局域网访问、设备配对、中转与公网隧道),连到本机内核以外主机的机制(远程实例、SSH、外部内核),以及不经用户操作就发往上游服务器的请求(更新检查、使用上报、推送),都关闭;连接模型服务是内核的正常工作,不在此列。OpenChamber 的网页版、VS Code 扩展、移动端与命令行不构建、不发布,用户只通过 GeoCode 的窗口使用它。

上游的其余功能按 `DESIGN.md` 第 3 节的原则取舍,落到具体功能上是两条:第三方代码与外部文件不能改变应用的行为,对话与凭据不在用户没有需要时交给第三方。所以用户不能自己往 GeoCode 里安装扩展与插件,GeoCode 不提供代码片段、Jev 与 Linear 集成,不读 OpenChamber 的企业策略,不读其他应用的登录凭据与其他 agent 工具的目录,也不采用项目里提交的团队共享设置(它会给应用加上在本机执行的命令);界面语言只提供英文、简体中文与繁体中文。与定位不冲突的功能照上游保留。

关闭不删源码:功能不启用、不显示,在它所在的地方关掉。壳服务端拒绝相应的接口,主进程拒绝相应的命令,界面隐藏入口、停掉自动发出的请求;界面的隐藏只是配合,拒绝发生在壳服务端与主进程。

## 4. 本机访问控制

只监听 127.0.0.1 挡不住本机:任何程序都连得上壳服务端,浏览器里的网页也能,因为 WebSocket 不受跨域限制,DNS 重绑定还能让网页以同源的身份发请求。能调用壳服务端,就能让 agent 以用户的身份执行命令、读写文件。所以要防的是浏览器里的网页、其他用户、沙箱内的程序与扫描本机端口的脚本;以用户身份运行、不受沙箱限制的程序本来就能修改用户的文件,不在此列。

壳服务端只认 GeoCode 自己的窗口。它运行在上游的口令模式下,口令每次启动随机生成,只在主进程的内存里,没有人输入它;主进程为窗口签发一个令牌,只存在于主进程与窗口的内存里,每次启动换新。设备令牌与会话重置的接口关闭,会话的签名密钥也每次启动随机生成,窗口以外没有取得令牌或会话的途径。另有两道防线:壳服务端只接受以 `127.0.0.1` 或 `localhost` 访问的请求,挡住 DNS 重绑定;内核的口令不留在壳的环境变量里,应用内的终端与其他子进程无法绕过壳直接访问内核。令牌失效时,界面提示重启应用,不出现登录页。

## 5. 环境变量

GeoCode 通过界面配置,不接受以环境变量给出的配置。用户环境里以 `OPENCODE_`、`OPENCHAMBER_`、`OTEL_`、`BUN_`、`ELECTRON_` 开头的变量是内核、壳与运行时的设置,能把配置与数据改到别处、从指定路径加载程序、把数据发往别处或打开调试功能;打包出的应用按前缀忽略它们,上游以后新增的同前缀变量也在内。其余变量是用户自己的环境,包括 `PATH`、语言、代理、证书与各种工具链的变量,照常交给内核、agent 执行的命令与终端:agent 调用 conda、GDAL、PROJ 这些地理工具,靠的就是它们。

代价是上游只能用环境变量调整的功能不再可用,例如内核的几个管理开关与 OpenTelemetry 遥测;OpenCode 自家模型服务的密钥改在服务商页填写。开发时的启动脚本正是用这些变量传参数,所以这条规则只在打包出的应用里生效。

# Google Earth Engine

GEE 能力域让 GeoAgent 用 Google Earth Engine 做遥感计算:模型写 Python 脚本,由 `geerun` 在内置环境里运行。`geerun` 替模型做好它自己做不好的几件事:长时间运行不被误杀,每次运行属于一个「任务」、耗时的结果存成资产供之后沿用,常见步骤有写对了的标准函数,等待与进度只给用户、事实只给模型,环境与登录由 GeoCode 管好。

框架(进程、通道、配置与状态)与地理工具的共同做法在 `GEOENGINE.md`,这里只写 GEE 自己的部分。

## 1. 定位

GeoAgent 用 earthengine-api 写 Python 脚本:脚本在本地搭出计算图,计算在 Earth Engine 的服务器上完成,结果以打印、资产、本地的影像或 Google Drive 里的文件交回。这样的脚本经 `shell` 也能运行,但有五件事模型自己做不好:

- 运行多久:服务器算几分钟时脚本毫无输出,超时设短了误杀正常的计算,设长了卡死的脚本也要等满(第 2.2 节)。
- 结果留在哪:每次重跑都从原始影像重算,换一个对话就不知道之前做过什么(第 2.3 节)。
- 常见的步骤:读研究区、合成、下载每次从头写,细节写错常常不报错,只是结果不对(第 2.4 节)。
- 信息给谁:等待、进度与脚本的打印混在一起进入模型的上下文,用户看不到进展,输出过长时截掉的可能正是结尾的报错(第 2.5 节)。
- 环境:模型自己找 Python、猜项目、写初始化,出错时分不清是缺包、没登录、项目不对还是网络不通(第 2.6 节)。

## 2. 核心设计

### 2.1 一次运行

一次调用一个进程:GeoEngine 用内置环境 `base` 的 Python 运行 GeoCode 的运行脚本,当前目录是会话目录,脚本结束它就退出,不常驻,也不复用。运行脚本先初始化 Earth Engine、读出任务里已有的东西,再执行 GeoAgent 的脚本,所以脚本里 `ee` 已经初始化,GEE 的函数可以直接导入。询问之前确认脚本文件存在时,项目外的脚本文件等它的目录获准访问之后再查,先查会透露文件在不在。

运行默认在前台。GeoAgent 也可以把它放到后台,做法与内核的 shell 命令一致:脚本开始执行时调用就返回,带着答复的开头(第 2.3 节的任务空间);运行结束时,答复的其余部分作为通知插进对话,并唤醒空闲的 GeoAgent。脚本开始之前就失败的(如任务被占用、初始化失败)照前台直接报错。前台的运行也能由用户中途移到后台。

用户停止后台运行时,对话收到它被停止的通知,通知里带着脚本停止前打印的内容。这一点有意与后台 shell 命令不同,后者被停止时什么输出都不交给模型:工具行给用户看了这些内容,GeoAgent 也该看得到。因应用或内核退出而停下的后台运行,内核再次启动时对话收到它因重启停止的通知,不唤醒 GeoAgent,也不重跑。无论怎样停下,已经提交的导出都在服务器上照常完成。

运行的生命周期(空闲时限、任务锁、Python 进程)只由 GeoEngine 管,内核只管谁在等这次运行、何时通知。等后台运行的服务是应用级的,不随某个工作目录被回收而关闭,所以通知不会丢。

### 2.2 不被误杀的运行

本地的 Python 只搭计算图、发请求、等结果,真正的等待都在向服务器要结果的那一刻:取值、提交与查询导出。这些请求都经同一个网络库发出,运行脚本守在这个出口上,有请求在等服务器回应就替脚本报活。所以运行时限按空闲计:脚本既没有输出、也没有在等服务器,持续一段时间才中止;服务器算得再久,脚本也不会因为没有输出被中止。替一个请求报活有上限,卡死的请求仍会被中止。

不设总时长:Earth Engine 的速度不稳定,固定的上限会误杀长的下载与导出;只看有没有输出也不行,服务器在算时脚本本来就一声不响。出口看不到的等待(分块下载、本地的计算),GeoCode 的函数以进度报活,模型自己写的代码要靠打印。

### 2.3 任务与资产

GEE 的工作常要好几天、跨几个对话,耗时的结果要留在云端接着用,就像人自己用 Earth Engine 时把中间结果存成资产再往下做。所以每次运行都属于一个任务。

一个任务是用户资产里的一个文件夹 `GeoCode/<任务名>/`,用户在 Code Editor 里一眼看得懂;GeoCode 只管这个文件夹,不碰其他资产。每次调用都指明任务,新建或继续:新建的名字已经被占用时拒绝,继续时写错的名字也拒绝,不会被当成新任务。任务名与资产名只用字母、数字、`_` 与 `-`,长度有上限:进行中的导出只在它的描述里写着「任务:资产:指纹」,而描述的长度有限。

文件夹在第一次存资产时才建,只查询的任务不在云端留下任何东西。还没有文件夹的任务只在建它的对话里认得:内核按对话记下建过的任务名,不记进项目的 `.geocode/`,因为那里常被提交进 git,不属于项目的对话也无处可放。一个任务同时只有一次运行,无论来自哪个对话:同一个任务的两次运行会抢着存同一个资产、互相取消对方的导出。不同的任务可以同时运行。

答复开头列出任务空间:已有的资产与它们的标题、说明,以及最近的其他任务。GeoAgent 不必另查就知道手头有什么,读这些也不耗计算配额。任务空间只写任务与资产的名字,不写完整路径:完整路径会诱使 GeoAgent 绕过 GEE 的函数直接存取,那样存下的资产没有说明与指纹。

脚本用 `gee.save` 把影像或表格存进任务,写上标题与说明,等导出完成再读回;`gee.load` 按名字读回本任务或其他任务的资产,也可以按完整路径读任何资产,写入则只经 `gee.save`。存一次,是用第一次运行的时间换之后每次的速度与配额,所以只存检查过、下游要反复用的结果和用户要留下的结果。删除在云端不可逆,GeoAgent 只在用户明确要求时删除任务与资产。

`gee.save` 按指纹判断内容变没变:没变就直接沿用,变了就替换原来的资产。指纹算进计算图读取的、`GeoCode` 文件夹里的资产的更新时间,因为上游的资产被替换后,读它的计算图本身并不变;公开数据集不算在内,它们几乎每天入库新影像,算进来的话,早已完成的合成也会显得变了。被停止的运行留下的导出,下一次同名的 `gee.save` 凭描述认得出来,内容相同就等它,不同就取消它。

### 2.4 GEE 的函数

GEE 的函数是 `geocodekit` 的子包 `gee`(`GEOCODEKIT.md`),只能在 `geerun` 里用,因为要运行脚本初始化好的 Earth Engine 与任务。处理函数以 geedim 为底,重在看清影像的覆盖与云况,避开写错也不报错的坑。核心链路是读研究区、取影像、合成、输出:

- `gee.region` 读本地矢量文件里的一个面作研究区。几何用原文件的坐标系建,并关掉测地线:GEE 在经纬度下默认把边当测地线,而 GIS 里的边是本坐标系中的直线,大范围的研究区边界会整体挪动几公里,不报错。旧椭球上的基准与 GEE 读不了的坐标系,照 QGIS 的做法换成经纬度再交给 GEE,因为 GEE 自己对旧基准的换算与 QGIS 差几米到几十米。
- `gee.images` 按拍摄汇总影像,给出研究区内的覆盖与无云比例:研究区跨图幅时,单景的数字既偏低又不能相加。
- `gee.composite` 合成后检查研究区内的空洞,分成没有影像与被云掩掉两类,覆盖不足时报错终止,并说明怎样补。合成本身没有固定的投影,GEE 会默认按很粗的经纬度像元算,所以每个波段挂上它在源数据里自己的网格。
- 输出有三处:`gee.download` 下载成本地的 GeoTIFF,`gee.to_drive` 导出到 Google Drive,`gee.save` 存进任务。三者都不收研究区,裁剪是单独的一步,用标准写法。一个文件只能有一套网格,默认用影像最细的那个波段的网格;没有边界或没有自己网格的影像,报错说明怎样改。

工具说明只列核心链路的函数(`GEOCODEKIT.md` 第 2.2 节)。

### 2.5 运行中的信息

信息按读者分开:运行中的状态给用户,事实给模型。模型在调用结束时得到一份答复:Python 的版本、任务空间、脚本的打印与报错,以及怎样结束。打印放不下时,先把连着重复的同一行合成一行,仍放不下再只留结尾,报错不会被截掉。报错的回溯只留经过脚本自己代码的部分:库内部的层对写脚本没有用;完整的回溯记进应用的日志。运行中的计时与进度对模型写脚本没有用,不给它;用户在工具行实时看到 GeoCode 的函数在做什么,或正在等服务器。

### 2.6 环境

GEE 只在内置环境的 `base` 里运行,不用 GeoAgent 的工作环境,也不支持用户自己的 Python。包的版本由锁定清单定下,GEE 的函数只需要对一个确定的版本核对;GeoAgent 往工作环境里装的包碰不到 GEE,运行因此总是确定的。代价是脚本只能用预装的包,要别的包的处理放到 `geerun` 之外去做。

Google Cloud 项目在设置里填,记在 `machine.json` 的 `gee` 块;项目 ID 只有用户知道,不猜;用户告诉 GeoAgent 之后,由它写进配置。登录用 Google 账号,只在设置里完成:GeoAgent 不发起登录,因为登录的命令要写明 `base` 的解释器。登录时,GeoEngine 启动的 Python 在本机回环地址上临时监听一个端口,等浏览器带回授权码,登录结束即关闭;本机的其他程序可以借这个端口提前结束登录,但伪造的授权码没有用,换取凭据要用只有这个 Python 持有的校验码。

凭据只认 earthengine-api 自己的那一份,位置固定在用户主目录下。检查与运行都从这个文件显式加载凭据,不像 earthengine-api 缺省那样退回 Google Cloud 的默认凭据(ADC):ADC 可以经环境变量指向一个服务账号,让 GEE 悄悄换一个身份;gcloud 登录得到的凭据常缺 Earth Engine 的授权范围。没有这个文件就是没登录,即使本机有 ADC。

检查把没登录、没有项目、项目不对、连不上等问题分开报告;远端的失败按异常的类型与服务器给的原因归类,不匹配报错的文字。没有就绪时,每次调用 `geerun` 都再检查一次,修好之后不必重启应用。给 GeoAgent 的提示写明缺什么、在哪里补:登录只有用户能在设置里完成,连不上与服务器忙只陈述事实。

项目本月的 Earth Engine 额度只给用户看,不给 GeoAgent,被问到时才查。

### 2.7 权限与界面

`geerun` 执行任意 Python,风险与 `shell` 相同,所以默认规则与 `shell` 相同:agent 本来就能经 `shell` 运行 Python,只问 `geerun` 守不住什么。它在设置里有自己的一行,规则与「始终允许」都按整个工具:脚本每次不同,按内容记住没有意义。询问卡片显示请求原因与脚本开头几行,不加警示:任意的 Python 靠扫描认不准。

标题栏有 GEE 的指示灯,未登录与缺项目不算故障:刚装好应用的用户就是未登录。放到后台的运行在界面上的一切表现都照后台的 shell 命令:哪里显示后台命令,哪里就同样显示它,判断它是否还在运行也用同一条规则。壳的目标与定时任务清理工作树时也等它,但不论它在哪一轮启动、跑了多久,都等到它结束,与内核的 `/goal` 一样;后台命令只等本轮启动、且没跑太久的,跑久了的多半是忘了关的服务器。它的工具行看实时的运行清单,而不是看有没有收到结束的通知:分叉出的对话复制了调用却收不到通知,否则会一直显示在运行;重载窗口或另开窗口也因此能恢复。

## 3. 边界与约束

- GeoCode 只在用户资产的 `GeoCode/` 文件夹里存取,不碰其他资产;删除只在用户明确要求时做。
- 只用 Earth Engine 自己的凭据,不退回 ADC,不支持服务账号。
- 只在 `base` 里运行;`geocodekit.gee` 在 `geerun` 之外导入即报错。

## 4. 与其他部分的关系

- 内核:`geerun` 是内核的内置工具,负责参数、权限、后台运行与通知、交给模型的答复。
- GeoEngine:GEE 是它的一个能力模块,有配置块与状态,管运行的生命周期与任务锁(`GEOENGINE.md`)。
- 内置的 Python 环境:GEE 只在它的 `base` 里运行(`PYTHON.md`)。
- GeoCode 的 Python 包:GEE 的函数在它的子包 `gee` 里(`GEOCODEKIT.md`)。

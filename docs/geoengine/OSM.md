# OpenStreetMap

OpenStreetMap 能力域让 GeoAgent 从 OpenStreetMap(OSM)取回干净的矢量数据:按名字找到地物,查看一片区域里有什么、有多少,再把边界或一类要素下载成文件。数据来自社区捐赠的公共服务,所以 GeoCode 礼貌地使用它们:先探路再提问,不把同一个查询交给几个服务器,满载的暂停,查看与下载排队。下载的数据不丢、几何正确、属性整洁,数据多时自己分批,停下时不留半截文件。

框架(进程、通道、配置与状态)与地理工具的共同做法在 `GEOENGINE.md`,这里只写 OSM 自己的部分。

## 1. 定位与范围

OSM 能力域只负责把数据干净地取回来。裁剪、投影、改字段名、换格式、由道路建路网这些处理,由 GeoAgent 用 QGIS 或 Python 去做:它们本来就做得到,放进下载工具只会让工具越来越重,还替用户做了未必想要的决定。

| 工具 | 做什么 | 权限 |
|---|---|---|
| `osmsearch` | 按名字找 OSM 对象,给出 id、类别与位置 | 默认放行 |
| `osmprobe` | 查看一片区域:日常说法对应的标签写法、各种标签的数量、几个键的取值分布 | 默认放行 |
| `osmgetobjects` | 按 id 下载对象,如校园、湖泊与行政区的边界 | 第 8 节 |
| `osmgetfeatures` | 按范围与标签下载一类要素,如道路、建筑、POI | 第 8 节 |

工作的顺序是先定研究区与内容,看清有什么、有多少,再下载,最后由 GeoAgent 用 `readgeodata` 检查结果。每个工具独立完成自己那一步:结果落成文件,答复只陈述拿到了什么、缺了什么,不把数据本身交给模型。

范围是在线的公共服务承担得了的下载:一个地物、研究区里的一类要素、一套基础数据的各个主题。省级以上的大范围数据(如一个省的全部建筑)超出了公共服务的承受能力,不在其中。

路网不单独做成一种产出,按范围下载的道路线就是它的原料。QGIS 的网络分析把坐标重合的顶点合并成图的节点,所以 OSM 里在路口共用的节点被连起来,不共用节点的立交不会被误连。下载为此守住三条:坐标原样写出,不简化、不降精度;道路单独成一个图层;能按需留下单行、限速这类建网要用的标签。

## 2. 执行

工具在内置 Python 环境的 `base` 里执行(`PYTHON.md`),由 GeoCode 的 Python 包的子包 `osm` 完成(`GEOCODEKIT.md`),一次调用一个进程。放在 Python 里,是因为内置环境已经照全应用的代理规则联网,不必另做,而 GeoEngine 用的 Node 不读代理;几何的运算交给 shapely,写 GeoPackage 交给 GDAL,都是现成的实现。

OSM 没有要配置与检查的东西:服务是公共的,环境是内置的。所以它不登记状态,没有指示灯,也不在「地理环境」设置页里;一个指示灯只能说「公共服务此刻不顺」,用户既无从修,也不必修。工具调用时等内置环境就绪,服务答不上就在答复里如实说明。

请求与几何的装配由 GeoCode 自己写,不以 osmnx 为底:它的下载层替换整个进程的域名解析、对同一个服务器无限地重试、只认一个服务器、对不完整的结果只记日志、默认把缓存写进当前目录,要改就得替换它的私有函数;它还连带装上一批用不到的依赖。

标签的写法取自 OSM 编辑器 iD 的预设库 `id-tagging-schema`(社区维护):它记着每类东西靠哪些标签认出、新建时一并加哪些标签、哪些属性值得记录,以及英文的名称与同义词,另有弃用标签与新写法的对照。只带英文:GeoAgent 用英语工作,把用户的说法转成英文不难。一条首尾相接的线算不算面,照另一份社区维护的规则 `osm-polygon-features`。两者都锁定一个版本,随包分发,用到时不联网;它们的许可证声明随其他第三方的一起放在发布仓库(`DESKTOP.md` 第 7 节)。地名不在此列,按当地语言检索(第 4 节)。

## 3. 公共服务

| 服务 | 用途 |
|---|---|
| Overpass | 下载与计数要素;在一个区域里按名字匹配,或列出一类对象;按 `wikidata` 标签取回对象 |
| Nominatim | 按名字检索地物;补全候选所在的地方;按 id 取对象的几何与标签 |
| Photon | 按名字检索地物 |
| Wikidata | 检索有名的地物的别名、正式名与各语言的名字,以及一句说明 |

Overpass 有几个公共实例,GeoCode 只问免费、覆盖全球、不用注册的几个。一个实例此刻接不接得下请求,事先无从知道,只有真实的请求看得出来;让请求干等的实例,要等满查询的时限才看得出来,一个个试下去就耗掉一次调用的大半。所以查看与下载问 Overpass 之前先探路:同时向每个可问的实例发一个只取一个节点的查询,声明的时限与下载的相同,因为服务器按查询声明的时限决定接不接,声明得短的探路在满载时也接得下,接下来的下载却会被挡回。答上了、数据也不太旧的实例,才交给它真正的查询;一次调用里刚答上查询的先用,其次是探路最先答上的,答得快说明它此刻有空。真正的查询不同时交给几个实例、谁先答用谁:没被用上的实例照样把查询算完,白占社区捐赠的服务器。

真正的查询失败时,交给另一个答上的实例,一个也不剩时再探路。答以满载、答到一半断开或探路时没有答上的实例,照官方的使用政策暂停一阵再问:满载的服务器过几分钟常常就空出来了,问得更勤只会添它的负担。暂停由 GeoEngine 记住,交给之后的调用:政策算的是这台电脑发出的请求,每次调用却是一个新进程。连不上的、答以不成结构的东西的、数据旧的,与让真正的查询一直等着的实例,这次调用里不再问:数据旧的仍然是旧的,一直等着的再问一次又要等那么久。数据旧的实例照常回答、不报错,只有答复里的数据时间看得出来。

查询本身写错时不换实例,把服务器说的原因交回。服务器以正常的结果说明它中途停下了(超时、内存不够)时,这一次算作不完整,服务器的原话随之交回:「超时」与「查询太宽」要求的是相反的改法。响应边收边计大小,超过上限就停止。

公共的 Overpass 按 IP 分配名额,一个查询占着名额直到跑完;官方的政策也不许并行的脚本。所以查看与下载在 GeoEngine 里排成一队,一次只运行一个;一次调用里,几个实例可以同时各做一件事,每个实例一次一件,所以一次调用自己就用得上所有有空的实例。检索不排队(第 4 节)。

这些都是社区捐赠、免费给所有人用的服务,GeoCode 照各自的使用政策使用:

- 请求的 User-Agent 写明 GeoCode、它的版本与发布仓库的地址。各家都要求标明来自哪个应用。
- User-Agent 与请求里都不带用户或安装的标识。Nominatim 的上限按应用计算,所有用户加在一起,分开标识减少不了总量;一个固定的安装标识还会让第三方把同一个用户长期的检索串起来。
- 按顺序、限速地发,Nominatim 每秒至多一次,整个应用的调用一起算:每次请求之前在状态目录的一个锁文件里看过、记下上一次请求的时刻(`PATHS.md`)。

服务的地址写死在代码里,不做配置。Nominatim 的政策要求服务方提出时,应用不更新软件就能换用别的服务,GeoCode 不满足这一条,被要求更换或被封时靠发新版解决;检索综合几个服务,少了任何一个只是变差,不会失效。答复与文件的说明不提数据来自哪个服务(`GEOENGINE.md` 第 3.5 节)。检索的名字与下载的范围交给这几个服务的运营者,这是用户要用的功能,不属于应用不发的那类后台请求(`DESKTOP.md` 第 1 节)。

OSM 的数据按 ODbL 许可提供,要求署名「© OpenStreetMap contributors」,下载的文件里写着它(第 7 节)。「OpenStreetMap」与「OSM」可以用来命名处理 OSM 数据的工具,也可以为署名而写出;工具行的图标用 OSM 的放大镜标志,OSM 基金会的商标声明随许可证声明一起处理。

## 4. 检索

`osmsearch` 一次检索一个名字。名字优先用当地语言的正式名:OSM 的 `name` 写的是当地的名字,大陆与台湾的地物多半没有英文名。简称与俗称哪个服务都对不上,由 GeoAgent 先展开成全称。可选的上下文说明这个地方在哪里,用来区分同名的地方:写城市,不写区与更小的地方,因为筛选按外包框,区写错或写小了,要找的对象会被当作离得远而去掉。可选的类别是一个标签过滤,只留下符合它的对象。

检索分两段。第一段找候选:几个服务并行,各自只交出 OSM 对象与命中的依据;Wikidata 找到的条目经 OSM 对象的 `wikidata` 标签接回 OSM;Overpass 只在给了上下文时,在那个区域里按名字匹配,不在全球扫描。第二段统一补全:所有候选一起由 Nominatim 补上名字、标签、外包框与所在的地方,再补上 Wikidata 的说明。各服务描述同一个对象的方式各不相同,按谁找到就用谁的描述拼起来,模型无从比较候选;统一补全之后,每个候选都有同样的字段、同样的写法。补全的服务没有回答时,答复写明结果可能不全,而不说没有这个地方。

几个服务互相补位:Nominatim 按地址理解输入,索引各语言的名字,简繁不同也对得上;Photon 对得上只给出一部分、或中间多了字的名字;Wikidata 记着有名的地物的别名与正式名;没上 Wikidata 的普通地物,靠 Overpass 在区域里逐字匹配。检索里 Overpass 的部分是可有可无的补充:不探路,只问不多的几个没在暂停的实例,从上一次答上的那个开始,答不上就算这部分没有完成。公共的 Overpass 常常满载,检索不该为它等上几分钟,也不该排在几分钟的下载后面。

排序综合几项打分,名字与输入有多像占的分量最重,其次是几个服务都找到它:名字逐字比较看不出简体与繁体是同一个名字,几个服务都找到它正好补上。再看重要度、它是否连着 Wikidata 的条目,面先于线与点;与地物同名的车站与地名点降分,它们在地名检索里数量多,几乎总是噪音。没找到符合的对象、而上下文找到了时,列出那个区域里这一类有名字的对象。

答复里每个候选的类别写成过滤条件的写法,照抄就能用于查看与下载。iD 对同一种东西另有旧写法的预设时,对象带着旧写法就写旧写法:OSM 里多数数据只带旧写法,模型照抄去下载,用新写法会漏掉大半。所在的地方取 Nominatim 结构化地址里现成的字段,不从完整地名里推,因为那要依赖它的输出格式。给了类别时,名字对上而类别不符的对象不算找到,答复也不能说没有叫这个名字的对象;检索有一部分没有完成时,没找到要说对象可能仍然存在。答复不写候选是谁找到的,排序本身就体现了可信的程度。

## 5. 范围与标签

`osmprobe` 与 `osmgetfeatures` 以同一种写法给出范围:检索得到的面状对象的 id(几个取并集,如一所学校的几个校区)、外包框、某点周围多少米、某些对象连同向外多远的一圈(即它们的缓冲区,距离在以对象为中心的等距投影里量),或本地边界文件里的面(任何坐标系都由工具转成经纬度)。坐标一律纬度在前,与 Overpass 和检索答复里的中心点一致,模型不必在两种顺序之间切换。写错的范围在查询要素之前报错,并说明正确的写法。

范围里的 id 先向 Nominatim 取几何,与探路同时进行:它一秒左右就答,不占 Overpass 的名额,带洞的面照样有洞,大的边界也不化简。Nominatim 没有的对象,与它只给出一个点的关系,再问 Overpass。

边界交给服务器之前可能要化简:顶点太多时换成凸包,仍太多或由很多块分开的面组成时换成外包框;后者对相隔很远的几处多出的部分可能远大于范围本身,所以给模型的说明请它分开查看、分开下载。化简只能向外,下载之后再按真实的边界收回,洞里的要素不属于范围:多下载的部分事后收得回,少下载的部分永远发现不了。与边界相交的要素整个保留,不在边界处切开,切开是 GeoAgent 的处理。

标签是一组写法的并集,写法与 Overpass 相同:有某个值、有某个键、值符合或不符合某个正则,几个条件各放进方括号连写时要同时满足。「不符合」用于「所有 POI,但不要长椅与垃圾桶」这类要求;方括号用于 iD 的预设里由两个标签合成的类别。`osmprobe` 答复里的写法可以原样用于下载。

## 6. 查看

`osmprobe` 在一个范围里回答三种问题,每次问一种:一个日常说法(英文)对应哪些标签写法、各有多少;一组标签各有多少、合起来有多少;几个键在这里各有哪些值、各有多少(要素太多时取样本并写明)。

第一种是下载时标签的来源。OSM 里同一类东西常有几种写法:医院有 `amenity=hospital` 与 `healthcare=hospital`,水库有 `natural=water` 加 `water=reservoir` 与 `landuse=reservoir`,只写一种会静默地漏掉一大块。写法取自社区的约定,而不是模型的记忆:在预设库里匹配名称与同义词,对每个预设的写法、新建时一并加的标签与弃用的写法各数一数;配上研究区里的实际数量,由 GeoAgent 决定要哪几种。同义词匹配得宽(医院的同义词里有诊所),所以数量与取舍必须摆在一起看。

下载之前不必先查看,数量多时由下载自己分批(第 7 节)。查看用来选标签,也让用户知道数据的量级。数量是在交给服务器的范围里数的,不按真实的边界收回,范围化简过或带洞时偏多。服务器中途停下时,已经数出的照常给出,没来得及数的写法另外列出,不当作这里没有。

## 7. 下载

`osmgetobjects` 按 id 下载对象,几何随结果一次取回,不逐个取回再拼接:后者在大的关系上会静默地拼出残缺的边界。Overpass 问不下来时,先写出 Nominatim 有的对象,它们的标签可能少几个,数据只比 OSM 晚几分钟;其余的照常等 Overpass。`osmgetfeatures` 按范围与标签下载一类要素,几何可以原样,也可以把每个要素塌缩成一个代表点,并记下它原来是点、线还是面。POI 要用代表点,而不是只取点类型的要素:大量设施以面测绘,只取点会静默地丢掉它们,丢的往往是多数。

一次调用下载一个主题。一套基础数据(道路、水系、建筑)分几次调用,各写一个文件:一个主题失败不牵连别的,每次调用的参数、询问卡片与答复都只关于一类数据。要合进一个文件时由 GeoAgent 处理。

数据多时,下载自己分批:先数一数,多了就把范围的外包框分成四块再数,仍多的再分,直到每块都是一次请求下得了的。各块的计数与下载分给探路答上的几个实例同时做,一个实例不行了,它手上的块交给别的;跨块的要素按 id 只留一份。一块在服务器上没下全时,再分成四块重下,分到一定深度仍下不全的记为缺失。多到在线下载承担不了时不下载,答复写明大约有多少与上限是多少。GeoAgent 因此不必管容量,也不必自己按数量拆分范围。

下载不设总时限:数据多、服务器慢时要很久,只要还在动就等,连续一段时间没有进展才停下。收到数据、一块下完、进入下一步算进展;探路、换实例、实例答以满载、等待时的报活不算,否则一直答以满载的实例会让下载永远挂着。排队等前一个查看或下载的时间也不算:那段时间它还没有开始问。这个门槛要比 Overpass 一次查询在服务器上的时限长,那段时间里服务器可能一个字节也不发。

下载的数据要干净:

- 不丢:范围的放宽与收回见第 5 节;服务器说不完整的,这一次算作不完整;部分失败时写出已经拿到的部分,并写明缺了哪些。
- 几何正确:多面的外环与内环装配正确,装配不出的对象不交出、写明缺了它;几何不简化,坐标不降精度;一个图层只有一种几何;坐标系为经纬度(EPSG:4326)。
- 属性整洁:每个要素有带着类型的 `osm_id`、`name` 与预设认出的类别;另外留下查询用到的键、预设库认为这类东西值得记录的属性,以及调用时点名要的键,要全部标签时另存进一列。各要素自己的预设推荐的键,只在有足够多的要素带着时才留:道路因此留下单行、限速、车道与路面,而校园里唯一一栋兼作餐厅的建筑,不会让所有建筑都多一列菜系。OSM 的元数据(编辑者、版本等)不当作标签。标签的值原样写出,不做解读:`maxspeed=CN:urban` 不换成数字。
- 不重、不覆盖:多个范围与分批之间按 id 去重;输出撞名时编号(`CONVENTIONS.md` 第 2 节)。

产出只有 GeoPackage:一个文件里点、线、面各一个图层,只有一种几何时只有那一个图层。GeoJSON 一个文件放不下几种几何,Shapefile 的字段名限 10 个字符;GeoPackage 在常用的 GIS 软件与库里都能直接打开,要别的格式时由 GeoAgent 转换。字段名照 OSM 的原样,如 `addr:street`、`name:en`。每个图层的说明写着署名、OSM 数据库的时间与下载了什么,不完整时注明缺了什么:文件过后被单独打开时不会显得是完整的,论文引用数据时也有依据。

输出的文件夹写不进时,在下载之前就报错,不让用户等完一次注定写不出的下载。一个要素都没有时不写文件。文件先写在一个临时的名字下,写完才改成正式的名字;失败、停下或被用户停止时,已经下完的几批也丢弃,不留半截文件:一份下了一半、又看不出缺了哪里的文件不干净。

答复写明写出的路径、每个图层的要素数、OSM 数据库的时间、保留了哪些字段、丢弃了哪些键与各有多少要素带着它,以及缺了什么。

## 8. 权限

在共同做法(`GEOENGINE.md` 第 3.6 节)之外:

- `osmsearch` 与 `osmprobe` 只读,默认放行。范围是本地的边界文件时不按 `read` 询问:GeoAgent 没有读到文件的内容,工具只把它当作范围,而 GeoAgent 多半已经用 `readgeodata` 读过它。
- 两个下载工具只新建文件,不覆盖已有的数据,所以不需要 `qgisrun` 那样的算法名单;写到项目外时问,判断与记住都同 `qgisrun`(`QGIS.md` 第 4 节)。下载不经上游访问项目外目录的询问,免得那条规则改成询问后一次下载弹两张卡。
- 询问之前拦下的,只查参数的个数、名字不空、输出的位置与边界文件在不在;范围与标签的写法要到调用开始时才查,因为读一个范围常要先问 OSM 的服务。

## 9. 界面

四个工具在对话里每次调用一行,不合并相邻的调用:检索与查看一般只有一两次,每次的结果也要单独看。检索与查看的行以工具名为标题,点开是候选的列表或数量的横条;下载的行以用途为标题,运行中写当前的步骤与分批的进度,排在前一个后面时写着在排队,完成后写出写入的要素数。

服务器计算查询时什么也不发,或者只发出答复的开头,算完才一起发出,收到了多少反映不了进度:答复还没开始传来时,行上写服务器正在查询与已等多久,不写收到的字节。服务器满载、一段时间没有进展时也写出来。

说给用户的话用界面语言:下载的步骤是固定的,结果与失败都是结构化的,界面能自己翻译;服务器的原话、请求写错时的具体原因与系统说的写不进的原因翻译不了,保留原文。询问卡片把范围翻成一句话,编号旁写这个会话里之前检索到的名字:只写一串编号,用户认不出是哪里。

## 10. 与其他部分的关系

- GeoEngine:OSM 是它的一个能力模块,没有配置块与状态;查看与下载的排队与实例的暂停由它记住(`GEOENGINE.md`)。
- 内置的 Python 环境与 GeoCode 的 Python 包:工具在 `base` 里运行,由包的子包 `osm` 完成(`PYTHON.md`、`GEOCODEKIT.md`)。
- QGIS:下载的结果由 GeoAgent 用 `readgeodata` 检查,后续处理(裁剪、投影、建路网)交给 QGIS 或 Python(`QGIS.md`)。

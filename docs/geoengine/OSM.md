# OpenStreetMap

OpenStreetMap 能力域让 GeoAgent 从 OpenStreetMap(OSM)取回干净的矢量数据:按名字找到地物,查看一片区域里有什么、有多少,再把边界或一类要素下载成文件。数据来自社区捐赠的公共服务,所以 GeoCode 礼貌地使用它们:先探路再提问,不把同一个查询交给几个服务器,满载的暂停,查看与下载排队。下载的数据不丢、几何正确、属性整洁,数据多时自己分批,停下时不留半截文件。

框架(进程、通道、配置与状态)与地理工具的共同做法在 `GEOENGINE.md`,这里只写 OSM 自己的部分。

## 1. 定位

| 工具 | 做什么 |
|---|---|
| `osmsearch` | 按名字找 OSM 对象,给出 id、类别与位置 |
| `osmprobe` | 查看一片区域:日常说法对应的标签写法、各种标签的数量、几个键的取值分布 |
| `osmgetobjects` | 按 id 下载对象,如校园、湖泊与行政区的边界 |
| `osmgetfeatures` | 按范围与标签下载一类要素,如道路、建筑、POI |

OSM 能力域只负责把数据干净地取回来。裁剪、投影、改字段名、换格式、由道路建路网这些处理,由 GeoAgent 用 QGIS 或 Python 去做:它们本来就做得到,放进下载工具只会让工具越来越重,还替用户做了未必想要的决定。工作的顺序是先定研究区与内容,看清有什么、有多少,再下载,最后由 GeoAgent 用 `readgeodata` 检查结果。每个工具独立完成自己那一步:结果落成文件,答复只陈述拿到了什么、缺了什么,不把数据本身交给模型。

范围是在线的公共服务承担得了的下载:一个地物、研究区里的一类要素、一套基础数据的各个主题。省级以上的大范围数据(如一个省的全部建筑)超出了公共服务的承受能力,不在其中。

路网不单独做成一种产出,按范围下载的道路线就是它的原料。QGIS 的网络分析把坐标重合的顶点合并成图的节点,所以 OSM 里在路口共用的节点被连起来,不共用节点的立交不会被误连。下载为此守住三条:坐标原样写出,不简化、不降精度;道路单独成一个图层;能按需留下单行、限速这类建网要用的标签。

## 2. 核心设计

### 2.1 执行

工具在内置 Python 环境的 `base` 里执行,由 `geocodekit` 的子包 `osm` 完成,一次调用一个进程。放在 Python 里,是因为内置环境已经照全应用的代理规则联网,而 GeoEngine 用的 Node 不读代理;几何的运算与写 GeoPackage 也都有现成的实现。

OSM 没有要配置与检查的东西:服务是公共的,环境是内置的。所以它不登记状态,没有指示灯;一个指示灯只能说「公共服务此刻不顺」,用户既无从修,也不必修。服务答不上就在答复里如实说明。

请求与几何的装配由 GeoCode 自己写,不以 osmnx 为底:它的下载层替换整个进程的域名解析、对同一个服务器无限地重试、只认一个服务器、对不完整的结果只记日志,要改就得替换它的私有函数。

标签的写法取自 OSM 编辑器 iD 的预设库 `id-tagging-schema`(社区维护):它记着每类东西靠哪些标签认出、新建时一并加哪些标签、哪些属性值得记录,以及名称与同义词。只带英文:GeoAgent 用英语工作,把用户的说法转成英文不难。一条首尾相接的线算不算面,照另一份社区维护的规则。两者都锁定一个版本,随包分发,用到时不联网;许可证见 `DESKTOP.md` 第 2.6 节。

### 2.2 公共服务

| 服务 | 用途 |
|---|---|
| Overpass | 下载与计数要素;在一个区域里按名字匹配 |
| Nominatim | 按名字检索地物;补全候选;按 id 取对象的几何与标签 |
| Photon | 按名字检索地物 |
| Wikidata | 检索有名的地物的别名与正式名,以及一句说明 |

Overpass 有几个免费、覆盖全球、不用注册的公共实例。一个实例此刻接不接得下请求,事先无从知道;让请求干等的实例,要等满查询的时限才看得出来,一个个试下去就耗掉一次调用的大半。所以查看与下载问 Overpass 之前先探路:同时向每个可问的实例发一个极小的查询,答上了、数据也不太旧的,才交给它真正的查询。探路声明的时限与下载的相同:服务器按查询声明的时限决定接不接,声明得短的探路在满载时也接得下,接下来的下载却会被挡回。真正的查询不同时交给几个实例、谁先答用谁:没被用上的实例照样把查询算完,白占社区捐赠的服务器。

满载的实例,照官方的使用政策暂停一阵再问,问得更勤只会添它的负担;暂停由 GeoEngine 记住,交给之后的调用:政策算的是这台电脑发出的请求,每次调用却是一个新进程。连不上、答非所问、数据旧的实例,这次调用里不再问;数据旧的实例照常回答、不报错,只有答复里的数据时间看得出来。查询本身写错时不换实例,把服务器说的原因交回;服务器说它中途停下了时,这一次算作不完整,服务器的原话随之交回:「超时」与「查询太宽」要求的是相反的改法。

公共的 Overpass 按 IP 分配名额,一个查询占着名额直到跑完;官方的政策也不许并行的脚本。所以查看与下载在 GeoEngine 里排成一队,一次只运行一个;一次调用里,几个实例可以同时各做一件事,所以一次调用自己就用得上所有有空的实例。检索不排队(第 2.3 节)。

这些都是社区捐赠、免费给所有人用的服务,GeoCode 照各自的使用政策使用:

- 请求写明来自 GeoCode、它的版本与仓库的地址:各家都要求标明来自哪个应用。
- 请求里不带用户或安装的标识。Nominatim 的上限按应用计算,分开标识减少不了总量;一个固定的安装标识还会让第三方把同一个用户长期的检索串起来。
- Nominatim 每秒至多一次,整个应用的调用一起算。

服务的地址写死在代码里,不做配置。Nominatim 的政策要求服务方提出时,应用不更新软件就能换用别的服务,GeoCode 不满足这一条,被要求更换或被封时靠发新版解决;检索综合几个服务,少了任何一个只是变差,不会失效。检索的名字与下载的范围交给这几个服务的运营者,这是用户要用的功能,不属于应用不发的那类后台请求(`DESKTOP.md` 第 1 节)。

OSM 的数据按 ODbL 许可提供,要求署名「© OpenStreetMap contributors」,下载的文件里写着它。「OpenStreetMap」与「OSM」可以用来命名处理 OSM 数据的工具,也可以为署名而写出。

### 2.3 检索

`osmsearch` 一次检索一个名字。名字优先用当地语言的正式名:OSM 的 `name` 写的是当地的名字,大陆与台湾的地物多半没有英文名。简称与俗称哪个服务都对不上,由 GeoAgent 先展开成全称。可选的上下文写城市,不写区与更小的地方:筛选按外包框,区写错或写小了,要找的对象会被当作离得远而去掉。

检索分两段。第一段几个服务并行找候选,各自只交出 OSM 对象;第二段所有候选一起由 Nominatim 统一补全名字、标签与所在的地方。各服务描述同一个对象的方式各不相同,按谁找到就用谁的描述拼起来,模型无从比较候选;统一补全之后,每个候选都有同样的字段、同样的写法。几个服务互相补位,各自对得上别的服务对不上的说法。检索里 Overpass 的部分只是补充,不探路、不排队,从 GeoEngine 记下的上一次答上的实例问起,答不上就算这部分没有完成:公共的 Overpass 常常满载,检索不该为它等上几分钟。

排序时名字与输入有多像占的分量最重,其次是几个服务都找到它:名字逐字比较看不出简体与繁体是同一个名字,几个服务都找到它正好补上。与地物同名的车站与地名点降分,它们几乎总是噪音。答复不写候选是谁找到的,排序本身就体现了可信的程度。

答复里每个候选的类别写成过滤条件的写法,照抄就能用于查看与下载。对象带着旧写法的标签时就写旧写法:OSM 里多数数据只带旧写法,模型照抄新写法去下载会漏掉大半。检索有一部分没有完成、或补全的服务没有回答时,答复写明结果可能不全,没找到要说对象可能仍然存在,而不说没有这个地方。

### 2.4 范围与标签

`osmprobe` 与 `osmgetfeatures` 以同一种写法给出范围,可以是检索得到的对象、外包框、缓冲区或本地边界文件里的面。坐标一律纬度在前,与 Overpass 和检索答复里的中心点一致,模型不必在两种顺序之间切换。

范围里的对象先向 Nominatim 取几何:它答得快,不占 Overpass 的名额,带洞的面照样有洞。边界交给服务器之前可能要化简,化简只能向外,下载之后再按真实的边界收回,洞里的要素不属于范围:多下载的部分事后收得回,少下载的部分永远发现不了。与边界相交的要素整个保留,不在边界处切开,切开是 GeoAgent 的处理。

标签是一组写法的并集,写法与 Overpass 相同,能表达「所有 POI,但不要长椅与垃圾桶」这类要求。`osmprobe` 答复里的写法可以原样用于下载。

### 2.5 查看

`osmprobe` 在一个范围里回答三种问题,每次问一种:一个日常说法(英文)对应哪些标签写法、各有多少;一组标签各有多少;几个键在这里各有哪些值。

第一种是下载时标签的来源。OSM 里同一类东西常有几种写法:医院有 `amenity=hospital` 与 `healthcare=hospital`,只写一种会静默地漏掉一大块。写法取自社区的预设库,而不是模型的记忆;配上研究区里的实际数量,由 GeoAgent 决定要哪几种。同义词匹配得宽(医院的同义词里有诊所),所以数量与取舍必须摆在一起看。

下载之前不必先查看,数量多时由下载自己分批。数量是在交给服务器的范围里数的,范围化简过或带洞时偏多。服务器中途停下时,已经数出的照常给出,没来得及数的另外列出,不当作这里没有。

### 2.6 下载

`osmgetobjects` 按 id 下载对象,几何随结果一次取回,不逐个取回再拼接:后者在大的关系上会静默地拼出残缺的边界。Overpass 问不下来的对象改取 Nominatim 的,它们的标签可能少几个,数据只比 OSM 晚几分钟;两边都没有的写明缺了。`osmgetfeatures` 下载一类要素,POI 要塌缩成代表点,而不是只取点类型的要素:大量设施以面测绘,只取点会静默地丢掉它们,丢的往往是多数。

一次调用下载一个主题。一套基础数据(道路、水系、建筑)分几次调用,各写一个文件:一个主题失败不牵连别的,每次调用的参数、询问卡片与答复都只关于一类数据。

数据多时,下载自己分批:多了就把范围分成几块,直到每块都是一次请求下得了的,各块分给有空的几个实例同时做。多到在线下载承担不了时不下载,答复写明大约有多少与上限是多少。GeoAgent 因此不必管容量,也不必自己拆分范围。

查看有几分钟的总时限,排队的时间也算在内:查看是为下一步做决定,不值得长等。下载不设总时限,只要还在动就等,连续一段时间没有进展才停下。探路、换实例、实例答以满载都不算进展,否则一直满载的实例会让下载永远挂着;排队的时间也不算,那时它还没有开始问。这个门槛要比 Overpass 一次查询在服务器上的时限长,那段时间里服务器可能一个字节也不发。

下载的数据要干净:

- 不丢:服务器说不完整的,这一次算作不完整;部分失败时写出已经拿到的部分,并写明缺了哪些。
- 几何正确:多面的内外环装配正确,装配不出的对象写明缺了它;几何不简化,坐标不降精度;一个图层只有一种几何;坐标系为经纬度。
- 属性整洁:留下认得出要素的、查询用到的与调用时点名要的键。一个要素自己的预设推荐的键,只在有足够多的要素带着时才留:道路因此留下单行与限速,而唯一一栋兼作餐厅的建筑,不会让所有建筑都多一列菜系。标签的值原样写出,不做解读。
- 不重、不覆盖:按 id 去重;输出撞名时编号(`CONVENTIONS.md` 第 2 节)。

产出只有 GeoPackage:GeoJSON 一个文件放不下几种几何,Shapefile 的字段名限 10 个字符;要别的格式时由 GeoAgent 转换。字段名照 OSM 的原样。每个图层的说明写着署名、OSM 数据库的时间、下载了什么与缺了什么:文件过后被单独打开时不会显得是完整的,论文引用数据时也有依据。

输出的文件夹写不进时,在下载之前就报错。一个要素都没有时不写文件。文件写完才改成正式的名字;整次调用失败、停下或被用户停止时,已经下完的几批也丢弃,不留半截文件。例外是按 id 下载时 Overpass 问不下来、而 Nominatim 给出了一部分:这算部分失败,照样写出,并写明缺了哪些。

### 2.7 权限

在共同做法(`GEOENGINE.md` 第 2.8 节)之外:

- 四个工具在设置里共用一行:检索、查看与下载是同一件事的几步,分开设置没有意义。询问与「始终允许」仍按各自的工具。
- `osmsearch` 与 `osmprobe` 只读,默认放行。范围是本地的边界文件时不按 `read` 询问,在项目外也不问:模型没有读到文件的内容,工具只把它当作范围。
- 两个下载工具只新建文件,不覆盖已有的数据,所以不需要 `qgisrun` 那样的算法名单;写到项目外时询问,按目录记住,同 `qgisrun`(`QGIS.md` 第 2.3 节)。
- 询问之前只查参数本身与输出的位置;范围与标签的写法要到调用开始时才查,因为读一个范围常要先问 OSM 的服务。

### 2.8 界面

每次调用在对话里一行,不合并相邻的调用:检索与查看一般只有一两次,每次的结果也要单独看。服务器计算查询时什么也不发,收到了多少反映不了进度,所以等待时写服务器正在查询与已等多久,不写收到的字节。说给用户的话用界面语言,服务器的原话保留原文。询问卡片把范围翻成一句话,编号旁写这个会话里之前检索到的名字:只写一串编号,用户认不出是哪里。

## 3. 边界与约束

- 只取数据,不做处理;不支持省级以上的大范围下载。
- 只用免费的公共服务,照它们的使用政策限速、排队,不带用户的标识。
- 服务的地址写死在代码里,不做配置。

## 4. 与其他部分的关系

- GeoEngine:OSM 是它的一个能力模块;查看与下载的排队、实例的暂停由它记住(`GEOENGINE.md`)。
- 内置的 Python 环境与 GeoCode 的 Python 包:工具在 `base` 里运行,由包的子包 `osm` 完成(`PYTHON.md`、`GEOCODEKIT.md`)。
- QGIS:下载的结果由 GeoAgent 用 `readgeodata` 检查,后续处理交给 QGIS 或 Python(`QGIS.md`)。

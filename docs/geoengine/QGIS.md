# QGIS

QGIS 能力域让 GeoAgent 用用户安装的 QGIS 读取地理数据、查阅与执行空间处理算法。最关键的几个决定:一切都在 QGIS 自带的 Python 里运行,环境采用 QGIS 自己的组装方式;不按版本号判断能不能用,由检查与执行说明问题;执行之前先检查数据、定下输出,用户批准的就是将要执行的;输出永不覆盖已有的数据。

框架(进程、通道、配置与状态)与地理工具的共同做法在 `GEOENGINE.md`,这里只写 QGIS 自己的部分。

## 1. 定位

| 工具 | 做什么 |
|---|---|
| `readgeodata` | 读一份地理数据:坐标系、范围、字段、统计与要素,栅格可以出预览图 |
| `qgisdoc` | 查本机 QGIS 的算法目录与算法的文档 |
| `qgisrun` | 执行一个 QGIS 算法 |

执行载体只有 QGIS 自带的 Python:算法、PyQGIS 脚本与数据读取都在这个解释器里运行,只需维护一套环境组装与一套验证。同一安装里的 `qgis_process` 不另外支持。

范围是 QGIS 内置的 native、qgis 与 gdal 三个提供方的算法,第三方插件的算法不在其中。其中剔除两类:QGIS 标为不能在独立工具中运行的算法,它们要用 QGIS 的界面或打开的项目;以及 `native:openurl`,它用系统默认的程序打开文件或网址,GeoAgent 用不着,也不该借它启动别的程序。

## 2. 核心设计

### 2.1 安装与环境

支持 QGIS 官方的安装包:macOS 上的应用包,Windows 上的独立安装包与 OSGeo4W;conda、Homebrew 等来源不支持。GeoCode 不按版本号判断能不能用:不同版本运行时会出各种意想不到的问题,只能由检查与执行说明,遇到的问题原样交给 GeoAgent,逐个版本验证、逐个解决。

环境采用 QGIS 自己的答案,GeoCode 只叠加它不会替自己设置的几项。macOS 上以应用包里官方的启动脚本运行解释器,再显式给出投影与 GDAL 的数据目录,否则坐标变换会静默失败。Windows 上每次都经 QGIS 自己的启动脚本运行,环境全由它组装,GeoCode 不自己组装,也不留环境的快照:Qt、GDAL 与各个依赖的位置随版本而变,自己组装就要跟着每个版本追,漏一项就是 Qt 找不到或 DLL 加载失败。脚本与请求经标准输入交给 Python,不放在命令行上,因为 Windows 的命令解释器会改写命令行里的特殊字符。QGIS 的配置与缓存位置也不改:定制得越多,兼容的版本越少。

### 2.2 配置、发现与检查

`machine.json` 的 `qgis` 块只记一个路径,其余由 GeoEngine 自己找与检查。路径落在一个应用包或 QGIS 根目录内部时,取它所在的那一套;一个根目录里有几套而路径没有指明时,报告为有多套,由用户或 GeoAgent 指定,不替用户挑。

设置里列出可选的安装时只读安装包自带的信息,不启动软件;完整的验证只对选中的那一套做。macOS 上按应用的身份找,不按名字,因为应用可以改名、放在别处。Windows 上按安装程序的目录布局在固定硬盘上找,不查注册表:独立安装包不在里面记安装位置,文件关联只记最后装的那一套。

检查真的去做一遍:导入 GDAL,做一次真实的坐标变换,导入 QGIS 核心,初始化处理框架。坐标变换单独一步,因为投影库在数据库缺失时照样能导入,要到真正变换时才失败。看 QGIS 得出的失败,在每次工具调用时再检查一次,因为在原处重装 QGIS 不改动配置文件;就绪时不再检查,不拖慢调用。

失败的两类信息分给不同的读者(`GEOENGINE.md` 第 2.6 节)。诊断给用户,另附 Python 实际拿到的几项与定位问题有关的环境变量,其余的可能带着密钥,所以不附。给 GeoAgent 的提示让它自己动手配置路径;有几套时用哪一套、安装与重装,只有用户能做。QGIS 坏了时提示只说哪一项不对,不给探针的输出:它会引着 GeoAgent 去修它修不了的 QGIS。

### 2.3 权限

`readgeodata` 把数据内容交给模型,所以照 `read` 询问。一份数据常要分几次读,同一会话里每份数据只检查一次。

`qgisrun` 按整个工具询问,不按算法逐个设权限:算法有数百种,逐个授权既不合理,也容易在少数算法上出意外。输入不检查,读数据的是 QGIS,内容不经过模型。要守住的是写到哪里,与少数后果不可逆的算法,规则允许时它们仍然询问(`GEOENGINE.md` 第 2.8 节):

- 写到会话目录与项目之外,或写进数据库、网络服务这类不是文件的位置。几乎每个算法的输出都能写进数据库,同名的表被直接替换。同一个库的各张表算一处。
- 后果不可逆的算法,如清空要素、改写坐标系、执行 SQL、把文件上传到网址,列成一份名单。名单只求挡住主要的危险;「没有输出参数就当作会修改」这样的通则会误伤一半无害的算法。

「始终允许」按其中的算法、目录与数据库各自记住,对整个工具的「始终允许」不算。

一次执行先检查、再询问、后执行:GeoEngine 认出参数里的文件、检查数据、定下输出,内核据此询问,得到允许后按检查过的参数执行。用户批准的就是将要执行的。

### 2.4 执行算法

每次执行是一个独立的任务进程,当前目录是会话目录。

无界面运行时没有 QGIS 项目,按椭球测量的算法(字段计算器的面积、线长等)会改在坐标上按平面量,经纬度数据得到以度为单位的数,不报错。所以每次执行一律设 WGS 84 椭球,与桌面版的结果一致。

算法要运行多久无从预估,所以不设总时限:模型按数据规模给出 QGIS 可以多久没有消息,到时中止,持续报告的算法不会被误杀。

执行之前,GeoCode 只拦下判断确定、而执行只会白跑或悄悄得出错误结果的请求,并说明怎样改,例如参数名不属于这个算法(QGIS 会忽略它而改用默认值)、输入图层混合了几类几何(无界面运行时图层的类型取第一个要素的)。取值与必填参数由 QGIS 自己检查;只有 QGIS 读得准的判断,用 QGIS 自己的函数判断,判断本身出错时照常放行;数据本身检查不了时,不执行。

QGIS 遇到已有的输出文件时直接覆盖,写到含多个图层的 GeoPackage 时整份文件被替换。所以输出撞名时编号(`CONVENTIONS.md` 第 2 节),判断的是 QGIS 实际会写的名字,包括它自动补的扩展名、Shapefile 的附属文件与 GeoPackage 里的表;已有文件的输出文件夹同样编号。询问与执行的都是编号后的路径。没有成功结束的执行,新建的输出文件与输出文件夹在 QGIS 退出后删掉,执行前就在的不动;删不掉的在答复里标为可能不完整。往 GeoPackage 里加表的输出不删,只标为可能不完整:表从库里删不干净,而新建的库里可能还有同时执行的另一次加的表。调用 GDAL 命令行的算法,命令以错误码退出时 QGIS 照常报告完成,`qgisrun` 把它当作失败,因为输出并没有写出。

答复先写执行前定下的事实,再按收到的顺序转达运行中的信息,最后写怎样结束,无论怎样结束前面的内容都保留。运行中的信息只按来源与时间转达,不按文字过滤或分级:要支持两个平台与各个版本,针对文字的规则必然在别处出错。

### 2.5 读取数据

`readgeodata` 读 GDAL 打得开的一切数据,事实由 QGIS 自带的 Python 取出,不启动 QGIS 本身,也不在数据旁边留下东西(统计缓存、GeoPackage 的 `-wal` 等)。读取有几分钟的总时限,到时停下并告诉模型,不让它对着一个过大的文件一直等。

- 矢量的几何混合时按类分开统计与取样,因为不同几何的要素往往连字段都不同。
- Shapefile 没有可信的编码声明时,能完整解成 UTF-8 就是 UTF-8,否则在 GB18030、CP950 与 Windows-1252 之间识别,对应 GeoCode 面向的中国大陆、台湾与英文世界。识别不对时由模型指定编码重读。
- 栅格的统计从全部像元精确算出,文件里缓存的近似统计可能差得很远。取值不多或带色表的整数波段当作分类数据。
- 坐标系声称是经纬度、坐标却远超经纬度的范围时,报告为未知。

预览图与描述分开读,模型多数时候只读描述。不选波段时照文件标明的红绿蓝显示,不按波段名或波段数猜传感器。预览图只给模型,不在对话里显示。

答复超出内核给工具结果的上限时,自己先少列不要紧的部分,并说明省略了多少,不让内核从中间截断。

### 2.6 查阅算法

`qgisdoc` 的内容全部来自本机 QGIS 自己的算法定义,不附 GeoCode 手写的说明与示例:各版本的算法与参数不同,手写的内容总会在某个版本上出错。查找不分大小写与标点,但不猜:一个名字对应多个算法时列出全部候选。`qgisrun` 只认准确的算法标识。

官方手册一个分组一页,大的超过内核给工具结果的上限。所以 `webfetch` 读 QGIS 的官方手册时,链接带锚点就只返回那一节。

### 2.7 界面

算法的名称与描述取 QGIS 自带的翻译,与用户自己的中文版 QGIS 叫法一致;对话里不显示算法标识。

## 3. 边界与约束

- 不安装 QGIS,不改动用户的 QGIS 与它的配置。无界面运行的 QGIS 用它自己的另一份配置,用户在桌面版装的插件与模型不可用。
- 不按版本号拒绝任何一套 QGIS;两个平台的官方安装包同等对待。

## 4. 与其他部分的关系

- GeoEngine:QGIS 是它的一个能力模块,有配置块与状态(`GEOENGINE.md`)。
- 内核:三个工具是内核的内置工具,`qgisrun` 与 OSM 的下载共用同一道「写到哪里」的检查;读 QGIS 手册经内核的 `webfetch`。
- 内置的 Python 环境:QGIS 不用它(`PYTHON.md`)。

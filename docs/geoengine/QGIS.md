# QGIS

QGIS 能力域让 GeoAgent 用用户安装的 QGIS 读取地理数据、查阅与执行空间处理算法。一切都在 QGIS 自带的 Python 里运行,环境采用 QGIS 自己的组装方式;GeoCode 不按版本号判断能不能用,由检查与执行说明问题。三个工具分别读数据、查算法与执行算法,执行时先检查数据、定下输出,询问之后才按检查过的参数运行,输出永不覆盖已有的数据。

框架(进程、通道、配置与状态)与地理工具的共同做法在 `GEOENGINE.md`,这里只写 QGIS 自己的部分。

## 1. 定位

执行载体只有 QGIS 自带的 Python。算法、PyQGIS 脚本与数据读取都要在这个解释器里运行;只用它,就只需维护一套环境组装与一套验证。同一安装里的 `qgis_process` 不另外支持。

范围是 QGIS 内置的 native、qgis 与 gdal 三个提供方的算法,第三方插件的算法不在其中。其中剔除两类:QGIS 标为不能在独立工具中运行的算法,它们要用 QGIS 的界面或打开的项目;以及 `native:openurl`,它用系统默认的程序打开文件或网址,GeoAgent 用不着,也不该借它启动别的程序。

| 工具 | 做什么 | 权限 |
|---|---|---|
| `readgeodata` | 读一份地理数据:坐标系、范围、字段、统计与要素,栅格可以出预览图 | 照 `read` |
| `qgisdoc` | 查本机 QGIS 的算法目录:分组、算法、文档与搜索 | 默认放行 |
| `qgisrun` | 执行一个 QGIS 算法 | 自己的规则(第 4 节) |

## 2. 安装与环境

支持 QGIS 官方的安装包:macOS 上的应用包,Windows 上的独立安装包与 OSGeo4W;conda、Homebrew 等来源不支持。目标是两个平台上的大多数版本,但 GeoCode 不按版本号判断能不能用:不同版本运行时会出各种意想不到的问题,只能由检查与执行说明,遇到的问题原样交给 GeoAgent,逐个版本验证、逐个解决。

环境采用 QGIS 自己的答案。用户为自己的工具设的变量不交给它(`ENVIRONMENT.md` 第 2.3 节),GeoCode 只叠加 QGIS 不会替它设置的几项:两个平台都让输出用 UTF-8、关掉 Qt 的日志。macOS 上以应用包里官方的 `python` 启动脚本运行解释器,再显式给出投影与 GDAL 的数据目录(否则 GDAL 找不到投影数据库,坐标变换静默失败)。Windows 上每次都经一套 QGIS 自己的启动脚本 `bin\python-<名字>.bat` 运行,环境全由它组装;GeoCode 不自己组装,也不留环境的快照:Qt、GDAL 与各个依赖的位置随版本而变,自己组装就要跟着每个版本追,漏一项就是 Qt 找不到或 DLL 加载失败。

脚本与请求经标准输入交给 QGIS 的 Python,不放在命令行上:Windows 的启动脚本要经命令解释器运行,它会改写命令行里的引号与 `%`、`^`、`&`、`!`,截断多行内容。两个平台用同一种传法。

QGIS 启动时在系统的临时目录建几个文件,只在它自己收尾时删掉,所以启动了 QGIS 的脚本送出结果之后要走 QGIS 的收尾再退出。QGIS 的配置与缓存位置不改:定制得越多,兼容的版本越少。

### 2.1 配置与发现

`machine.json` 的 `qgis` 块记一个路径。macOS 上它指向应用包,落在应用包内部时取它所在的应用包。Windows 上它可以是 QGIS 根目录里的任何位置,GeoEngine 往上找到根目录:路径指明了哪一套就用那一套;没有指明时,根目录里只有一套能启动的就用它,有几套就报告为一个文件夹里有多套,由用户或 GeoAgent 指定,不替用户挑。

设置里列出的安装只读安装包自带的信息,不启动软件;完整的验证只对选中的那一套做。macOS 上按应用的身份找,不按名字,因为应用可以改名、放在别处:范围是两个应用程序文件夹,加上系统的 Spotlight 按包标识找到的,磁盘映像、外接磁盘与废纸篓里的不列。Windows 上按安装程序的目录布局在每块固定硬盘上找,一个根目录里的每一套各列一项;不查注册表,因为独立安装包不在里面记安装位置,文件关联只记最后装的那一套。装在别处的,由用户在设置里指定,或由 GeoAgent 去找。

## 3. 检查、状态与提示

检查由一段探针在组装好的环境里依次完成:导入 GDAL,做一次真实的坐标变换,导入 QGIS 核心,初始化处理框架;前一步失败就不往下查。坐标变换单独一步,因为投影库在数据库缺失时照样能导入,要到真正变换时才失败。除了框架共有的状态,QGIS 还按失败的原因分出各种状态:平台不支持、路径不存在、不是 QGIS、一个文件夹里有多套、找不到 QGIS 的 Python、探针某一步失败、探针超时或崩溃。看 QGIS 得出的失败,在每次工具调用时再检查一次,因为在原处重装 QGIS 不改动配置文件;就绪时调用不再检查,不拖慢调用。

诊断带上配置的路径、用的是哪一套与它的版本、检查运行的启动脚本与探针的输出。探针某一步失败时,另附 Python 实际拿到的几项环境变量(QGIS 的前缀、Python 的位置、Qt 的插件目录与前缀、`PATH`),用户贴回诊断就看得出是哪一项不对。只附这几项,其余环境变量可能带着密钥;这几项也只进诊断、不进提示,因为提示会发给模型的服务商,而 `PATH` 里有用户的文件夹名。

给 GeoAgent 的提示让它自己动手配置:写明配置文件的位置与写法、在这台电脑上找 QGIS 的位置与办法;找到多套时先问用户用哪一套,写好之后调用 `qgisdoc` 验证。QGIS 坏了时,附上探针输出的结尾,请用户重装或改用另一套。提示还要求 GeoAgent 不安装 QGIS、不写包装脚本、不自己运行 QGIS 的 Python 去试探:安装由用户决定,后两件只会添乱。

## 4. 权限

`readgeodata` 把数据内容交给模型,所以照 `read` 询问,没有自己的一条规则。一份数据常要分几次读(图层、翻页、预览),所以同一会话里每份数据只检查一次;放行只记在内核的内存里,拒绝不记住。

`qgisrun` 按整个工具询问,不按算法逐个设权限:算法有数百种,逐个授权既不合理,也容易在少数算法上出意外。输入不检查,读数据的是 QGIS,数据内容不经过模型。要守住的是写到哪里,以及少数后果不可逆的算法:

- 输出按算法的参数定义认出。写到会话目录与项目之外,或写进数据库、网络服务这类不是文件的位置时询问:几乎每个算法的输出都能写进数据库,同名的表被直接替换,也不经过项目内外的判断。同一个库的各张表算一处。
- 后果不可逆的算法列成一份名单,如清空要素、往已有的栅格里烧值、改写坐标系、执行 SQL、把文件上传到网址。名单只求挡住主要的危险;「没有输出参数就当作会修改」这样的通则会误伤一半无害的算法。

规则允许时,这些情况仍然询问,除非其中的算法、目录与数据库各自有过「始终允许」(`GEOENGINE.md` 第 3.6 节)。规则按算法标识求值,所以按算法写的拒绝与询问(如拒绝 `gdal:*`)在任何情况下都成立。

权限只决定问不问,所以一次执行分三步:GeoEngine 先按参数的类型认出参数里的文件,内核把它们按 `read` 与 `write` 的规则解析成绝对路径后交回;GeoEngine 检查数据、定下输出,不执行算法;内核据此询问,得到允许后 GeoEngine 按检查过的参数执行。用户批准的就是将要执行的。

## 5. 执行算法

每次执行是一个独立的任务进程,当前目录是会话目录,执行中按处理框架报告的进度回报。

无界面运行时没有 QGIS 项目,项目带来的测量椭球随之缺失:按椭球测量的算法(字段计算器的面积、线长、距离矩阵等)改在图层的坐标上按平面量,经纬度数据得到以度为单位的数,不报错。所以每次执行一律设 WGS 84 椭球,与桌面版按椭球测量的结果一致。

算法要运行多久无从预估,GeoEngine 不计时。`qgisrun` 由模型按数据规模给出时限,内核按 QGIS 连续多久没有任何消息计算,到时中止,持续报告的算法因此不会被误杀。QGIS 冷启动时什么也不报告,所以算法开始执行之前等得更久。调用 GDAL 命令行的算法,只在命令自己打印时才有消息,有的直到结束才有输出,时限对它们就是整个运行时间,工具说明要求模型在大数据上给足。

### 5.1 执行前的检查

`qgisrun` 把请求原样交给 QGIS,取值与必填参数由 QGIS 自己检查,它在算法开始前就会清楚地报错。GeoCode 只在判断确定、而执行只会白跑或悄悄得出错误结果时,才在询问之前拦下,并说明怎样改。例如:算法不在目录里(区分被剔除的与不存在的,给出相近的候选);参数名不属于这个算法(QGIS 会忽略它而改用默认值);输入图层混合了几类几何(无界面运行时图层的类型取第一个要素的,产出的数据是错的);输出写成只存在于内存的临时位置(结果随任务进程消失);坐标系类参数的值 QGIS 读不出(QGIS 当作没给,输出没有投影)。

只有 QGIS 读得准的判断,用 QGIS 自己的函数判断;判断本身出错时照常放行,由执行说明问题。数据本身检查不了时,不执行。

### 5.2 路径与输出

参数里的路径按参数的类型认出:只有输入类与输出类参数的值可能是路径,临时输出、GDAL 的虚拟路径、数据库连接的写法与网址不算。认出的路径由内核解析成绝对路径,规则与 `read`、`write` 相同;其余参数原样交给 QGIS,其中的相对路径经任务进程的当前目录同样落在会话目录。

QGIS 遇到已有的输出文件时直接覆盖,不报错:写到含多个图层的 GeoPackage 时整份文件被替换,输出就是输入时数据被清空。地理数据没有撤销,所以输出撞名时编号(`CONVENTIONS.md` 第 2 节)。判断的是 QGIS 实际会写的名字,包括它自动补的扩展名、Shapefile 的附属文件与 GeoPackage 里的表,不分大小写。输出是文件夹的,算法往里写它自己定的文件名,会覆盖上次的结果或与之混在一起,所以已有文件的文件夹同样编号,空文件夹照用;不存在的文件夹在执行前建好,因为有的算法遇到不存在的文件夹就失败。询问与执行的都是编号后的路径,答复结尾列出的输出位置带着编号。定下的名字保留到这次执行结束,同时检查的两次执行不会写到同一个名字。

### 5.3 答复

答复逐段累加,无论怎样结束,前面的内容都保留:

- 开头是执行前定下的事实:QGIS 的版本、算法、按默认值运行的参数与取值。
- 中段按收到的顺序转达运行中的信息:QGIS 处理框架的反馈,以及任务进程自己打印的行(PROJ 与 GDAL 直接打印的报错就在这里)。只按来源与时间转达,不按文字过滤或分级:要支持两个平台与各个版本,针对文字的规则必然在别处出错。QGIS 启动时的输出不转达,它附在最后的输出汇总也不重复。中段过长时只留它的结尾(`GEOENGINE.md` 第 3.6 节)。
- 结尾写怎样结束:成功时列出每个输出;失败时补上报错点名的参数的说明;超时时写连续多久没有消息。

没有成功结束的执行(失败、崩溃、超时与停止)写了一半的输出不留下:GeoEngine 在 QGIS 退出后删掉这次新建的输出文件,连同 Shapefile 的附属文件与 SQLite 的日志文件;执行前就在的不动,所以往已有 GeoPackage 里加的表与文件夹里的内容会留下。失败与崩溃的答复列出删不掉的输出,标为可能不完整。

调用 GDAL 命令行的算法,命令以错误码退出时 QGIS 只报告这个错误码,照常以完成结束;`qgisrun` 把它当作失败,因为输出并没有写出。用户在对话里停止执行时,内核直接中断工具,答复不送到模型。

## 6. 读取数据

`readgeodata` 读 GDAL 打得开的一切数据。事实由 QGIS 自带的 Python 取出,不启动 QGIS 本身;给模型的文字由 GeoEngine 写。读取不在数据旁边新留下东西,如统计缓存与 GeoPackage 的 `-wal`、`-shm`。文件有多个图层而没有指定时,照 QGIS 的列法列出,由模型选一个再读。读取有几分钟的总时限,到时停下并告诉模型,不让它对着一个过大的文件一直等。

- 矢量:几何类型、坐标系、范围、每个字段的统计,与可以翻页的样本要素。不声明单一几何类型的图层逐个要素清点,几何混合时按类分开统计与取样,因为不同几何的要素往往连字段都不同。样本里的数字照写入时的样子。
- Shapefile 的编码:先看文件的声明,声明 UTF-8 而文字不是 UTF-8 的当作没有声明,因为有的工具对没转换过的文字也这样声明;没有声明时,能完整解成 UTF-8 就是 UTF-8,否则在 GB18030、CP950 与 Windows-1252 之间识别,对应 GeoCode 面向的中国大陆、台湾与英文世界。识别不对时由模型指定编码重读。
- 栅格:尺寸、坐标系、地理参照、像元大小与每个波段的统计。统计从全部像元精确算出,因为文件里缓存的近似统计可能差得很远。取值不多或带色表的整数波段当作分类数据,给出每个值的占比。没有地理参照的图片答以不是地理数据。
- 坐标系声称是经纬度、坐标却远超经纬度的范围时,坐标系报告为未知。

预览图与描述分开读,模型多数时候只读描述。显示哪些波段由模型选,不选时照文件标明的红绿蓝,不按波段名或波段数猜传感器;分类数据逐值上色并附图例。预览图只给模型,不在对话里显示。

答复按内核给工具结果的上限裁剪,先少列不要紧的部分,并说明省略了多少,不让内核从中截断。读取不限总时长,连续一段时间没有消息才中止,所以耗时的读取要定时报活。

## 7. 查阅算法

`qgisdoc` 的内容全部来自本机 QGIS 自己的算法定义,不附 GeoCode 手写的说明与示例:各版本的算法与参数不同,手写的内容总会在某个版本上出错。目录在第一次用到时导出,换一套 QGIS 或版本变了之后重新导出,剔除的算法与 `qgisrun` 相同。

它有四个动作:列出分组、列出一个分组里的算法、读一个算法的文档、按英文词搜索(目录是英文的,模型读英文也更准)。算法名的大小写、空格与标点不影响查找,但不猜:一个名字对应多个算法时,列出全部候选。`qgisrun` 只认准确的算法标识。

文档照 `qgis_process help` 的版式由算法定义写出,补上调用需要而它没写的(能否多选、字段与波段属于哪个图层、高级参数),删去或改正在 GeoEngine 的运行方式下会失败的写法。文档开头写 QGIS 的版本,末尾给出对应版本官方手册里这个算法那一节的链接。

官方手册一个分组一页,大的超过内核给工具结果的上限,模型只能看到开头。所以 `webfetch` 读 QGIS 的官方手册时,链接带锚点就只返回那一节,否则只返回正文;找不到那一节时返回正文并说明。别的网站照原样。

## 8. 界面

算法的名称与描述取 QGIS 自带的翻译,与用户自己的中文版 QGIS 叫法一致;对话里的行与 `qgisrun` 的询问卡片不显示算法标识。`qgisdoc` 与 `readgeodata` 只是查阅,同一个工具相邻的调用在对话里合成一行。`webfetch` 读 QGIS 官方手册时,对话里显示手册网页本身,停在链接所指的那一节。

## 9. 边界与约束

- 不安装 QGIS,不改动用户的 QGIS 与它的配置;无界面运行时 QGIS 照它的默认位置写自己的配置与缓存。
- 无界面的 QGIS 用它自己的另一份配置,用户在桌面版装的插件与模型不可用。
- 不按版本号拒绝任何一套 QGIS;两个平台的官方安装包同等对待。

## 10. 与其他部分的关系

- GeoEngine:QGIS 是它的一个能力模块,有配置块与状态(`GEOENGINE.md`)。
- 内核:三个工具是内核的内置工具,`qgisrun` 与 OSM 的下载共用同一道「写到哪里」的检查;读 QGIS 手册经内核的 `webfetch`。
- 内置的 Python 环境:QGIS 不用它,用 QGIS 自带的 Python(`PYTHON.md`)。

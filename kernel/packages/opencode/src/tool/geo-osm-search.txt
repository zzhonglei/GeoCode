Use this tool to find OSM objects by name. It returns candidate objects with their OSM ids — the ids you need for OsmGetObjects (boundaries) or as "area:R<id>" extents for OsmProbe / OsmGetFeatures.

TIMING: this calls public services over the network. A few seconds is normal, but one unresponsive endpoint is given 90 seconds before the tool moves to the next, so a bad run reaches minutes. That wait is the tool working, not hanging — do not abandon the call and retry, because a retry pays the same cost from the start.

Parameters:
- query: The place or entity name, e.g. "武汉大学", "中国地质大学武汉", "Mount Tai".
- context: Optional geographic context for disambiguation, e.g. "武汉" / "山东". Adding it strongly improves ranking when the name exists in many regions.
- category: Optional OSM tag hint to narrow results, e.g. "amenity=university", "boundary=administrative", "natural".

Reading the results:
- Each candidate shows: id (R/W/N prefix), element type, category tags, importance, center coordinates.
- The bracket lists which lookups matched it. Two or more means separate lookups landed on the same object — the strongest signal here.
- (transit) marks bus stops / transit routes that share the entity's name — usually noise unless the user wants stops.
- A candidate marked "(member of site relation R…)" belongs to that relation — include it when the user means the whole multi-part entity.
- Lines starting with NOTE: say what degraded. The results are still usable; the note tells you what may be missing from them.

When nothing relevant comes back: expand abbreviations to full official names, add context, try alternate languages, or fall back to extent + tag queries via OsmProbe / OsmGetFeatures.

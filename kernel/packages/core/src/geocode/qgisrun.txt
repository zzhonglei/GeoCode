Run a QGIS Processing algorithm and return its outputs.

Read the algorithm's documentation with qgisdoc (action "help") before running it: parameter names, types and defaults differ between algorithms and between QGIS versions. QGIS runs here without its interface or a project, so give inputs and outputs as files, not "memory:" or TEMPORARY_OUTPUT; there are no open layers or map layouts to refer to.

Coordinate reference systems: QGIS does not check whether the input's CRS suits the algorithm, and the documentation often does not say. An algorithm that takes or produces distances or areas, such as buffers, lengths, densities or slopes, MUST run on projected data (metres or feet): on geographic data a 500 m buffer becomes 500 degrees. Reproject first, with native:reprojectlayer for vectors or gdal:warpreproject for rasters. GeoJSON output MUST be in WGS 84 (EPSG:4326), as the GeoJSON standard requires.

In a multi-step workflow, reduce the data first (clip, filter), then run the expensive steps (joins, classification). For layers with many features, such as POIs or grids, use .gpkg for inputs and outputs: it is much faster. Otherwise prefer .shp or .geojson.
